# Provisioning a consumer

Một consumer là repo **dùng** harness, không phải repo ship nó. Tài liệu này là runbook duy nhất cho
việc đưa một consumer lên: nó thay cho ba bản riêng `provisioning-x79.md`,
`provisioning-baplatform.md`, `provisioning-fineso.md` — ba bản đó chỉ khác nhau ở `projectId` và
port, và đã lệch khỏi code ở đúng chỗ nguy hiểm nhất (port).

| Consumer | `projectId` | Observatory port |
|---|---|---|
| `~/Workspaces/x79` | `x79` | 8792 |
| `~/Workspaces/baplatform` | `baplatform` | 8793 |
| `~/Workspaces/FinESO` | `fineso` | 8794 |
| `~/Workspaces/atrievefin` | `atrievefin` | 8795 |

> **Port không phải tham số của runbook này.** Port thuộc về project và được ghi **một lần** trong
> `~/.harness/workspace.json`; cấp phát và kiểm tra bởi
> `packages/harness-foundation/src/observe-port.mjs`. Bảng trên chỉ để đọc, đừng sửa JSON bằng tay —
> xem [§6](#6-observatory-cho-consumer).

## Quy ước thư mục làm việc

- Lệnh quản lý product profile (`./harness init profile`, `./console.sh`, `./deploy.sh`) chạy từ
  **`harness-eso`**.
- Lệnh sửa file repo, chạy hook, kiểm tra cục bộ chạy từ **trong consumer**.
- **Không** chạy `.harness/host-pack/harness-hook.mjs` khi cwd là `harness-eso`: file session
  (`.eso-preflight.json`) sẽ rò vào product repo.

---

## 1. Điều kiện

- Node ≥ 20, Bun.
- Docker Desktop / Engine đang chạy (Observatory + Console).
- Clone sibling trong một thư mục cha, ví dụ `~/Workspaces` chứa cả `harness-eso` và consumer.
- AgentMemory: mỗi consumer một instance (x79 `:3111`, baplatform `:3211`), viewer tương ứng.

---

## 2. Provision

```bash
cd ~/Workspaces/harness-eso

# 1) Xem trước — không ghi gì
./harness init profile ../x79 --id x79 --plan

# 2) Áp dụng (dual-IDE: Cursor + Antigravity)
./harness init profile ../x79 --id x79
```

Port được cấp phát ở bước này, ghi vào **cả hai** registry:

- `~/.harness/workspace.json` — `projects[].port` (nguồn duy nhất, resolver đọc từ đây)
- `~/.harness/projects/<id>.json` — `observe.port` (bản ghi cho Console, phải bằng workspace)

Nếu hai chỗ lệch nhau, Console báo `portConflict` trong `/api/projects` và
`node scripts/reconcile-observe-ports.mjs` in ra chính chỗ lệch. Đó là **báo lỗi**, không phải trạng
thái bình thường để chạy tiếp.

Kết quả trên consumer:

| File | Nội dung |
|---|---|
| `harness.config.json` | tenant anchor — `project.id`, `server.port` (phải bằng port đã cấp) |
| `.harness/host-pack/` | `harness-hook.mjs`, `route-hook.py`, `path-policy.default.json` |
| `.harness/decision-policy.json` | policy merge (operator key được giữ) |
| `.harness/host-bootstrap.json`, `.harness/sidecar.env` | URL sidecar = `http://127.0.0.1:<port>` |
| `.cursor/hooks.json`, `.agents/hooks.json` | wiring dual-host |

Chạy lại là idempotent. `harness.config.json` là **create-if-missing** — sửa nó cần `--force`
(xem [§7](#7-vòng-đời-host-pack)).

## 3. Kiểm tra provision

```bash
# Tenant anchor + sidecar phải cùng một port
cat ~/Workspaces/x79/harness.config.json | jq '.server.port'
grep HARNESS_SIDECAR_URL ~/Workspaces/x79/.harness/sidecar.env

# Token diet (eager rules ≤ 7, prefix ≤ 5k token)
./harness check token-diet ../x79

# Conformance H0–H5 của consumer (contract + recipe, không chỉ file tồn tại)
./harness verify consumer ../x79 --strict
```

Cả ba phải khớp nhau. Nếu `harness.config.json` ghi một port mà `workspace.json` ghi port khác, dừng
lại — đó chính là trạng thái từng làm `deploy.sh baplatform` khởi động stack của `x79`.

---

## 4. Chạy thử hook trong consumer

```bash
cd ~/Workspaces/x79

# Preflight (Cursor)
node .harness/host-pack/harness-hook.mjs preflight
cat .cursor/session/.eso-preflight.json

# Write guard — phải bị chặn khi không có attestation
python3 .cursor/hooks/guard-write.py AGENTS.md
```

Antigravity dùng cùng pack qua `.agents/hooks.json`; payload là protobuf-wrapped nên hook trả `{}`
kèm `decision` đúng dialect, không trả lỗi schema.

## 5. MCP cho hai IDE

`docgraph` dùng **CLI chung** (không MCP daemon): index ở `<consumer>/.docgraph/`, build bằng
`docgraph build`, query bằng `docgraph --q "<terms>"`. Codegraph cũng index theo consumer
(`codegraph serve --mcp --path <consumer>`).

```jsonc
// .cursor/mcp.json — ví dụ tối thiểu
{
  "mcpServers": {
    "agentmemory": { "command": "npx", "args": ["-y", "@agentmemory/mcp"],
                     "env": { "AGENTMEMORY_URL": "http://localhost:3111" } },
    "codegraph":   { "type": "stdio", "command": "codegraph",
                     "args": ["serve", "--mcp", "--path", "/Users/…/x79"] },
    "deepseek-direct": { "command": "bun", "args": ["run", "/Users/…/deepseek_direct.js"] }
  }
}
```

`.agents/mcp_config.json` giữ bộ server tương đương nhưng **tách hoàn toàn** khỏi `.cursor/`:
không file nào được trỏ vào script của bên kia. Mỗi IDE tự quản runtime MCP của nó.

Không commit file MCP có token. Giữ token trong env file và trỏ tới bằng `env`.

## 6. Observatory cho consumer

Đăng ký + khởi động là **một** lệnh; nó tự đọc port đã cấp:

```bash
cd ~/Workspaces/harness-eso
./deploy.sh x79
```

`deploy.sh` build SPA + image (bỏ bằng `--no-build`), restart stack `harness-observatory-x79`, rồi
**kiểm `/api/tenant` chứa đúng `x79`** — không chỉ tin `/health` trả 200. Một stack của consumer khác
cũng trả 200.

Kỳ vọng:

```text
✅ Consumer 'x79' đã sẵn sàng tại: http://127.0.0.1:8792/
```

Không đăng ký project bằng cách sửa `~/.harness/workspace.json` trực tiếp — nếu buộc phải sửa, chạy
`node scripts/reconcile-observe-ports.mjs` sau đó để hai registry về khớp.

## 7. Vòng đời host pack

| Việc | Lệnh |
|---|---|
| Viết lại hook bins + `hooks.json` + `sidecar.env` | `./harness init profile <consumer> --id <id>` (idempotent) |
| Sửa một `harness.config.json` đã cũ | `./harness init profile <consumer> --id <id> --force` |
| Nâng pack trên consumer đang chạy | `./harness host-pack refresh ../x79` |
| Gỡ / thêm một IDE | `./harness host-pack remove-ide ../x79 --tree agents` · `add-ide` |
| Rollback | [07.rollback-host-pack.md](../04.operations/07.rollback-host-pack.md) |
| Sự cố pack | [06.host-pack-runbook.md](../04.operations/06.host-pack-runbook.md) |

`reload` qua Console tương đương, nhưng Console là surface cho người vận hành —
`curl -X POST http://127.0.0.1:8791/api/projects/x79/reload`. Với `{"tenant":true}` thì
`harness.config.json` cũng được ghi lại (đường sửa duy nhất cho một anchor đã stale).

## 8. Policy riêng của từng consumer

Baseline `generic-eso` để Jev (L2) và Flash route (L3) **off**. Bật chúng là quyết định của
consumer, ghi vào `.harness/integrations.json` + `.harness/decision-policy.json` của consumer — không
phải vào repo này.

`baplatform` là ví dụ có bật: `jev.adapterId = jev-typesafe-active` (`mode: active`),
`l3_route.adapterId = deepseek-flash-route`, `memory.adapterId = agentmemory-mcp`, kèm
`fallback.l3_flash: true`. Chỉ bật khi consumer thật sự có key (`TYPESAFE_API_KEY`) và
AgentMemory riêng; pack tự đọc `installation/typesafe/typesafe.env` nếu biến chưa export.

Khoá path governance cũng thuộc consumer: `paths.locked` trong `.harness/decision-policy.json` là thứ
`guard-write.py` đọc. Danh sách đó là Source of Truth **của consumer**, không phải của harness-eso.
