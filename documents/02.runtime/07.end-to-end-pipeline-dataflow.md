## 2. Diễn Giải Chi Tiết Các Mắt Xích Quyết Định

### 2.1 Cổng Quyết Định L0 vs Jev (Decision Facade)
Code cài đặt tại `packages/harness-decision/src/decide.mjs` và `jev-l2.mjs`.

* **Tầng L0 (Quy tắc tất định)**:
  * Chi phí tính toán là `0ms` (in-process Regex & mapping).
  * Lệnh shell nguy hiểm bị chặn ngay lập tức mà không cần gọi ra ngoài (`rm -rf`, `dropdb`, `git push --force`).
  * Route bucket được xác định dứt khoát nếu chỉ có 1 winner rõ ràng.
* **Tầng L1/L2 (Jev System One)**:
  * Kích hoạt khi có **Ambiguity**: L0 hòa điểm (`l0.tie`) hoặc lệnh shell lạ (`verdict = ask`).
  * Gọi HTTP đến `api.typesafe.ai` để phân xử.
  * Ngưỡng tự động: Confidence $\ge 0.9$ tự động áp đặt (`route_jev`); ngược lại đưa vào `HIL Required` để con người xác nhận.

---

### 2.2 Cổng Bằng Chứng Đầy Đủ (Evidence Sufficiency Gate)
Code cài đặt tại `packages/harness-eso-core/src/turn-verdict.mjs` và tài liệu `documents/02.runtime/05.decision-facade.md`.

* **Công thức chấm điểm**:
  $$\text{score} = (\text{lawRatio} \times 0.55) + (\text{readRatio} \times 0.45)$$
* **Bất biến**:
  $$\text{level} = \text{sufficient} \iff \text{score} \ge T_{\text{high}} \land \text{gaps.length} === 0$$
* **Rào chắn Write Gate**:
  * Chế độ `enforceWrites = fail_closed` sẽ từ chối (`deny`) mọi yêu cầu sửa đổi file nếu `level !== 'sufficient'`.
  * Agent bắt buộc phải thực hiện lệnh `docgraph` hoặc đọc file để đóng toàn bộ các Gap mới được cấp quyền ghi.

---

### 2.3 Phân Tầng Bộ Não (Brain Tier: Zero vs Flash vs Pro)
Quy định tại `AGENTS.md` và `KI-01`:

1. **Zero Brain (Dispatcher Tooling)**:
   * Không tốn token mô hình ngoài.
   * Dùng cho tra cứu Jira, duyệt thư mục, chạy `bun test`, đọc file, sửa 1 dòng config cơ học.
2. **Brain Flash (`ask_deepseek_flash`)**:
   * Mô hình ong thợ mặc định.
   * Tối ưu cho TDD, viết Unit Test, sinh mã nghiệp vụ đã có spec/DoR rõ ràng, fix bug có trace.
3. **Brain Pro (`ask_deepseek_pro`)**:
   * Kích hoạt khi cần suy luận kiến trúc sâu (Chain-of-Thought).
   * Dùng cho thiết kế Domain Model, xử lý xung đột quy tắc Multi-Tenancy/RBAC, giải quyết vi phạm Invariant hoặc lỗi tranh chấp tài nguyên phức tạp.
