This document details the complete end-to-end lifecycle of data within Harness ESO: from the moment a user submits a prompt, through deterministic classification, adapter reconnaissance, evidence sufficiency evaluation, cognitive routing, precision execution, to knowledge distillation.

## 2. Detailed Architectural Mechanisms

### 2.1 Decision Facade: Level L0 vs Level L1/L2 Jev
*Implementation reference:* `packages/harness-decision/src/decide.mjs` and `jev-l2.mjs`.

* **Level L0 (Deterministic Rules)**:
  * Computes in `0ms` (in-process regex checks and bucket mapping).
  * Dangerous terminal commands (`rm -rf`, `dropdb`, `git push --force`) are denied immediately without external calls.
  * Route bucket assignment resolves instantly when a single bucket decisively wins.
* **Level L1/L2 (Jev System One)**:
  * Triggered exclusively upon **Ambiguity**: tied route scores (`l0.tie`) or unknown shell commands (`verdict = ask`).
  * Dispatches an HTTP request to `api.typesafe.ai` for probabilistic classification.
  * Thresholds: Confidence $\ge 0.9$ automatically enforces the decision (`route_jev`); otherwise it halts for Human-in-the-Loop (`HIL Required`) approval.

---

### 2.2 Evidence Sufficiency Gate
*Implementation reference:* `packages/harness-eso-core/src/turn-verdict.mjs` and `documents/02.runtime/05.decision-facade.md`.

* **Scoring Formula**:
  $$\text{score} = (\text{lawRatio} \times 0.55) + (\text{readRatio} \times 0.45)$$
* **Core Invariant**:
  $$\text{level} = \text{sufficient} \iff \text{score} \ge T_{\text{high}} \land \text{gaps.length} === 0$$
* **Write Gate Protection**:
  * In `enforceWrites = fail_closed` mode, any attempt to modify protected files is denied if `level !== 'sufficient'`.
  * The agent is required to query `docgraph` or inspect referenced files to close all identified gaps before write authorization is unlocked.

---

### 2.3 Cognitive Allocation (Brain Tiers: Zero vs Flash vs Pro)
*Implementation reference:* `AGENTS.md` and `KI-01`:

1. **Zero Brain (Dispatcher Tooling)**:
   * Consumes 0 external model tokens.
   * Dedicated to Jira lookups, directory listing, running tests, slice reading, and mechanical config edits.
2. **Brain Flash (`ask_deepseek_flash`)**:
   * Default workhorse model.
   * Optimized for Test-Driven Development (TDD), unit testing, implementing business logic with clear DoR, and fixing bugs with stack traces.
3. **Brain Pro (`ask_deepseek_pro`)**:
   * Activated when deep architectural synthesis (Chain-of-Thought) is required.
   * Dedicated to designing new Domain Models, resolving multi-tenancy/RBAC conflicts, addressing invariant violations, or debugging complex deadlocks.
