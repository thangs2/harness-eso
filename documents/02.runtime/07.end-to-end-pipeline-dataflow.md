## 2. Detailed V2.0 Architectural Mechanisms

### 2.1 Cognitive State Machine (`COLD / WARM / HOT`) & JIT-Pinning
*Implementation reference:* `packages/harness-eso-core/src/preflight.mjs` & `context-contract.mjs`.

- **`COLD` State:** Triggered on the first turn of a session, when user intent drifts to a new topic, or when the Git index fingerprint changes. Runs full adapter reconnaissance and emits explicit gap closure instructions.
- **`WARM` State:** Triggered when sufficiency is established. Instead of re-injecting 50-line document chunks on subsequent turns, Preflight emits a **$\le 30$-token JIT-Pin** listing only the active domain's `INV-*` codes from `00.context-contract.json`.
- **`HOT` State:** Triggered on continuation turns with matching prompt stem ($\ge 6$ chars, **Gate G1**) and a verified clean disk fingerprint (**Gate G2**). Short-circuits in `0ms` and injects `0` tokens of additional context.

### 2.2 Dual-Zone SDLC & Normative Docgraph Slicing
*Implementation reference:* `packages/harness-eso-core/src/docgraph-adapter.mjs` & consumer `sdlc/00.agent-manifests/`.

- **Agent Zone (`sdlc/00.agent-manifests/`):**
  - `01.domains/01..17.spec.md`: High-density domain manifests containing `## Invariants` (`INV-*`), `> [!CRITICAL]` callouts, and compact unstyled `stateDiagram-v2` / `flowchart LR` state machines.
  - `02.jira-waves/00..04.spec.md`: Incremental wave topology maps (`Epic -> Story -> TDD Quartet`) that eliminate reading 800-line human ticket maps.
- **Human Zone (`sdlc/01..12`):** Full narrative specifications and color-coded Mermaid diagrams preserved for human engineers and `delivery-intake` / `jira-enrich`.
- **Normative Slicer:** `docgraph-adapter.mjs` strips narrative prose and extracts only normative blocks (`## Invariants`, `INV-*`, `> [!CRITICAL]`). Legacy documents lacking normative structure trigger `specDebt = true` in Observatory telemetry.

### 2.3 Cryptographic HMAC Sufficiency Receipt & Write Gate
*Implementation reference:* `packages/harness-eso-core/src/eso-attestation.mjs`, `gap-closure.mjs`, and `.cursor/hooks/guard-write.py` (twin `.agents/hooks/guard-write.py`).

- Every `SUFFICIENT` verdict (either at Preflight or promoted via `recordGapToolUse` when `allClosed === true`) generates an HMAC-SHA256 signed receipt in `.eso-bundle-stamp.json`.
- `guard-write.py` validates both the HMAC Sufficiency Receipt and the Brain Stamp (`.pipeline-brain-stamp.json` or `.direct-mode` sentinel) before allowing any write to protected paths.
