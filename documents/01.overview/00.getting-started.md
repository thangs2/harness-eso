# Getting Started — Harness ESO (Quickstart)

> For the full deep-dive product overview and complete operator handbook, see:
> * [**Deep Introduction, Philosophy & Target Audience**](./04.introduction-and-audience.md)
> * [**Complete User & Operator Guide**](./05.user-and-operator-guide.md)

Harness ESO runs two local services:
* **Console (`:8791`)** — Write-side project onboarding wizard, policy configuration, and human consent management.
* **Observatory (`:8792`)** — Read-only turn-level monitor, evidence sufficiency tracker, and SQLite ingest server.

---

## 1. Install & Start (Once Per Machine)

```bash
git clone https://github.com/thangs2/harness-eso.git
cd harness-eso
./install.sh
./harness up
```

* Open **http://127.0.0.1:8792** for the **Observatory** (or run `./harness console` for the **Console** wizard at **http://127.0.0.1:8791**).

---

## 2. Provision a Consumer Repository

Never provision `harness-eso` itself. Target an external consumer repository (e.g., `~/Workspaces/x79`):

```bash
# 1. Dry-run to preview changes
./harness init profile ~/Workspaces/x79 --plan

# 2. Apply provisioning (wires Cursor + Antigravity hooks)
./harness init profile ~/Workspaces/x79 --id x79 --host-mode dual-ide

# 3. Verify host-pack integrity
./harness host-pack status ~/Workspaces/x79
```

> [!IMPORTANT]
> **Reload your IDE window** (`Developer: Reload Window`) after running `init profile` so Cursor/Antigravity loads the updated `hooks.json`.

---

## 3. Where Configuration & State Live

| Location | Owner | Contents |
| :--- | :--- | :--- |
| `~/.harness/workspace.json` | Product State | **The one registry**: `projects[]` holds each project's document (root, port, status, plugins), plus the default project pointer |
| `~/.harness/observe/<id>/harness.db` | Product State | Per-project SQLite database of requests, tool calls, and turns |
| `~/.harness/attest/` & `consent/` | Product State | Trusted ESO attestations and human consent records (guarded from agent writes) |
| `<consumer>/harness.config.json` | Consumer Repo | Root anchor file (created by `init profile`, do not hand-edit) |
| `<consumer>/.harness/decision-policy.json` | Consumer Repo | Path protection tiers (`locked`, `ask`, `gated`, `sot`) and ESO adapter rules |

> **Docker Workspace Mount Note:** By default, containerized services expect consumer repositories under `~/Workspaces`. To use a different parent directory, set `export HARNESS_AGENT_ROOT=/path/to/parent` before running `./harness up`.

---

## 4. Switching the Default Observed Project

Either select the default project in the Web UI (**Projects** tab → **Set Default**) or via CLI:

```bash
bun run harnessctl configure list
bun run harnessctl configure use <id>
./harness restart
```
