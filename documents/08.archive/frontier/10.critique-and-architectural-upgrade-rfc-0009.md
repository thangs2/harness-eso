## 1. Tóm Tắt Điều Hành (Executive Summary)

Tài liệu này ghi lại toàn bộ nội dung phản biện chuyên sâu (Architectural Critique) và giải pháp kỹ thuật nâng cấp (Next-Gen Solution) đối với **RFC-0009**.

Mặc dù RFC-0009 đã xác định chính xác triệu chứng **Context Window Bloat & Token Burnout** do việc nhồi nhét thô dữ liệu (`[EVIDENCE CONTEXT]`), giải pháp ban đầu của RFC-0009 còn mang tính cơ học, mắc bẫy thiết kế M2M vs M2LLM, và chưa tối ưu hóa được chu trình nhận thức của AI Coding Agent. 

Tài liệu này xác lập mô hình **Dual-Plane Decoupling** kết hợp **Zero-Token Preflight** và **Contract-First AST Folding**, cho phép cắt giảm token lãng phí về xấp xỉ **0 token** trong các turn đã đủ bằng chứng, đồng thời bảo đảm an toàn tuyệt đối cho các chốt chặn ghi mã nguồn (`guard-write.py`).

## 2. Phản Biện Chuyên Sâu Các Lỗ Hổng Trong RFC-0009 Gốc

```
┌────────────────────────────────────────────────────────────────────────┐
│                        RFC-0009 CRITICAL FLAWS                         │
├───────────────────────────────┬────────────────────────────────────────┤
│ 1. Cryptographic Hash Noise   │ LLM prompt chứa sha256 vô nghĩa.       │
│ 2. Token Cost Shifting        │ Cắt mù quáng dẫn đến bùng nổ tool loop │
│ 3. Double-Injection Loophole  │ Nhồi lại dữ liệu Agent đã tự đọc       │
│ 4. Phantom Path Mappings      │ Nhầm lẫn công cụ ngoài với repo package│
└───────────────────────────────┴────────────────────────────────────────┘
```

### 2.1 Bẫy "Cryptographic Hash Rác" trong Prompt LLM (M2M vs M2LLM Confusion)
* **Lỗ hổng trong RFC-0009:** Đề xuất đưa `proofHash: "sha256-e3b0c44..."` vào payload `[EVIDENCE CONTEXT]` của LLM.
* **Phản biện:** LLM suy luận bằng ngữ nghĩa (Semantics), không thể xác minh băm SHA-256. Một chuỗi băm hex dài 64 ký tự là "rác ngữ cảnh" (context noise), vừa tốn token vô ích, vừa phân tán trọng số chú ý (attention weight) của mô hình.
* **Nguyên lý đúng:** Cryptographic Hash và State Proof là giao thức **Machine-to-Machine (M2M)**. Chúng bắt buộc phải lưu trên đĩa (`.eso-preflight.json`, `~/.harness/attestation/`) để Python/Node verify. Prompt gửi tới Brain chỉ cần **Chỉ thị ngữ nghĩa (Semantic Directive)** có thể hành động được.

### 2.2 Nguy cơ "Chuyển dời chi phí Token" (Token Cost Shifting)
* **Lỗ hổng trong RFC-0009:** Cắt bỏ toàn bộ nội dung snippet và chỉ trả về mã danh mục (ví dụ `INV-PROJECT-01`) mà không tính đến tri thức sẵn có của LLM.
* **Phản biện:** Nếu Agent chưa từng đọc file/tài liệu liên quan, việc tước bỏ snippet sẽ buộc Brain phải phát sinh thêm 2–3 tool calls (`docgraph`, `view_file`) ở các step sau. Mỗi round-trip tool call mang theo toàn bộ lịch sử chat trước đó, dẫn đến **tổng chi phí token thực tế tăng vọt gấp 2–3 lần** so với việc cung cấp đúng lát cắt nhỏ ngay từ đầu.
* **Nguyên lý đúng:** Cần cơ chế phân định rõ giữa **Push (Eager Context)** và **Pull (Lazy JIT Discovery)** tùy theo trạng thái phiên.

### 2.3 Vấn nạn "Double-Injection" (Ngữ cảnh trùng lặp)
* **Lỗ hổng trong RFC-0009:** Chưa nhận diện được xung đột giữa **Agent-driven Recon** (Agent tự gọi tool theo `AGENTS.md`) và **Preflight-driven Recon** (Hook chạy ngầm tự gom snippet).
* **Phản biện:** Trong hầu hết các phiên làm việc, Agent đã tự thực hiện `docgraph` hoặc `view_file` ở turn trước. Việc Preflight gom lại và inject vào `[EVIDENCE CONTEXT]` tạo ra hiện tượng trùng lặp 100% dữ liệu trong cùng một ngữ cảnh.

### 2.4 Sai lệch đường dẫn hệ thống (Phantom Path Discrepancy)
* **Lỗ hổng trong RFC-0009:** Bảng WBS liệt kê các path như `packages/codegraph/`, `packages/docgraph/`, `packages/agentmemory/`, `packages/harness-core/eso-preflight.mjs`.
* **Thực tế `harness-eso`:** Các thư mục trên không tồn tại. `harness-eso` chỉ sở hữu **Adapter layer** (`packages/harness-eso-core/adapters/*`), trong khi `codegraph`, `docgraph` là external CLI/MCP tools. Việc thực thi phải tập trung vào Adapter và Orchestration layer của `harness-eso`.

## 3. Bản Thiết Kế Nâng Cấp Toàn Diện (Next-Gen Architecture)

```
┌────────────────────────────────────────────────────────────────────────┐
│                   UPGRADED HARNESS-ESO ARCHITECTURE                     │
├───────────────────────────────┬────────────────────────────────────────┤
│     PLANE 1: MACHINE GATE     │        PLANE 2: BRAIN COGNITIVE        │
│    (Deterministic / Fast)     │          (High-Density Tokens)         │
├───────────────────────────────┼────────────────────────────────────────┤
│ • .eso-preflight.json         │ • Zero-Token if Sufficient             │
│ • ~/.harness/attestation/     │ • High-Density Semantic Directive      │
│ • State Proof Hash (SHA-256)  │ • Contract-First AST Stubs (CFIF)      │
│ • Python guard-write verified │ • Normative Spec Slices (No Prose)     │
└───────────────────────────────┴────────────────────────────────────────┘
```

### 3.1 Nâng Cấp 1: Phân Tách Hai Mặt Phẳng (Dual-Plane Decoupling) & Zero-Token Preflight

Tách rời tuyệt đối giữa **Mặt phẳng Kiểm soát (Gate Plane)** và **Mặt phẳng Nhận thức (Cognitive Plane)**:

1. **Gate Plane (Machine-Only, 0 Token Cost):**
   * Tính toán `proofHash`, `sufficiency.score`, `verifiedInvariants`, `gaps`.
   * Ghi trực tiếp ra tệp nội bộ:
     * `.cursor/session/.eso-preflight.json` (hoặc `.agents/session/`)
     * `~/.harness/attestation/<root-hash>.json`
   * `guard-write.py` và `guard-brain-hook.mjs` đọc trực tiếp từ đĩa cứng. **Hoàn toàn không đẩy dữ liệu này vào prompt LLM.**

2. **Cognitive Plane (Semantic Directives):**
   * **Khi trạng thái là `SUFFICIENT`:** Preflight hook áp dụng cơ chế **Zero-Token Injection**. `additional_context` được gán bằng `undefined`. Khi đã đủ bằng chứng, không làm phiền Brain bằng bất kỳ snippet thừa thãi nào.
   * **Khi trạng thái là `INSUFFICIENT`:** Chỉ trả về **Gap Resolution Directives** (< 50 tokens):
     ```markdown
     [ESO GAP NOTICE - Score: 0.45] Evidence missing before protected write:
     → docgraph --q "INV-PROJECT-ISOLATION"
     → Read code: 1 file in backend/mu-service/
     ```

### 3.2 Nâng Cấp 2: Contract-First Interface Folding (CFIF) cho Codegraph

Thay vì chỉ cắt bỏ body hàm sơ sài, thiết lập quy tắc bóc tách AST theo 3 tầng:

1. **Tier 1 (Target File):** File mã nguồn đang được chỉnh sửa $\rightarrow$ Giữ nguyên 100% full implementation.
2. **Tier 2 (Direct Dependencies):** Các interface, class phụ thuộc, DTOs $\rightarrow$ Chỉ giữ Class declaration, Attributes (`[Authorize]`, `[Route]`), Method signatures. Loại bỏ toàn bộ `private`/`internal` members và thân hàm.
3. **Tier 3 (Indirect Types):** Enums, Constants, ValueObjects $\rightarrow$ Rút gọn thành Folded Stub:
   ```csharp
   public enum BookingStatus { Pending = 1, Confirmed = 2, /* +5 more */ }
   ```

* **Adapter-Level Stream Filter:** Adapter `packages/harness-eso-core/adapters/codegraph-code.mjs` tích hợp bộ lọc Regex State Machine để tự động gập thân method ngay trên luồng stream stdout, không phụ thuộc vào việc CLI codegraph bên ngoài đã nâng cấp hay chưa.

### 3.3 Nâng Cấp 3: Normative Spec Slicing cho Docgraph

Chuyển đổi Docgraph từ cơ chế trích xuất theo đoạn văn (prose chunk) sang trích xuất **Mệnh đề Quy chuẩn (Normative Statements)**:

1. **Tiêu chuẩn hóa khối trích xuất:**
   * **Mức 1 (Bắt buộc):** GitHub Alert Blocks: `> [!IMPORTANT]`, `> [!CRITICAL]`, `> [!WARNING]`.
   * **Mức 2 (Luật):** Các section mang tính ràng buộc: `## Invariants`, `## Rules`, `## Constraints`, `## Acceptance Criteria`.
   * **Mức 3 (Bảng tra cứu):** Bảng ánh xạ Error Codes, Permissions, State Transitions.
   * **Loại bỏ triệt để:** Bối cảnh lịch sử, lời dẫn nhập, hướng dẫn cài đặt môi trường, hình vẽ ASCII không mang tính trạng thái.
2. **Hiệu quả:** Rút gọn tài liệu từ ~3.000 tokens văn xuôi xuống còn **150 – 200 tokens logic thuần túy**.

### 3.4 Nâng Cấp 4: Hierarchical Memory & Delta-Scoping cho AgentMemory

Giải quyết dứt điểm tình trạng nhớ lặp và nhớ chéo domain:

1. **Delta Memory Retrieval (`excludeSessionId`):**
   * Preflight hook truyền `excludeSessionId = ctx.conversationId`. Bộ nhớ do chính phiên hiện tại sinh ra sẽ không bị query ngược lại vào prompt (vì đã có trong transcript).
2. **Tiered Memory Compaction:**
   * Chỉ nạp ký ức thuộc phân loại **Rule/Decision** (`tier: 'rule'`).
   * Bỏ qua toàn bộ các ký ức dạng nhật ký sự kiện, chat vụn vặt, hoặc log debug lỗi thời.

### 3.5 Nâng Cấp 5: Cache-Attested Short-Circuit (Ngắt Mạch Nhanh)

* Đối với các prompt mang tính tiếp nối hội thoại (`continuation steps`, `invocationNum > 0` trong Antigravity/Cursor):
  * Nếu `conversationId` không đổi và tệp attestation trên máy còn hiệu lực (TTL 10 phút), preflight lập tức trả về kết quả có sẵn trong cache memory.
  * Giảm độ trễ preflight từ 400ms xuống **< 2ms**, tiêu tốn **0 token** mạng và 0 CPU I/O.

## 4. Bản Thiết Kế Mã Nguồn Chi Tiết (Implementation Code Blueprint)

### 4.1 Nâng Cấp `packages/harness-host-generic/src/preflight-hook.mjs`

```javascript
// Thay thế đoạn nhồi nhét additional_context cũ:
const out = {
    permission: 'allow',
    esoPreflight: { level: projection.level, score: projection.score },
};

if (projection.level === 'sufficient') {
    // ZERO-TOKEN OPTIMIZATION: Bằng chứng đã đủ, không làm ô nhiễm prompt!
    out.additional_context = undefined;
} else {
    // Chỉ đưa ra playbook khắc phục gap súc tích (< 50 tokens):
    const gapDirectives = (projection.gaps || [])
        .slice(0, 5)
        .map((g) => `• [${g.kind.toUpperCase()}] ${g.query || g.path}`)
        .join('\n');
    out.additional_context = `[ESO EVIDENCE GAP - Score: ${projection.score.toFixed(2)}]\nRequired before protected write:\n${gapDirectives}`;
}

if (projection.ok === false && projection.enforceWrites === 'fail_closed') {
    out.permission = 'deny';
    out.user_message = 'ESO preflight insufficient for dev slice — resolve gaps or narrow prompt.';
    out.agent_message = out.user_message;
}
emitHook(out, shape);
```

### 4.2 Nâng Cấp `packages/harness-eso-core/adapters/docgraph-law.mjs`

```javascript
/**
 * Trích xuất các khối quy chuẩn (Normative Blocks), loại bỏ văn xuôi.
 */
function extractNormativeSpec(rawMarkdown, maxChars) {
    if (!rawMarkdown) return '';
    const lines = rawMarkdown.split('\n');
    const normativeLines = [];
    let capture = false;

    for (const line of lines) {
        // Nhận diện Header bắt đầu vùng ràng buộc
        if (/^#{1,3}\s+(invariants?|rules?|constraints?|acceptance criteria)/i.test(line)) {
            capture = true;
            normativeLines.push(line);
            continue;
        }
        // Gặp Header khác thì ngắt vùng bắt
        if (/^#{1,3}\s+/.test(line) && capture) {
            capture = false;
        }
        // Giữ lại alerts quan trọng và bullet points Invariant
        if (capture || /^>\s*\[!(IMPORTANT|WARNING|CRITICAL)\]/.test(line) || /^\s*-\s*\*\*INV-/.test(line)) {
            normativeLines.push(line);
        }
    }

    const result = normativeLines.length > 0 ? normativeLines.join('\n') : rawMarkdown;
    return result.slice(0, maxChars);
}
```

### 4.3 Nâng Cấp `packages/harness-eso-core/adapters/codegraph-code.mjs`

```javascript
/**
 * Thu gọn thân hàm của class phụ thuộc thành stub gọn nhẹ.
 */
function foldMethodBodies(sourceCode) {
    if (!sourceCode) return '';
    // Gập khối { ... } thành { /* stub */ }
    return sourceCode.replace(/\{[^{}]*(?:\{[^{}]*\}[^{}]*)*\}/g, '{ /* stub */ }');
}
```
