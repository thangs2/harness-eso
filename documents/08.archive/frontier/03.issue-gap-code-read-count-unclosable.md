# Issue — code read-count gap never closes

**Status:** FIXED in `packages/harness-host-generic/src/eso-gap-io.mjs` (unit-tested in `packages/harness-host-generic/src/eso-gap-io.test.mjs`). Do not treat a consumer host-pack bundle as the fix.

**Seen on:** consumer `baplatform`, Cursor tree, 2026-10-15. Preflight `5bf78d3e-9540-4ee0-8643-56b14100d34d` and the following turn. Surface bucket `root` (remapped to pack `tools`). Score `0.183`. `eso.mode` `hint`, `enforceWrites` `fail_closed`, `cognition.enforceBrain` `fail_closed`.

## Symptom

`.cursor/session/.eso-gap-closure.json` stays `allClosed: false` after the agent has already `Read` real source files. The gap that stays open is:

```text
code:need at least 1 file read(s); have 0
```

Law gaps (`law:harness-tooling`, `law:harness-eso`) do close, because those queries are terms that appear in a tool path or a Grep pattern. The code gap does not.

While it stays open, `shouldBlockBrain` keeps denying Brain MCP (`ask_deepseek_*`) for the rest of the turn.

## Why

Two functions disagree about what the query means.

1. `packages/harness-eso-core/src/collect.mjs` — `detectGaps` (about line 24). When `retrieval.reads.readCount < pack.minReadPaths`, it emits:

```javascript
{ kind: 'code', query: `need at least ${minReads} file read(s); have ${readCount}`, priority: 2 }
```

That string is a status sentence. It is not a path and it contains no `/`.

Preflight always starts with `reads.readCount === 0`. `resolveSkillPack` in `packages/harness-eso-core/src/skill-pack.mjs` maps surface bucket `root` onto pack `tools`, and that pack sets `minReadPaths: 1`. So every root-bucket prompt is born with this gap. Score on the observed turn was `1/3 * 0.55 = 0.183` (one of three law terms hit, zero file reads).

2. `packages/harness-host-generic/src/eso-gap-io.mjs` — `closesGap` (about line 66). After the kind matches, a non-empty query closes only when the tool-input JSON contains the whole query, or when a `/`-separated segment longer than 3 characters appears in that JSON:

```javascript
return hay.includes(target) || target.split('/').some((seg) => seg.length > 3 && hay.includes(seg));
```

A sentence with no `/` is one segment. The segment is the entire sentence. A normal `Read` input is `{ path: "/abs/file.mjs" }`. That path never contains `need at least 1 file read(s); have 0`, so the gap never closes.

`gapKindsForTool` already classifies `Read`, `Grep`, `Glob`, `CallDynamicTool`, and `Shell` as kind `code`. The kind check passes. The query check is what fails.

## How to fix

Change `closesGap` in `packages/harness-host-generic/src/eso-gap-io.mjs`. Leave `detectGaps` as it is: the sentence is the right report of a read-count deficit. The matcher has to understand that sentence.

When `kind === 'code'` and the query matches `/^need at least \d+ file read\(s\); have \d+$/`:

- Close if the tool input has a non-empty `path`, `file_path`, or `target_file`.
- Close if the tool input is a codegraph call: the serialized input matches `/codegraph/i` and `query` is non-empty.
- Do not close a `Shell` whose input has no file path. `Shell` is tagged `code`, but `ls` is not a file read.

Do not loosen the existing substring / path-segment match for law gaps. `law:harness-tooling` must still require that term in the tool input.

Do not replace the query with `tools/harness` (the pack `codeQueries` entry). Segment matching would then close on any path that merely contains `harness`, including `.harness/`, and would miss a real read of `packages/...`.

`closesGap` is currently private. Export it, or drive the cases through `recordGapToolUse` with a temp root and a fixture `.eso-preflight.json`. There is no test within three caller hops of `closesGap` today (`qc/eso-orchestrator.test.mjs` covers `detectGaps` only).

Suggested cases:

| Tool input | Read-count gap |
|---|---|
| `Read` `{ path: 'packages/harness-eso-core/src/collect.mjs' }` | closes |
| `codegraph_explore` `{ query: 'detectGaps' }` (blob contains `codegraph`) | closes |
| `Shell` `{ command: 'ls' }` | stays open |
| `Read` `{ path: '' }` | stays open |
| law gap `harness-tooling` plus a `Read` whose path does not contain that term | stays open |

Run `bun test` for the new test. Behaviour on a consumer is a later `host-pack` rebuild and refresh. Unit test is the gate in this repo.
