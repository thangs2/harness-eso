# Evidence sufficiency — closure, scoring, and what the four consumer sessions proved

On 2026-10-22 four consumers (`x79`, `baplatform`, `fineso`, `atrievefin`) each produced a session log.
Between them they reported 26 runtime findings. This file is the result of checking those claims
against the code instead of against each other: **six are real harness defects in one file**, and
**two of the loudest are not reproducible at all**.

Read this before touching `eso-gap-io.mjs`. The evidence it cites lives in
[`../../comments/artifacts/`](../../comments/artifacts/README.md) — review artifacts, not law.

---

## 1. The mechanism, in one paragraph

Preflight writes `.cursor/session/.eso-preflight.json` with a `score`, a `level`, and a list of `gaps`.
Each tool call afterwards goes through `recordGapToolUse()` in
`packages/harness-host-generic/src/eso-gap-io.mjs`, which decides whether that call **closed** a gap.
When every gap closes, the bundle stamp is rewritten with `allowWrite: true`. Write enforcement
(`guard-write.py`) reads that stamp. So the whole write gate hangs on one predicate: `closesGap()`.

It is 7 lines long. Three defects live in it.

## 2. Harness defects — confirmed by reading the code

### H1 · A `law` gap naming a `core.*` rule cannot be closed by reading that rule

`eso-gap-io.mjs:128-131`:

```js
const target = String(gap?.query || gap?.path || '').toLowerCase();
if (!target || target === '?') return true;
const hay = JSON.stringify(toolInput || {}).toLowerCase();
return hay.includes(target) || target.split('/').some((seg) => seg.length > 3 && hay.includes(seg));
```

The gap query is a bare term — `pipeline-gate` from `skillPacks.tools.lawQueries`. The artifact the
consumer can actually read is `.cursor/rules/core.pipeline-gate.mdc`. Substring check:

| needle | haystack | `includes` |
|---|---|---|
| `pipeline-gate` | `.cursor/rules/core.pipeline-gate.mdc` | **false** — `core.` breaks the run |

The dotted prefix is what makes this unfixable from the consumer side: *every* consumer rule is
named `core.*` / `stack.*` / `delivery.*`, so **no consumer can ever close a law gap by reading the
law**. The only ways to close it are accidental — a `Grep` whose *pattern* text happens to contain the
term, or a tool input containing a path from a different repo that does contain it. Both were observed
in the artifacts and read as "it closed on an accidental path". They were right about what happened
and wrong about why.

**Fix direction:** normalise stems on both sides before comparing — fold `.`, `-`, `_` to one
separator, compare case-insensitively, and treat the term as matching when it appears as a token of the
basename. Do **not** relax to bare-segment matching; the caveat in
`08.archive/frontier/03.issue-gap-code-read-count-unclosable.md` still applies.

### H2 · The score after closure is invented, not re-measured

`eso-gap-io.mjs:187`:

```js
score: Math.max(Number(pre.score || 0), 0.85),
```

Nothing recomputes the score. A preflight that measured `0.1833` becomes `0.85` because a JSON blob
contained a substring. `level` flips to `sufficient` and `allowWrite` to `true` in the same breath.

Consequence: **an `85` produced this way means "the right words appeared in a tool argument"**, and it
is indistinguishable in the state files from an `85` produced by real evidence. Every downstream reader
— Console, attestation, a human — is told the same number.

**Fix direction:** `score = closedGapIds.length / requiredGapIds.length`, with `level` recomputed from
that. No floor, no `Math.max`. If a consumer needs a pass threshold, that is a policy decision made
against a measured number, not a clamp applied on write.

### H3 · The stamp is frozen until *every* gap closes

`eso-gap-io.mjs:180`:

```js
if (doc.allClosed && pre) {
```

Partial progress writes `closedGapIds` into `.eso-gap-closure.json` and rewrites nothing else. The two
state files then disagree: one says `1 of 2 closed`, the other still says `insufficient`. `guard-write.py`
prefers the attestation, which is only written from this same branch — so the gate sees nothing until
the last gap closes, and if H1 makes the last gap unclosable, it never will.

**Fix direction:** rewrite stamp + attestation on every closure change. Keep `preflightAt` stable so a
reader can tell *when* the verdict was measured as opposed to *when* it was updated.

### H4 · Law gaps are inevitable because preflight never fetches law

`packages/harness-eso-core/src/collect.mjs:9-22`, `detectGaps()`:

```js
const lawText = (retrieval.snippets || []).filter((s) => s.kind === 'law').map((s) => s.text).join('\n');
for (const term of pack.requiredDocTerms || []) {
    if (!lawText.includes(t)) gaps.push({ kind: 'law', query: term, priority: 1 });
}
```

The law adapter that would populate `retrieval.snippets` runs in `runCollect()` — a **different path**
from the hook-time preflight. The only escalation that would call docgraph inside preflight is JEV, and
JEV is `off` on these consumers. So `lawText` is empty, `requiredDocTerms` never matches, and a `law`
gap is emitted **every turn on every consumer** with a `tools` or `backend` bucket.

Combined with H1, that is a closed loop: the gap cannot be avoided and cannot be closed.

**Fix direction:** run the law adapter for `lawQueries` once inside preflight, cached under
`.harness/cache/docgraph/` (TTL already exists), before `detectGaps`. Cheaper alternative: make a
consumer that cannot pre-fetch law emit no law gap rather than an unclosable one.

### H5 · The `code` gap closes on any path at all

`eso-gap-io.mjs:119-120`:

```js
if (kind === 'code' && READ_COUNT_GAP_RE.test(query)) {
    if (extractFilePath(toolInput)) return true;
```

No path filter. Reading `.cursor/skills/eso-recon/SKILL.md` closes a gap whose stated purpose is "prove
the project's code was inspected". Reading a file in a *different repo* closes it too. The gap text —
`need at least 1 file read(s); have 0` — is also written as an accusation when it means "at turn
start" (the probe fires before the first tool call).

**Fix direction:** require the path to be inside the preflight root and to match the bucket's
`codeQueries`; at minimum exclude `.cursor/`, `.agents/`, `.harness/`, `node_modules/`.

### H6 · `verify-consumer.sh` is blind to all of the above

The T0–T5 standard checks that files **exist**. It never:

- runs `token-diet` (the CLI has it; the standard does not call it),
- checks whether a gap is closable,
- compares `decision-policy.paths` against `host-pack/path-policy.default.json`.

Both T5 consumers on this machine are **red on `token-diet`** and report `pass=25 fail=0`. A green
score next to a red linter is the definition of a check that measures the wrong thing.

**Fix direction:** `token-diet` becomes a real T-check with `frontmatterIntegrity` as a CRITICAL sub-
assertion, and T3.4 gates on the zone **path existing**, not on the scope line being written.

### H7 · `*mcp.json` is not in `privacy.denyPathPatterns`

Covered today: `.env`, `credentials`, `session/*.json`, `typesafe.env`. Covered: `.cursor/mcp.json` for
**writes** only. So an agent doing the most natural first probe — reading its own MCP config to see
which servers are wired — lifts a live Atlassian token into model context, and repeated it on two
consumers. Three of four session logs flagged it against themselves.

**Fix direction:** add `**/mcp.json` env blocks to the deny-read set, or ship a reader that redacts
`env` before the content reaches the model.

## 3. Claims that do NOT reproduce — do not "fix" these

Recorded because a report in the artifacts is not evidence, and an agent acting on a false positive
writes a patch for a bug that does not exist.

### D3 · "guard commands are emitted as bare `python`" — not from this tree

The emitters are `profiles/host/cursor-superset.json:35` and `agents-superset.json:38`:

```text
bash -lc 'export HARNESS_TREE=cursor; exec node .harness/host-pack/harness-hook.mjs --hook guard-shell --tree cursor'
```

No `python` anywhere. `ensureConsumerGuards()` (`host-install.mjs:177`) only *copies* `.py` files and
emits no command. Searching `baplatform/.cursor/hooks.json`, `.agents/hooks.json` and
`.harness/host-install-state.json` for `"python ` returns zero commands.

The symptom reported (exit 127, every shell denied) may well have happened; the cause was not this
code. Most likely a stale hook entry in the host's own settings, predating the pack, surviving the
repo-level `.cursor/hooks.json` deletion — which the report itself noticed and misread as evidence for
its theory.

### D2 · points at a module that no longer exists

The report cites `harness/evidence-sufficiency-orchestrator/src/eso-preflight.mjs`. That path is from
the archived design. The behaviour it describes is real — H4 above — but the file is not. A report
naming a deleted module is a report written from memory.

### F-C / F-3 / "evaluated only the first tool round"

This appeared in three of four logs. The tracker evaluates **every** round; `recordGapToolUse` runs on
each `postToolUse`. The gap simply never matches (H1). This distinction decides the fix: a
"first round only" bug is fixed by re-evaluating, and re-evaluation already happens — it would change
nothing.

## 5. Order of work

H1 alone unblocks the deadlock; H1 without H4 reproduces it through a different door; H2/H3 are what
makes the *next* report truthful even when a gap is stuck.

| Order | Item | File | Why this order |
|---|---|---|---|
| 1 | H1 | `eso-gap-io.mjs` | without it no consumer can close a law gap by reading law |
| 2 | H4 | `collect.mjs` + preflight | removes the gap that H1 has to make closable |
| 3 | H2 + H3 | `eso-gap-io.mjs` | one change: recompute score, write on every transition |
| 4 | H5 | `eso-gap-io.mjs` | same file; stops the false-positive closure |
| 5 | H6 | `verify-consumer-cmd.mjs` + standard JSON | makes a green verdict mean something |
| 6 | H7 | `path-policy.mjs` / policy defaults | stops the routine credential read |

Regression cases already drafted in the baplatform artifact and correct as written:

| Tool input | Gap | Expected |
|---|---|---|
| `Read { path: '.cursor/rules/core.pipeline-gate.mdc' }` | `law:pipeline-gate` | **closes** (H1) |
| `Grep { pattern: 'pipeline-gate' }` | `law:pipeline-gate` | closes |
| `Read { path: 'AGENTS.md' }` | `law:pipeline-gate` | stays open |
| `Read { path: '.cursor/skills/eso-recon/SKILL.md' }` | `code:need at least 1 …` | **stays open** (H5) |
| `Read { path: 'packages/…/eso-gap-io.mjs' }` | `code:need at least 1 …` | closes |

They belong in `packages/harness-host-generic/src/eso-gap-io.test.mjs` next to the existing cases.
