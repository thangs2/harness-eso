# Observe API

**Read-only monitor API**, served by `harness-observe-server` on **`:8792`**, alongside the built
Observatory SPA at `/`.

Everything prefixed `/api/` is JSON unless stated otherwise. Mutations exist but are limited to
operator controls (toggle tracking, run ingest, switch project) — the monitor cannot change what it
displays.

## Endpoints

| Method | Path | Returns |
|---|---|---|
| `GET` | `/health` | liveness, for Docker healthchecks |
| `GET` | `/api/version` | server build/version |
| `GET` | `/api/tenant` | the project this instance serves |
| `GET` | `/api/tenants` | all known tenants |
| `GET` | `/api/workspace`, `/api/workspace/…` | product-state index: projects, current selection |
| `GET` | `/api/requests` | **request list**, filtered and paginated |
| `GET` | `/api/requests/<id>` | **request detail** — the big one |
| `GET` | `/api/calls` | model-call rows |
| `GET` | `/api/decisions` | decision-ledger rows |
| `GET` | `/api/decision-flow` | the per-request flow view-model |
| `GET` | `/api/aggregates` | rollups for the dashboard |
| `GET` | `/api/brain/graph.json` | **brain graph** — nodes/links composed from this DB for the `/brain` page; `meta.omitted` / `meta.truncated` carry the honest gaps |
| `GET` | `/api/brain/file?path=…` | one file's text for the Brain card. Allowlisted to `note` nodes of the graph, real-path confined to the project root, text extensions only, 512 KB cap |
| `GET` | `/api/route/graph.json` | the static route/rule graph (no Observatory page reads it any more — see note) |
| `GET` | `/api/ingest/status` | ingest diagnostics |
| `POST` | `/api/ingest/run` | run one ingest cycle **now** |
| `GET` | `/api/toggle` | tracking state |
| `POST` | `/api/toggle` | pause/resume tracking |
| `POST` | `/v1/preflight` | preflight over HTTP (**not** used by hooks — see note) |
| `GET` | `/api/live` (SSE) | `event: live` snapshots of the whole feed |

**`/api/brain/graph.json`** is derived, never stored: the server composes it from `project`,
`request`, `request_file`, `request_rule`, `request_tool` and `event`, and memoises it on a
fingerprint of the database file *and its WAL*. It reads no `route-graph.json`: that artifact was
never a contract of this package, which is also why the Observatory no longer has a `/graph` tab.

**`/api/brain/file`** is the only route that reads an arbitrary path, so it carries two independent
gates: the path must be a `note` node the caller can already see (the DB decided which paths exist),
and the *real* path — symlinks resolved — must stay inside the project root, checked with a separator
so `/root-evil` cannot pass as `/root`. Non-text extensions, NUL bytes and oversized reads are
refused or truncated with `truncated: true`; nothing is written.

### Query parameters

| Param | Used by | Meaning |
|---|---|---|
| `limit`, `offset` | list endpoints | pagination |
| `requestId` | `/api/calls`, `/api/decisions`, `/api/decision-flow` | scope to one turn |
| `conversationId` | list endpoints | scope to one conversation |
| `jevMode`, `eventType` | `/api/decisions` | filter ledger rows |
| `q` / `kind` | `/api/decisions` | text / kind filtering |

### `GET /api/requests/<id>`

Where `id` is `<conversationId>:<boundaryIndex>`. Use `%3A` for the colon.

This single response is the largest surface (tens of KB) and is worth knowing structurally, because
almost every UI defect in this project traced to one of its fields meaning something subtly different
from its name:

| Field | Meaning | Watch out |
|---|---|---|
| `request` | the turn row | `generation_id` may be a placeholder |
| `requestMetrics` | header numbers | `callCount` = **model** calls; `toolCount` = tool uses; `mcpToolCalls`/`mcpToolKinds` = **tool** calls over MCP. These are three different quantities. |
| `mcpCallStats` | per-turn model-call summary | `brain*` are null when unreported; `jevCount` is decisions, not MCP calls |
| `tokenSummary` | dispatcher tokens, plus `source` and `estimated` | `source: "transcript-est"` means **output is estimated** from text length, and input is unknown — never a measurement |
| `checks[]` | the five conformance verdicts | `heuristic` flag says how strongly to read it |
| `rules[]` / `attached[]` | rules in force | two sources: `request_rule` (from the prompt link) and event-derived attachments. They agree after `F36`; historically one was empty |
| `files[]` | paths touched with `reads`/`edits` | see the shell-write trap in the data model |
| `tools[]` | tool counts | rolled up from hooks when available, else from transcript |
| `evidence` / `eso` | ESO verdict and gaps | `score` + `gaps` must be consistent |
| `consent` | human approval state | `outcome: continue` also means "nothing was required" — check `liveCount`/`path` to tell "approved" from "not needed" |
| `decisionFlow.graph` / `flowGraph` | the graph view-models | |
| `llmCalls[]` | per-call rows with resolved tool names | |
| `stops[]` | `stop` payloads | the **dispatcher's** tokens |

### SSE: `event: live`

A named `live` event carries a whole-feed snapshot (`revision`, totals, turns). Two consequences:

- A client that reconnects must tolerate a full snapshot replacing its state, not a delta.
- There is a **legacy** live snapshot path (`buildLive`, `route-watch.mjs`) as well as the modern REST
  detail. Both exist; the REST path is the one the SPA uses for a request page.

## `POST /v1/preflight`

Documented here because its existence is misleading. Preflight runs **inside the host pack** on
`beforeSubmitPrompt`, locally, so it works with no server and no Docker. This HTTP route is a
convenience for scripts to ask the same question; **no hook calls it**, and wiring a hook to it would
make every prompt depend on the observe plane being up — which is exactly the coupling the standalone
host pack was built to remove.

## Error behaviour

| Situation | Response |
|---|---|
| unknown `/api/…` path | **404 JSON** — not the SPA's HTML fallback |
| unknown non-API path | the SPA `index.html` (client-side routing) |
| a handler throws | 500 with a JSON error |

The 404 rule is not cosmetic: before it, an unknown API path returned the SPA HTML with a **200**, so a
typo in a client request looked like a successful response containing HTML (`F27`).

## Console API (`:8791`) — the write side

Different process, different port, and it is the only place that mutates. The route set is small:

| Method | Path | Effect |
|---|---|---|
| `GET` | `/api/meta` | liveness + build info |
| `GET` | `/api/projects` | list registered projects |
| `POST` | `/api/projects` | register a project |
| `GET` | `/api/projects/<id>` | read one |
| `PATCH` | `/api/projects/<id>` | update one |
| `GET` | `/api/projects/<id>/preview` | show the provision plan, change nothing |
| `POST` | `/api/projects/<id>/provision` | apply the provision plan |
| `POST` | `/api/projects/<id>/reload` | rewrite consumer host config; `{"tenant":true}` also rewrites `harness.config.json` |
| `GET` | `/api/projects/<id>/observe-health` | probe the project's observe plane |
| `GET` | `/api/projects/<id>/consent` | live and all consent records |
| `POST` | `/api/projects/<id>/consent` | **grant consent** — the only writer |
| `DELETE` | `/api/projects/<id>/consent` | revoke, by `path` or `id` |
| `GET` | `/api/host-profiles`, `/api/plugin-catalog` | profiles and plugin options for the wizard |
| `GET`/`POST` | `/api/jev/status`, `/api/jev/smoke-test` | Jev reachability |

`preview` vs `provision` is a deliberate split: a plan can be inspected before anything is written.
