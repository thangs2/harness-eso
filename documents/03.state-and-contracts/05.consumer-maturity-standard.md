# Consumer Maturity Standard — Contract for Verify / Diagnostic

> **Document ID:** `HARNESS-ESO-CONTRACT-05-CONSUMER-MATURITY`  
> **Machine SoT:** [`profiles/standards/consumer-maturity.v1.json`](../../profiles/standards/consumer-maturity.v1.json)  
> **Ops checklist (narrative):** [`../04.operations/08.consumer-maturity-checklist.md`](../04.operations/08.consumer-maturity-checklist.md)  
> **Behaviour:** `harnessctl verify consumer` · `./verify-consumer.sh`

---

## 1. Purpose

Every **consumer** (repo that installs Harness ESO) is different. Provision alone cannot prove maturity. This standard defines **read-only probes** that:

1. Score the consumer against tiers **T0–T5**.  
2. Emit a **diagnostic evaluation file** under the consumer.  
3. Attach **remediation hints** (provision / sync / docs) — never silent domain invention.

```text
provision  →  install / refresh host surface
verify     →  diagnose vs this standard → .harness/diagnostics/*
fix        →  human/agent applies remediations from the diagnostic (domain-aware)
```

---

## 2. Law

| Rule | Meaning |
| :--- | :--- |
| **Verify is read-only** | Must not rewrite consumer hooks, policy, or source during diagnostic. |
| **Mechanism vs domain** | Probes check harness *mechanism*. Failed T3+ remediation must be authored for **that** consumer (INV names, packages). Forbidden: copy baplatform ABP/Jira rules wholesale. |
| **Severity** | `CRITICAL` fails the command (exit 1). `WARN` / `INFO` appear in the report but do not fail unless `--strict`. |
| **Versioned standard** | Machine file `consumer-maturity.v1.json`. Bumps require a new `v2` file + doc update — do not silently change probe semantics in place. |

---

## 3. Diagnostic artifact schema

Written to:

- `<consumer>/.harness/diagnostics/latest.json`  
- `<consumer>/.harness/diagnostics/latest.md`  
- `<consumer>/.harness/diagnostics/<ISO-stamp>.json` (+ `.md`)

```json
{
  "ok": true,
  "standardId": "consumer-maturity",
  "standardVersion": "1.0.0",
  "consumerRoot": "/abs/path",
  "consumerId": "fineso",
  "at": "2026-10-19T15:00:00.000Z",
  "summary": {
    "pass": 12,
    "fail": 3,
    "skip": 0,
    "criticalFail": 0,
    "tierReached": "T2"
  },
  "checks": [
    {
      "id": "T0.1",
      "tier": "T0",
      "title": "…",
      "severity": "CRITICAL",
      "status": "PASS|FAIL|SKIP",
      "evidence": "…",
      "remediation": { "action": "provision|sync|docs", "hint": "…" }
    }
  ]
}
```

**`tierReached`:** highest tier whose **CRITICAL** checks all PASS (WARN/INFO may still fail).

## 4. CLI contract

```bash
# From harness-eso root
./verify-consumer.sh fineso
./verify-consumer.sh all
./verify-consumer.sh fineso --json
./verify-consumer.sh fineso --strict

harnessctl verify consumer <path|--project <id>> [--json] [--strict] [--out <dir>]
```

| Exit | Meaning |
| :---: | :--- |
| 0 | No CRITICAL failures (`--strict`: also no WARN) |
| 1 | One or more CRITICAL failures (or WARN under `--strict`) |
| 2 | Usage / unknown consumer / standard missing |

---

## 5. Relationship to host-pack status

| Command | Scope |
| :--- | :--- |
| `harnessctl host-pack status` | Pack integrity + hook wiring only |
| `harnessctl verify consumer` | Full maturity T0–T5 vs this standard (includes host surface + SDLC/recon/SLP) |

Prefer **verify consumer** for upgrade planning; use **host-pack status** for “hooks broken?” triage.

## 7. Fix behaviour (semi-auto)

```bash
./fix-consumer.sh fineso
./fix-consumer.sh fineso --dry-run
harnessctl fix consumer /path/to/FinESO --from-latest
```

| Class | Actions | Effect |
| :--- | :--- | :--- |
| **AUTO-SAFE** | `provision`, `sync` (WORKFLOW_GUIDE + session dirs + **T3.4** `docgraph.scope` Agent Zone path line), `host-pack-refresh` | Applied by fix |
| **OPEN (never auto)** | `docs` (context-contract, manifest *specs*, eso-coverage, jira, domain INV) | Written to `.harness/diagnostics/OPEN_FIXES.md` |

**T3.4 (v1.1.0):** `docgraph.scope` must contain an explicit `path:sdlc/00.agent-manifests` or `path:SDLC/00.agent-manifests` line (Agent Zone listed separately from Human Zone `path:sdlc` / `path:SDLC`). Probe type: `file_contains_any`. `fix-consumer` appends the line when the manifests directory already exists; it never authors domain `.spec.md` files.

Flags: `--dry-run` · `--force-provision` (opt-in) · `--no-provision` · `--from-latest` · `--strict` (fail if OPEN docs remain) · `--json`.

After safe fixes, fix re-runs verify and refreshes `latest.{json,md}`.
