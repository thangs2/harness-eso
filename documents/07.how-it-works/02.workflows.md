# 02 — Workflows: một phiên chạy qua những bước nào

## 1. Vòng đời một turn (host pack)

```mermaid
sequenceDiagram
  autonumber
  participant U as Người dùng
  participant H as Host (IDE/DSH)
  participant P as Host pack / plugin
  participant C as eso-core
  participant R as Providers
  participant S as Session state

  U->>H: prompt
  H->>P: UserPromptSubmit / agent/pre-step
  P->>C: orchestrateTurn(event)
  C->>C: decide() — L0 route + JEV
  C->>R: law / code / memory (theo registry)
  R-->>C: snippets + trace
  C->>C: scoreSufficiency → gaps
  C->>C: buildTurnVerdict(blockers)
  alt hard blocker
    P-->>H: reject + ghi trail (TRƯỚC)
  else thiếu bằng chứng
    P-->>H: additionalContext (hint) · allowPromptSubmit theo policy
  else đủ
    P-->>H: allow
  end
  P->>S: .eso-preflight.json + route-trace.jsonl

  H->>P: PreToolUse / tools/pre-execute
  P->>C: decideToolCall(path tier) hoặc guards trong pack
  alt locked / không quyết được
    P-->>H: deny + reason (model thấy)
  else gated không consent
    P-->>H: ask / deny (tuỳ askMode)
  else
    P-->>H: allow
  end

  H->>P: PostToolUse / tools/post-execute
  P->>S: gap-tracker + post-tool-hint

  H->>P: PreCompact (chỉ host pack)
  P->>S: ghi chi phí context
```

Hai điểm bất biến: **preflight không chặn hội thoại** (trừ hard blocker), và **mọi quyết định chặn ghi
trail trước khi trả về**.

## 2. Rẽ nhánh của gate (một hình để tra nhanh)

```mermaid
flowchart TB
  IN["Tool call / prompt"] --> KIND{"Loại"}
  KIND -->|"prompt"| PB{"eso.checks báo\nhard blocker?"}
  PB -->|"có"| REJ["reject + trail"]
  PB -->|"không"| PASS1["đi tiếp"]

  KIND -->|"write / shell"| MODE{"path tier"}
  MODE -->|"locked"| DENY["deny + trail"]
  MODE -->|"ask"| ASK{"askMode"}
  ASK -->|"deny (mặc định)"| DENY2["deny + hướng dẫn + trail"]
  ASK -->|"host"| ASKH["ask cho host"]
  MODE -->|"gated"| CON{"consent còn hạn?"}
  CON -->|"có"| PASS2["đi tiếp"]
  CON -->|"không"| ASK
  MODE -->|"không tier"| PASS3["không ý kiến"]
```

`askMode: "host"` là lựa chọn có ý thức: trên DSH, `ask` **không phải** gate (đã đo — write lọt), nên
mặc định ESO deny.

## 3. Cài đặt consumer mới (host pack)

```mermaid
flowchart LR
  A["consumer repo"] --> B["harnessctl init profile <path>\n--host-mode dual-ide|all-ide|claude|superset"]
  B --> C["installHostPack\n(.harness/host-pack + manifest)"]
  C --> D["applyHostTree cho từng tree\n(cursor · agents · claude)"]
  D --> E["mergeHooksDocument\n(chỉ thêm entry của ESO)"]
  E --> F["write .harness/host-install-state.json\n+ host-bootstrap.json"]
  F --> G["verifyHostPack\n(mỗi hook phải chạy được)"]
  G -->|"fail"| X["dừng, báo lỗi"]
  G -->|"ok"| H["harnessctl verify host\nH0–H5"]
  H --> I["observe: harnessctl observatory up\n(:8792)"]
```

Consumer đã có pack thì **không chạy lại toàn bộ**: thêm một IDE bằng
`harnessctl host-pack add-ide <consumer> --profile claude-superset`.

Gỡ một tree (giữ hook của consumer):

```mermaid
flowchart LR
  R["remove-ide --ide <tree>"] --> S{"state có tree?"}
  S -->|"có"| T["prune entry của ESO trong hook config"]
  S -->|"không"| U["bỏ qua hook"]
  T --> V["xoá state.hooks[tree]"]
  U --> W["vẫn dọn bootstrap"]
  V --> W
  W --> Z["drop profile id khỏi host-bootstrap.json"]
```

## 5. Kiểm chứng một host (conformance H0–H5)

```mermaid
flowchart LR
  X["verify host <consumer>"] --> H0{"H0 hook config\ngọi harness-hook.mjs?"}
  H0 -->|"không"| STOP0["dừng — chưa nối"]
  H0 -->|"có"| H1{"H1 pack có mặt\n+ guard wired?"}
  H1 --> H2{"H2 .eso-preflight.json\ncó level + at?"}
  H2 --> H3{"H3 route-trace\n≥1 event?"}
  H3 --> H4{"H4 native provider?\n(chỉ khi --require-native)"}
  H4 --> H5{"H5 gate ngoài\neditable surface?"}
  H5 --> OK["ok = H0..H3 ∧ H5 ≠ fail"]
```

H4/H5 **không chặn mặc định**: H4 `skip` khi không có shim; H5 `skip` khi consumer không khai
`harnessSurface`. Một consumer không dùng optimizer vẫn đạt H3.

## 7. Quan sát sau phiên (observe plane)

```mermaid
flowchart LR
  T1["transcript của host\n(.cursor/.agents jsonl)"] --> I["ingest worker\npoll mỗi N ms"]
  S1["session artifacts\n.preflight · route-trace · gaps"] --> I
  I --> N["normalize theo shape\n(cursor | antigravity)"]
  N --> L[("SQLite\n.harness/harness.db → ~/.harness/observe/")]
  L --> A["REST :8792"]
  A --> O["Observatory UI"]
  A --> C["Console :8791\n(provision, projects, tenants)"]
```

Điều **không** xảy ra: ingest không quyết định gì, và dashboard không phải nguồn của verdict. Số trên
UI là replay; muốn kết luận phải đọc `reads`/event gốc.

## 8. Bảng: việc gì chạy ở đâu

| Việc | Host pack | DSH plugin | CLI |
|---|---|---|---|
| Preflight + verdict | ✅ `preflight` hook | ⛔ (chỉ checks) | ✅ `capability probe` |
| Chặn write theo path tier | ✅ `guard-shell` + consumer `guard-write.py` | ✅ `tools/pre-execute` | — |
| Chặn prompt vì hard blocker | ⛔ | ✅ `agent/pre-step` | — |
| Hint sau tool | ✅ `post-tool-hint` | ⛔ (chưa) | — |
| Chi phí context trước compact | ✅ `pre-compact` | ⛔ (bridge không hỗ trợ) | — |
| Trail quyết định | session artifacts | `~/.harness/eso-blockers.jsonl` | — |
| Conformance / doctor | — | — | ✅ |
