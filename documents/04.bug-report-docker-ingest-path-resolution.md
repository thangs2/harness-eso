# Báo Cáo Kỹ Thuật: Lỗi Nhận Diện Request FinESO Trên Port :8794 (Docker Ingest Path Remapping Bug)

> **Mã lỗi:** `BUG-HARNESS-INGEST-DOCKER-PATH-01`  
> **Dự án bị ảnh hưởng:** `harness-eso` (`harness-observe-server`), các consumer chạy qua Docker (`FinESO`).  
> **Mức độ nghiêm trọng:** **Critical** (Chặn hoàn toàn khả năng thu thập telemetry và audit log của agent trong môi trường đóng gói container).  
> **Ngày phát hiện:** 15/10/2026.

---

## 1. Tóm Tắt Hiện Tượng (Symptoms)

* Người dùng làm việc trên workspace **`FinESO`**, gửi nhiều câu lệnh/prompt cho AI Agent (Google Antigravity / Cursor).
* Dashboard Harness Observatory của FinESO cấu hình tại cổng **`:8794`** (`http://127.0.0.1:8794/requests`) **không hiển thị bất kỳ request nào** (hoặc chỉ hiển thị các request không có metadata tài liệu).
* Trong khi đó, cổng **`:8792`** (thuộc dự án `x79`) lại ghi nhận danh sách request bình thường, gây hiểu lầm rằng request của FinESO đang bị gửi nhầm sang port `:8792`.

---

## 2. Nguyên Nhân Gốc Rễ (Root Cause Analysis)

### A. Sự khác biệt giữa môi trường x79 (Native Host) và FinESO (Docker)
* **x79 trên port `:8792`:** Chạy bằng tiến trình Node thuần trực tiếp trên máy Host (`node packages/harness-observe-server/src/server.mjs --root ../x79 --port 8792`). File system của server trùng khớp 100% với file system của máy phát triển.
* **FinESO trên port `:8794`:** Chạy bên trong Docker container (`harness-observatory-8794-observe-server-1`), mount `/Users/thangs2net/Workspaces/FinESO` vào `/data/repo` (read-only).

### B. Bug thẩm định quyền sở hữu Transcript (`projectRootOf` trong `ingest-transcript.mjs`)
1. Mỗi khi Antigravity ghi nhận một tương tác của người dùng, file transcript (`~/.gemini/antigravity-ide/brain/<id>/.system_generated/logs/transcript.jsonl`) lưu thông tin cửa sổ làm việc:
   ```text
   Active Document: /Users/thangs2net/Workspaces/FinESO/.cursor/rules/core.pipeline-gate.mdc (LANGUAGE_UNSPECIFIED)
   ```
2. Container `:8794` quét qua thư mục `~/.gemini/...` (được mount tại `/host-gemini`) và gọi hàm thẩm định quyền sở hữu `resolveTranscriptOwnerInfo(transcriptPath)`.
3. Hàm này bóc tách `docPath` thành `/Users/thangs2net/Workspaces/FinESO/.cursor/rules/core.pipeline-gate.mdc` và gọi:
   ```javascript
   function projectRootOf(filePath) {
       let cur = path.dirname(filePath);
       let repoRoot = null;
       for (let i = 0; i < 24; i += 1) {
           if (fs.existsSync(path.join(cur, 'harness.config.json'))) return cur;
           ...
       }
       return repoRoot;
   }
   ```
4. **Điểm gãy (The Defect):** Bên trong Docker container, đường dẫn `/Users/thangs2net/Workspaces/FinESO` **không hề tồn tại** (nó nằm ở `/data/repo` hoặc `/agent-repos/FinESO`).
5. Kết quả:
   * `fs.existsSync(...)` luôn trả về `false`.
   * `projectRootOf` trả về `null` $\to$ `owner` là `null`.
   * Nhưng vì transcript có trường `Active Document:`, biến `hasMetadata` được gán `true`.
   * Hàm `discoverTranscripts` kích hoạt điều kiện loại trừ:
     ```javascript
     if (hasMetadata) {
         // The transcript has window metadata, but none of its documents belong to this project
         continue; // => BỎ QUA HOÀN TOÀN!
     }
     ```
6. **Hậu quả:** 100% transcript làm việc của Antigravity trên FinESO bị coi là "thuộc dự án khác bên ngoài" và bị engine Ingest loại bỏ, dẫn đến dashboard `:8794` rỗng.

Chạy kiểm chứng trực tiếp logic `projectRootOf` bên trong container `harness-observatory-8794-observe-server-1`:

```bash

const fs = require("fs");
const path = require("path");

function projectRootOf(filePath) {
    let cur = path.dirname(filePath);
    let repoRoot = null;
    for (let i = 0; i < 24; i += 1) {
        if (fs.existsSync(path.join(cur, "harness.config.json"))) return cur;
        const up = path.dirname(cur);
        if (up === cur) break;
        cur = up;
    }
    return repoRoot;
}

```

###  Cách 2: Sửa Path Resolver trong Docker Ingest Server
> **Phạm vi áp dụng:** **Giải pháp chuẩn bắt buộc (Production-Grade Fix) cho nền tảng Harness ESO.**

* **Mục tiêu:** Cho phép `harness-observe-server` nhận biết được sự khác biệt giữa đường dẫn máy Host và đường dẫn được Mount trong Container thông qua các biến môi trường đã có sẵn trong Docker Compose:
  * `HARNESS_REPO_ROOT_HOST`: Thư mục gốc dự án trên máy host (ví dụ `/Users/thangs2net/Workspaces/FinESO`).
  * `HARNESS_AGENT_ROOT_HOST`: Thư mục chứa các workspaces (ví dụ `/Users/thangs2net/Workspaces`).
  * `HARNESS_AGENT_MOUNT`: Thư mục mount trong container (mặc định `/agent-repos`).
  * Container repo root: `/data/repo`.

#### Đề xuất Patch kỹ thuật cho `packages/harness-observe-server/src/ingest-transcript.mjs`:

```javascript
/**
 * Ánh xạ đường dẫn Host ghi trong Transcript sang đường dẫn hợp lệ bên trong Container (nếu chạy Docker).
 * @param {string} rawPath
 * @returns {string}
 */
function normalizeDocPathForContainer(rawPath) {
    const hostRepo = process.env.HARNESS_REPO_ROOT_HOST;
    if (hostRepo && rawPath.startsWith(hostRepo)) {
        return path.join('/data/repo', rawPath.slice(hostRepo.length));
    }

    const hostAgentRoot = process.env.HARNESS_AGENT_ROOT_HOST;
    const containerAgentMount = process.env.HARNESS_AGENT_MOUNT || '/agent-repos';
    if (hostAgentRoot && rawPath.startsWith(hostAgentRoot)) {
        return path.join(containerAgentMount, rawPath.slice(hostAgentRoot.length));
    }

    return rawPath;
}
```

* Trong hàm `resolveTranscriptOwnerInfo`:
  ```javascript
  const vote = (docLine) => {
      const normalizedPath = normalizeDocPathForContainer(docPath(docLine));
      const root = projectRootOf(normalizedPath);
      if (root) votes.set(root, (votes.get(root) ?? 0) + 1);
  };
  ```

* Khi so khớp quyền sở hữu trong `discoverTranscripts`:
  ```javascript
  // Nếu owner là /data/repo hoặc khớp với root cấu hình trong container
  if (path.resolve(owner) === root || (process.env.HARNESS_REPO_ROOT_HOST && path.resolve(owner) === '/data/repo')) {
      out.push(logFile);
      continue;
  }
  ```
