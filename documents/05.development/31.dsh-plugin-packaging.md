# 31 — harness-eso như một plugin DSH (package, không patch DSH)

> Ràng buộc mày đặt ra, ghi thành luật cho mọi việc sau:
> **1)** DSH là hộp đen — không sửa, không touch code DSH. **2)** harness-eso là plugin — phải đóng gói
> được thành package. **3)** Cài bằng **Plugins → harness-eso** trong DSH, không sửa profile bằng tay.
>
> Trạng thái: phân tích. Chưa implement. Nguồn: package `@deepseek-ai/dsh-hooks-claude-code@0.2.1-rc.2`
> (đọc từ tarball) + `app.asar` 0.2.1-rc.2, chỉ đọc.

## 1. Vì sao đường cũ sai (không phải vì code sai)

Đường cũ: bundle của ESO **trỏ** tới `@deepseek-ai/dsh-hooks-claude-code` (một package không có trong
`app.asar`). Row chỉ là một dòng `name:`; package đó phải được cài vào profile, và nó kéo theo
peerDependencies là các package **app đã ship**. Kết quả: hai instance `dsh-tools` ⇒ `Symbol()` khác
identity ⇒ mọi tool call chết ở `.prepare()` (ATF-OPS-001, `30 §7`).

Bài học không phải "đừng cài plugin", mà là: **plugin không được kéo bất kỳ package nào mà app đã ship**.
Điều đó chỉ đúng nếu plugin **tự chứa** (zero dependency) và **không import `@deepseek-ai/*`**.

## 2. Hợp đồng plugin DSH — những gì đã kiểm chứng

Plugin = `{ name, inject?, apply(ctx, config) }`. `ctx.on(event, handler)` với `next()` trả decision.
Bảy điểm can thiệp, đọc trực tiếp từ bridge (cùng API công khai, không phải API nội bộ):

| Điểm | Payload | Trả về | ESO dùng để |
|---|---|---|---|
| `agent/created` | `{agent, source, signal}` | — | ghi nhận session (evidence) |
| `agent/pre-step` | `{agent, messages, turn, signal}` | `{kind:'reject'}` hoặc `next()` (decision `kind:'enter'` + `messages`) | chặn prompt / bơm context |
| **`tools/pre-execute`** | `(exec, next)`; `exec.name`, `exec.arguments`, `exec.agent` | `{kind:'deny', reason}` · `{kind:'ask', reason}` · `next()` | **guard write/shell — enforcement thật** |
| `tools/post-execute` | `(exec, result, next)` | `{kind:'block', feedback:[{type:'text',text}], additionalContexts}` | hint sau tool |
| `agent/turn-stopping` | `{agent, turn, signal}` | — | chốt turn, ghi evidence |
| `subagent/start` · `subagent/end` | `info` | — | attribution |

Hai chỗ adapter hiện tại của ESO **sai** (đã lộ khi đọc bridge):

1. `agent/pre-step` payload có `turn`, **không phải** `step`; decision của host là `kind:'enter'`, không
   phải `'continue'`. Chỉ được thêm message khi `downstream.kind === 'enter'`.
2. Bridge **append** message vào cuối `downstream.messages` (`[...downstream.messages, ours]`), không
   chèn "sau message cuối đã claimed" như `cordis.mjs` đang làm.

## 3. Kiến trúc đích

```
packages/harness-eso-dsh/            ← package mới, ZERO dependency
  src/plugin.mjs                     ← { name, inject, apply(ctx, config) }
  src/guards.mjs                     ← tái dùng path-policy/shell-writes/consent từ foundation
  dist/eso-plugin.mjs                ← build self-contained (bun build, 0 external import)
  cordis.patch.yml                   ← insert row: name: harness-eso-dsh/plugin
  package.json                       ← exports ./plugin; dsh.bundle.patch
```

Luồng cài: **Plugins → install bundle → chọn `@mu/harness-eso-dsh`** → DSH link package (không có dep
nào để pnpm cài) → row `harness-eso-dsh/plugin` active → không reboot profile bằng tay.

Vì sao an toàn: plugin chỉ import `node:*` (sau khi bundle) ⇒ **không có đường nào** để pnpm hoist
`dsh-tools`/`dsh-llm`. Bất biến ATF-OPS-001 được bảo vệ bằng cấu trúc, không bằng lời dặn.

## 4. Map năng lực ESO → điểm can thiệp

| Năng lực ESO hiện có | Điểm DSH | Ghi chú |
|---|---|---|
| `guard-shell` (shell writes → path policy) | `tools/pre-execute` khi `exec.name` là bash/pwsh | trả `{kind:'deny', reason}` — reason model thấy |
| `guard-write` (Write/Edit vào path bảo vệ) | `tools/pre-execute` khi `exec.name` là write/edit | cần đọc `exec.arguments.path` |
| consent (`ask`) | `tools/pre-execute` → `{kind:'ask'}` | tương đương HIL của DSH |
| `post-tool-hint` | `tools/post-execute` → `{kind:'block', feedback}` | hint không chặn |
| preflight + evidence gap | `agent/pre-step` | reject chỉ khi **hard blocker** |
| hard blocker (`eso.checks`) | `agent/pre-step` reject | mang `eso-blockers.jsonl` |
| route trace / ledger | `agent/created`, `agent/turn-stopping` | ghi product state |
| observe plane | không đổi (REST/observatory) | ngoài DSH |

**Điểm mất so với hook pack:** hooks `.claude/settings.json` trỏ tới `harness-hook.mjs` (process con,
fail-open nếu node lỗi). Plugin in-process: nhanh, nhưng một exception trong `apply` sẽ làm hỏng bước —
nên mọi handler phải `try/catch` và fail theo hướng đã chọn (B1: không quyết được thì deny, nhưng chỉ
ở kênh write/tool, không làm chết turn).

## 5. Câu hỏi phải trả lời trước khi code (P0)

| # | Câu hỏi | Cách trả lời không cần sửa DSH |
|---|---|---|
| Q1 | Row `name` có resolve được **chính bundle** (`harness-eso-dsh/plugin`) không? | Cài một bundle zero-dep tối giản, xem log activate; nếu fail thì fallback: bundle export plugin, row trỏ `@mu/harness-eso-dsh/plugin` |
| Q2 | ✅ **đã trả lời**: `exec.arguments` chính là tool input (`tool_input`), `exec.name` là tên tool, thêm `exec.callId`, `exec.agent`, `exec.signal` (đọc `preToolPayload` của bridge). Guard đọc `exec.arguments.command` / `.path` được ngay | — |
| Q3 | Message inject có bị session store từ chối nếu tự dựng `id`? | Để **phase sau**; P1 chỉ reject/deny (không cần message). Bridge dùng `[...downstream.messages, ours]` — append, không chèn giữa |
| Q4 | `inject` cần gì? | Bridge inject `['shell','sessionProjections','workingDirectory']`, nhưng handler trên không dùng service nào; thử `inject: []` trước |

## 6. Kế hoạch

| Phase | Nội dung | Test |
|---|---|---|
| **P0** | Bundle tối giản zero-dep: `apply` chỉ log + `ctx.on('tools/pre-execute')` trả `next()` | cài qua Plugins, chạy 1 tool, xem log; `doctor dsh` phải vẫn `healthy` |
| **P1** | `guard-shell`/`guard-write` thật (tái dùng `path-policy`, `shell-writes`, consent) → deny + reason | fake `exec` trong `qc/`; live: 1 lệnh ghi vào path bảo vệ phải bị chặn |
| **P2** | `agent/pre-step`: preflight + reject khi hard blocker; trail `eso-blockers.jsonl` | fake ctx; live: 1 prompt với `drop-table` trong `eso.checks` ⇒ step bị chặn, trail có record |
| **P3** | `tools/post-execute` hint + `agent/turn-stopping` evidence; cân nhắc message inject | fake ctx; chưa hứa gì về context trên UI |

Nguyên tắc giữ nguyên từ `26`/`30`: không score trên đường quyết định; marker `tenant:global` /
`breaking:approved` là quyết định, không phải finding; fail-closed chỉ ở kênh write.

## 7. Điều **không** làm

- Không sửa `~/.dsh`, không thêm row bằng tay, không `pnpm add` vào profile — mọi thứ qua Plugins.
- Không import `@deepseek-ai/*` (kể cả `dsh-llm` để lấy `createUserMessage`) — đó chính là đường dẫn
  tới ATF-OPS-001. Muốn context thì tự dựng message với `id` của mình, và chỉ khi test live chứng minh
  session store chấp nhận.
- Không bundle `dsh-hooks-claude-code` — bridge chỉ dùng được khi upstream sửa cách resolve.
