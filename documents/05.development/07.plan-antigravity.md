> **Mục tiêu:** Đảm bảo môi trường **Google Antigravity (`agy` / `.agents/`)** vận hành đồng nhất 100% với Cursor trên mọi repo consumer (`x79`, `baplatform`, `FinESO`), bao gồm:

> 2. **Observe Plane (Observatory):** Phân định chính xác chủ sở hữu transcript từ `~/.gemini/antigravity/brain`, hiển thị đúng số liệu Token / Net Input / Tool Evidence và badge `Antigravity`.

## 1. Tổng quan Kiến trúc Tích hợp Antigravity (`--tree agents`)

Khác với Cursor (dùng `.cursor/hooks.json` phẳng và lưu transcript theo từng workspace), Antigravity có **5 đặc thù kỹ thuật riêng** mà `harness-eso` phải xử lý:

1. **Protobuf Hook Output Schema nghiêm ngặt:**
   - Sự kiện `PreInvocation` / `PostInvocation` **chỉ** chấp nhận `{ "injectSteps": [...] }`.
   - Sự kiện `PreToolUse` chấp nhận `{ "decision": "allow" | "deny", "reason"?: string, "additionalContext"?: string }`.
   - Sự kiện `PostToolUse` và `Stop` **cấm tuyệt đối** trường `"decision"` — phải trả về `{}` và exit `0`, nếu không Antigravity sẽ báo lỗi parse Protobuf.
2. **Working Directory khi spawn hook:**
   - Antigravity đôi khi spawn hook với `cwd` nằm tại `<repo>/.agents` thay vì `<repo>`. Nếu không tự chuẩn hóa (`cd ..`), hook sẽ không tìm thấy `harness.config.json` và ghi nhầm `.agents/session` thành `.agents/.agents/session`.
3. **Thiếu `tool_input` ở sự kiện `PostToolUse`:**
   - Ở một số phiên bản runner Antigravity, payload `PostToolUse` chỉ báo tên tool hoàn tất mà không kèm đầy đủ tham số đường dẫn file (`AbsolutePath`, `TargetFile`, `SearchPath`), khiến `gap-tracker` không biết file nào vừa được đọc nếu không cache lại từ `PreToolUse`.
4. **Global Brain Transcript (`~/.gemini/antigravity/brain/<conversation-id>`):**
   - Mọi hội thoại của mọi repo đều nằm chung trong một thư mục global. Việc gán hội thoại về đúng project (`x79` hay `baplatform`) phải dựa trên việc parse `ADDITIONAL_METADATA` (`Active Document:` / `Other open documents:`) thay vì tìm kiếm chuỗi đường dẫn thô.
5. **Global MCP Config (`~/.gemini/antigravity/mcp_config.json`):**
   - Antigravity dùng file cấu hình MCP global thay vì `.cursor/mcp.json` theo từng repo.

## 3. Kế hoạch Hoàn thiện Phần Còn Lại để Đạt 100% Parity trên Antigravity

Dù phần lõi đã chạy, vẫn còn **5 hạng mục** cần hoàn tất để trải nghiệm cài đặt và quan sát trên Antigravity đạt 100% tự động hóa (zero-manual-step) như Cursor:

### Phase A: Đồng bộ Built-in ESO Write Gate vào `agents-superset.json`

- **Hiện trạng:** Trong [`profiles/host/agents-superset.json`](../../profiles/host/agents-superset.json), `PreToolUse` mới đăng ký `guard-shell`, `guard-brain`, `route`, trong khi việc chặn ghi file đang phụ thuộc vào `.agents/hooks/pre-tool-use.py` (gọi `guard-write.py`) do runbook tạo thủ công.
- **Công việc cần làm:**
  - [ ] **A.1.** Bổ sung slot `harness-eso-guard-write` vào [`profiles/host/agents-superset.json`](../../profiles/host/agents-superset.json) với matcher `"write_to_file|replace_file_content|multi_replace_file_content"` gọi `--hook guard-write --tree agents --event PreToolUse`.
  - [ ] **A.2.** Trong [`packages/harness-host-generic/src/guard-write-hook.mjs`](../../packages/harness-host-generic/src/guard-write-hook.mjs), đảm bảo `WRITE_TOOL_RE` khớp đầy đủ `write_to_file`, `replace_file_content`, `multi_replace_file_content` và trích xuất đúng `TargetFile` từ `tool_input`.
  - [ ] **A.3.** Rebuild host pack (`bun run build:host-pack`) để `dist/host-pack/harness-hook.mjs` chứa đầy đủ thay đổi mới nhất.

### Phase B: Tự động hóa Provisioning `.agents/rules/` và `.agents/skills/` trong `host-install.mjs`

- **Hiện trạng:** Khi chạy `./harness init profile ../<consumer> --id <id> --host-mode dual-ide`, [`host-install.mjs`](../../packages/harness-foundation/src/host-install.mjs) đã merge `.agents/hooks.json`, nhưng operator vẫn phải chạy tay một số bước copy rules/skills trong runbook ([`provisioning-baplatform.md`](../02.runtime/provisioning-baplatform.md)).
- **Công việc cần làm:**
  - [ ] **B.1.** Trong [`host-install.mjs`](../../packages/harness-foundation/src/host-install.mjs), tự động tạo `.agents/rules/core.law-gate.md` (bản Markdown thuần không chứa frontmatter `.mdc` riêng của Cursor, hoặc có frontmatter `trigger: always_on` chuẩn của Antigravity).
  - [ ] **B.2.** Tự động đồng bộ các skills cốt lõi của ESO (`eso-recon`, `eso-verify`) vào `.agents/skills/` nếu consumer chưa có.
  - [ ] **B.3.** Tự động thêm `.agents/session/` vào `.gitignore` của consumer khi provision.

### Phase C: Xử lý Concurrency cho `.agy-tool-cache.json` khi Gọi Parallel Tool Calls

- **Hiện trạng:** [`dispatcher.mjs`](../../packages/harness-host-generic/src/dispatcher.mjs) lưu một object đơn lẻ `{ tool_name, tool_input, ts }` vào `.agents/session/.agy-tool-cache.json` tại thời điểm `PreToolUse`.
- **Rủi ro:** Trong Antigravity, agent rất thường xuyên gọi **nhiều tool song song trong cùng 1 step** (ví dụ gọi 3 lệnh `view_file` cùng lúc). Nếu 3 `PreToolUse` chạy trước khi 3 `PostToolUse` chạy, file `.agy-tool-cache.json` chỉ giữ lại `tool_input` của lệnh thứ 3, làm 2 lệnh đầu mất đường dẫn hoặc đọc trùng đường dẫn.
- **Công việc cần làm:**
  - [ ] **C.1.** Chuyển `.agy-tool-cache.json` từ single-object sang hàng đợi ngắn (bounded FIFO queue / map theo `toolCallId` hoặc `{ tool_name, tool_input, ts }[]` tối đa 16 phần tử).
  - [ ] **C.2.** Khi `PostToolUse` (`gap-tracker`) chạy, khớp theo `toolCallId` (nếu có) hoặc `shift()` phần tử đầu tiên cùng `tool_name` trong cửa sổ 30 giây.
  - [ ] **C.3.** Viết unit test kiểm tra 3 lệnh `view_file` song song trên `--tree agents` trong [`qc/host-guards.test.mjs`](../../qc/host-guards.test.mjs).

### Phase D: Nâng cấp Attribution cho Antigravity Transcript trên Observe Server

- **Hiện trạng:**
  - Antigravity lưu transcript tại `~/.gemini/antigravity/brain/<conv-id>/.system_generated/logs/transcript.jsonl` (hoặc `~/.gemini/antigravity-ide/brain/...`).
  - Trong một số trường hợp khi user mở workspace ở thư mục con hoặc chưa mở file nào trong editor (`Active Document:` trống ở turn đầu), `resolveTranscriptOwnerInfo()` chưa tìm được owner ngay ở turn 1.
- **Công việc cần làm:**
  - [ ] **D.1.** Trong [`ingest-transcript.mjs`](../../packages/harness-observe-server/src/ingest-transcript.mjs), ngoài `Active Document:`, cho phép `resolveTranscriptOwnerInfo()` đọc thêm trường `Active Workspaces:` / `Command Working Directory:` hoặc `Cwd` trong `tool_calls` (`run_command`) và `AbsolutePath` trong `view_file` của 5 steps đầu tiên để xác định project owner chính xác 100% kể cả khi user không mở tab editor nào.
  - [ ] **D.2.** Liên kết `conversationId` trong `.agents/session/route-trace.jsonl` với `conversation_id` của transcript Antigravity để gắn đúng `rules` và `skills` đã kích hoạt cho từng turn trên Observatory.

### Phase E: Build Host Pack & E2E Verification trên Consumer (`x79` / `baplatform`)

- **Công việc cần làm:**
  - [ ] **E.1.** Chạy `bun run build:host-pack` và `bun run build:observatory` để cập nhật bundle mới nhất.
  - [ ] **E.2.** Chạy `./harness init profile ../x79 --id x79` (refresh host pack sang consumer).
  - [ ] **E.3.** Chạy full test suite (`bun test` + `bun run test:observatory`) đạt 100% pass.
  - [ ] **E.4.** Kiểm chứng E2E: Thực hiện 1 turn trên Antigravity ở consumer, kiểm tra `.agents/session/.eso-gaps.json` tự động đóng gap sau khi gọi `view_file` / `codegraph_explore`, và kiểm tra request xuất hiện trên Observatory với badge **`Antigravity`**.
