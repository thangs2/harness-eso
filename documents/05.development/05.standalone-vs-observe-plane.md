# Standalone vs observe plane

> Sau `init profile`, consumer **không** phụ thuộc repo harness-eso. Tài liệu này nói rõ cái gì chạy
> độc lập, cái gì cần observe plane, và **mất gì** khi observe plane tắt.

---

## 1. Hai mặt phẳng

| | **Host pack** — standalone | **Observe plane** — cần process |
|---|---|---|
| Ở đâu | `<consumer>/.harness/host-pack/` | máy chạy observatory (:8792) |
| Ai chạy | IDE gọi hook | operator (`./harness up`, hoặc `node …/server.mjs`) |
| Phụ thuộc | chỉ `node` + `python3` | SQLite, consumer mount, ingest worker |
| Vai trò | **quyết định** (guard, route, preflight, evidence) | **ghi & xem** (ingest → DB, Observatory UI) |

Câu chốt: **host pack quyết định, observe plane ghi lại và hiển thị.**

## 2. Hook nào ở mặt phẳng nào

| Hook | Event | Cần observe plane? |
|---|---|---|
| `guard-shell` | `beforeShellExecution` | **không** — static deny + `decide()` + policy |
| *(write gate)* | `preToolUse` | **không thuộc pack** — ESO write gate do `guard-write.py` của **consumer** giữ: nó đọc cùng `.eso-bundle-stamp.json` **và** scope theo `PROTECTED_PREFIXES` / `locked-paths.txt` / secret. Gate của pack không có path scope nên đã bị gỡ (F26) |
| `guard-brain` | `preToolUse` | **không** — đọc `.eso-preflight.json` local |
| `preflight` | `beforeSubmitPrompt` | **không** — COLLECT + GATE chạy in-process |
| `route` | nhiều event | **không** — spawn `route-hook.py` trong pack |
| `gap-tracker` | `postToolUse` | **không** — ghi file phiên |
| `post-tool-hint` | `postToolUse` | **không** — đọc file phiên |
| `pre-compact` | `preCompact` | **không** — ghi checkpoint local |

**Không hook nào cần observe plane đang chạy.** Đó là toàn bộ điểm của host pack.

`preflight` từng POST `/v1/preflight` trên sidecar; giờ nó gọi `orchestrateTurn` trực tiếp. Route HTTP
vẫn tồn tại cho client khác, và **cả hai đường dùng chung một builder projection** — có test parity
khoá điều đó (`qc/v1-preflight.test.mjs`).

## 3. Biên giới degrade khi observe plane tắt

| Mất | Không mất |
|---|---|
| Xem trên Observatory (`:8792`) — request, token, decision ledger, đồ thị | Guard shell / write / brain |
| ESO evidence gate **ghi ledger** để xem lại | Preflight COLLECT + GATE (vẫn đo, vẫn ghi `.eso-preflight.json`) |
| Gap history trên UI | Route trace (`.cursor/session/route-trace.jsonl`) |
| | Cost checkpoint (`preCompact`) |

Nói cách khác: tắt observe plane ⇒ **chưa xem được**, không phải **mất dữ liệu**. Mọi hook đều
`writeLedger: false`; dòng `decision_ledger` được **tái dựng** bởi facade backfill trong ingest từ
transcript JSONL. Chạy lại plane là ingest dựng lại đủ.

**Không có fallback nào được thêm vào hook.** Preflight chạy đầy đủ, không phải bản rút gọn: nó vốn
đã pure (policy của consumer + CLI docgraph/codegraph của consumer), nên "standalone" không phải một
mức chất lượng thấp hơn.

## 4. Consumer cần gì để guard chạy

| | |
|---|---|
| `.harness/host-pack/harness-hook.mjs` | dispatcher đã bundle, **0 import ngoài `node:*`** |
| `.harness/host-pack/route-hook.py` | Python stdlib |
| `.cursor/hooks.json` · `.agents/hooks.json` | đăng ký hook (trỏ vào pack) |
| `.harness/decision-policy.json` | policy của consumer — **nguồn duy nhất** cho thresholds |
| `node` · `python3` | trên PATH |

**Không cần:** `node_modules`, `@mu/*`, checkout harness-eso, Docker, observe plane.

Kiểm tra: `harness host-pack status <consumer>` — exit 1 nếu pack thiếu/hỏng/không wire.

## 5. Product state ở đâu

| | |
|---|---|
| `~/.harness/workspace.json` · `tenants.json` | registry của operator — một file, `projects[]` chứa document từng project |
| `~/.harness/observe/<projectId>/harness.db` | DB của observe plane |
| `<consumer>/.harness/` | cấu hình **của consumer** (policy, host pack, hook state) |

Không có gì của product nằm trong checkout, và không có gì của product nằm trong working tree consumer.
`HARNESS_PRODUCT_STATE_DIR` / `HARNESS_DATA_ROOT` để đổi chỗ khi cần; Docker dùng `/data/product-state`
và `/data/observe` (bind từ `~/.harness`).
