# Feature & classification map

**What this is.** The repo has prose (`01.overview/`, `02.runtime/`), diagrams (`06`, `07`) and a defect
registry (`09`). It had no **table of what the product can do** — so "what is a probe?", "which layer
decides this?", "what can I turn off?" were answered by reading code. This file is that table set.

**Two readers, one row.** Every feature row has an *operator* half (the lever: policy key, env var, CLI
command) and an *agent* half (the symbol that implements it, the test that pins it). If you need only one
half, read only its columns.

**This file is executable.** `qc/feature-map.test.mjs` fails when: a row cites a file that no longer
exists, a `register` id is not in `09.gate-defect-register.md`, a maturity tier is not in
`04.operations/08.consumer-maturity-checklist.md`, or a layer/plane name is not defined in §2. Add a
feature → add its row and its anchor, in one change. The drift this prevents is G-16: a document that
states behaviour the code does not have.

---

## 1. The seven classification axes

A "feature" is not one kind of thing. These are the axes this product is actually cut along; every row
in §3 is classified on all seven.

| Axis | Question it answers | Values |
|---|---|---|
| **Plane** (§2.1) | where does it run? | `control` · `observe` · `both` |
| **Layer** (§2.2) | which stage of a turn owns the decision? | `L0` · `L1` · `L2` · `L3` · `L4` · `L5` · `L_ingest` · `n/a` |
| **Enforcement** (§2.3) | what happens when it says no? | `deny` · `prompt-deny` · `report` · `none` |
| **Trigger** | when does it run? | `per-prompt` · `per-tool-call` · `per-turn` · `per-ingest` · `on-demand` |
| **Probe** (§4) | is there a way to interrogate it without a turn? | `P-xx` or `—` |
| **Lever** (§4.3) | how does an operator change its posture? | policy key · env var · CLI · Console route · `—` |
| **Maturity** | which tier of a consumer can exercise it? | `T0`…`T5` (`04.operations/08`) |

## 2. The axes in detail

### 2.1 Plane

| Plane | Owns | Runs | Trust posture |
|---|---|---|---|
| **Control** (`control`) | the decision about *this* turn: collect, score, gate, guard | inside the IDE, synchronously, before the tool call | **must decide alone** — it cannot wait for the observer |
| **Observe** (`observe`) | attribution and history: ingest, ledger, REST, Observatory | a separate process (`:8792`, `:8790` in container) | read-only w.r.t. the consumer's working tree |

The split exists because a gate that needs the observer would fail on every prompt where the observer is
down. Anything that must be true *at gate time* lives in Control; anything that answers "what happened"
lives in Observe. `documents/05.development/05.standalone-vs-observe-plane.md` lists what is lost when
Observe is off.

### 2.2 Layer — one turn, seven stages

| Layer | Stage | Module (anchor) | Decides |
|---|---|---|---|
| **L0** | route | `packages/harness-decision/src/l0-route.mjs` | which bucket (`root`, `sdlc`, `docs`, …) |
| **L1** | collect | `packages/harness-eso-core/src/collect.mjs` | what evidence exists (law / code / memory) and which gaps remain |
| **L2** | score | `packages/harness-eso-core/src/collect.mjs` (`scoreSufficiency`) | `level` + `score` from closed gaps |
| **L3** | gate | `packages/harness-eso-core/src/gate.mjs` | `allowProtectedWrite`, `allowPromptSubmit`, `enforceWritesSource` |
| **L4** | guard | `profiles/templates/hooks/guard-write.py`, `guard-shell.py` | allow / deny per tool call, from tier + attestation |
| **L5** | cognition | `packages/harness-host-generic/src/eso-gap-io.mjs` (`shouldBlockBrain`) + Brain attestation | whether a Brain-tier call is required first |
| **L_ingest** | attribution | `packages/harness-observe-server/src/ingest-transcript.mjs` | which request/generation an event belongs to |

`L0`–`L3` are engine (`@mu/harness-*`, testable without an IDE). `L4`/`L5` are **host pack** (Python,
runs from the consumer). That difference is why a fix can pass `bun test` and still not change what an
agent experiences — see `00.README.md` ground rule 4.

### 2.3 Enforcement strength

| Value | Means | Where |
|---|---|---|
| `deny` | the tool call is refused by the host hook | `profiles/templates/hooks/guard-write.py`, `profiles/templates/hooks/guard-shell.py` |
| `prompt-deny` | the turn never starts | preflight `beforeSubmitPrompt` |
| `report` | a verdict is written; nothing is stopped | `eso.mode: hint`, attestation-only paths |
| `none` | advisory text only (a hint in the reply) | `post-tool-hint`, Observatory |

## 4. Probes — how to interrogate the system without a turn

A **probe** answers one question by reading state, and is the only sanctioned way to ask. A probe never
changes a verdict; it explains one. Three kinds:

### 4.1 Index probes (a script entry point)

| ID | Probe | Answers | Where |
|---|---|---|---|
| **P-01** | `capability-probe` | which adapters can this host actually reach (docgraph/codegraph/memory/brain)? | `packages/harness-eso-core/src/capability-probe.mjs`, `packages/harness-cli/src/capability-probe-cmd.mjs` |
| **P-02** | `conformance` | does the installed pack match the published contract? | `packages/harness-eso-core/src/conformance.mjs` |
| **P-03** | `contract-diff` | what changed between pack versions? | `packages/harness-eso-core/src/contract-diff.mjs` |
| **P-04** | `isolation-check` | can a consumer see another consumer's state? | `packages/harness-eso-core/src/isolation-check.mjs` |
| **P-05** | `surface-check` | is every advertised hook actually installed? | `packages/harness-eso-core/src/surface-check.mjs` |
| **P-06** | `migration-check` | is a consumer's state migratable to this version? | `packages/harness-eso-core/src/migration-check.mjs` |

### 4.2 State probes (the operator runbook, `09` §4)

| ID | Probe | Reads | Answers |
|---|---|---|---|
| **P-07** | tier probe | `.harness/decision-policy.json` → `paths` | which tier does the target have? (C-a) |
| **P-08** | verdict probe | `~/.harness/attest/<projectId>.json` | what did the gate believe, and is the receipt valid? (C-c) |
| **P-09** | gap probe | `.cursor/session/.eso-preflight.json` → `.gaps`, `.unanswerableGaps` | which gaps remain, and can any close? |
| **P-10** | posture probe | `eso.enforceWrites` + `enforceWritesSource` | did the operator declare the posture, or did the default supply it? (G-08) |
| **P-11** | memory probe | `.harness/law-misses.json` | has this repo already failed to answer a term? (G-13) |
| **P-12** | brain probe | `.cursor/session/.pipeline-brain-stamp.json` | is a Brain call what is missing? (C-d) |

### 4.3 Lever table — the levers a probe names

A probe is only useful if it names a lever that exists. These are the real ones:

| Lever | Written by | Changes | **Does not change** |
|---|---|---|---|
| `eso.enforceWrites` | operator, policy | evidence posture `fail_closed` \| `off` | `eso.mode` (different axis) |
| `eso.mode` | operator, policy | `observe` \| `hint` \| `fail_closed` for **cognition** behaviour | the evidence gate (that reads `enforceWrites`) — G-08/G-12 |
| `eso.sources.<kind>.enabled` | operator, policy | which providers are asked | the default (off unless written) — G-01b |
| `paths.{locked,ask,gated}` | operator, policy | the path tier | evidence level |
| `eso.cognition.enforceBrain` | operator, policy | whether a Brain call is required | evidence |
| `POST /api/projects/<id>/consent` | **Console only** | opens an `ask` path for a TTL | evidence, `locked` |
| `HARNESS_ESO=0` | env | skips the engine | the guards (they read product state) |
