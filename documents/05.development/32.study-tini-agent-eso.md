## 1. What it is

A **local-first personal assistant** for one human on one laptop, published as a teaching artifact:
every architecture box maps to one readable file. Python, ~26k LOC, 164 files, MIT.

The thesis is *legibility over abstraction*: the agent loop is 118 lines with no framework, and
`tini/app.py` (183 lines) is the whole composition root —
`Settings → SQLite → Memory → ToolRegistry → Session → Tracer`.

Six pillars named on its whiteboard: **Harness · Context · Tools · Loop · Memory · Eval/LLM-Ops**.

## 3. The mechanisms worth remembering

### 3.1 The loop — and why its shape matters

```text
while iteration <= max_iterations:
    response = llm(messages, tools)      # reason
    messages += assistant content
    if no tool_use:        return reply   # guardrail 1: natural end
    for call in tool_use:  messages += tool_result   # act + observe
# guardrail 2: max_iterations (10) → honest "I hit my iteration limit"
```

`messages` is **mutated in place** and is the full working memory of the turn — which is exactly what
gets traced. Observers (`notify(kind, event)`) are the only side-channel; the loop never knows the
UI or the tracer exist. `stream=True` emits `text` deltas, and **any streaming hiccup falls back to
one non-streaming call** (so streaming can never cost a reply).

### 3.2 Fail-open, applied consistently

Two independent agents gate work with a small model, and **both default to the expensive/correct
answer when anything goes wrong**:

- `should_retrieve()` → on error returns `(True, message, "gate failed open")`. A stale memory beats
  a lost one.
- `classify_message()` (triage) → on error returns `"full"`. A broken classifier must cost latency,
  never capability.

The same rule appears a third time at the graph boundary: `Tini.respond()` wraps the whole graph run
in `try/except` and falls open to the plain loop, and again inside `gather` via `_safe()` per branch.

### 3.3 Graph ≠ swarm

`engine.py` is a **blackboard + waves**, not a message-passing agent swarm:

- One plain `dict` state. Nodes read a snapshot, return keys to merge.
- **Parallel nodes writing the same key raise `GraphStateCollision`** — a silent lost write is
  treated as a bug, not a race to tolerate.
- **Routers are code, never models.** The model writes state; code reads it and picks the edge. This
  is what makes control flow traceable and testable.
- Guards generalize the loop's two exit conditions: per-node `max_visits`, global `max_steps=25`.
- A 1-node wave runs on the calling thread so trace order stays exact; ≥2 nodes go to a
  `ThreadPoolExecutor`. All `notify` is mutex-guarded so JSONL lines stay whole.
- `describe()` returns the topology as data, and **the dashboard draws from `describe()`**, so the
  picture cannot drift from the code.

`agent_node(name, out_key, tools=…)` wraps a whole `run_loop` as one node — the only sanctioned way
to nest an agent inside a workflow. `gather` deliberately does **not** use it: it holds the "it
proposes, it never acts" rule and backs it with a test that reads the file's own source to assert no
`run_loop`/`ToolRegistry` appears in it.

### 3.4 Loop vs graph — the decision rule they actually state

- **Loop** when the shape cannot be drawn in advance ("work this PR": read diff → test → discover
  rebase → decide). Any shape you commit to is wrong by step three.
- **Graph** when the shape is known at design time and has genuinely independent parts (morning
  gather: 4 scans, no dependencies → one wave; triage: classify ∥ load calendar → route).

### 3.5 Memory: three pillars + two managing agents

- **Semantic** `facts` (subject, content, source ∈ {user, consolidation}) — FTS5 + BM25, **no
  embeddings**. `_fts_query()` neutralizes punctuation, avoids `car`→`carpet`, prefix-searches CJK.
- **Episodic** `episodes` (happened_at, summary) — FTS5, relevant-then-recent ranking.
- **Procedural** `SKILL.md` files on disk, with progressive disclosure: always scan frontmatter, load
  body only on keyword overlap, max 2 per turn.
- Behind `FactStore` protocol: SQLite / Supabase / Mem0 / Zep / LangMem — a conformance suite holds
  every backend to the same contract, so upstream never learns which is live.

**Consolidation invariant (the good one):** read unconsolidated rows → distill → `UPDATE ... WHERE id
IN (the exact ids read)`. So summarizer failure ≠ lost conversation, and rows arriving *during* the
summarize are not marked done. Returns 0 on any error and leaves the log intact.

### 3.6 One message contract, many providers

The loop speaks Anthropic's Messages shape. `models.py` maps 11 providers onto two wires; the
OpenAI-compatible shim is ~60 lines that carry over assistant `tool_calls`, `tool` results, and
Gemini's `extra_content`/`thought_signature` (required for the next tool turn to be valid).

The subtle, worth-stealing part: **a model id inherited from the env for a *different* provider is
dropped** rather than carried across. Without it, the arena switched main model to xAI while
`TINI_SMALL_MODEL` still pointed at `claude-haiku`, every gate call 400'd, and the gate **failed
open forever** — a permanent failure wearing the costume of a healthy "retrieve" decision.

### 3.7 Observability: one observer protocol, three sinks

`compose(observer, tracer.event, _capture)` fans one event stream out to the gateway UI, the JSONL
trace, and a per-turn metadata capture. Two distinct ledgers:

- `traces/<date>.jsonl` — resettable for demos.
- `usage.jsonl` — **append-only, never wiped**; dollar cost is derived from tokens, which are ground
  truth.

Per-turn metadata rides on the assistant row of `chat_log`, so reopening a thread shows the gate
decision, route, iterations, usage, latency, tool statuses and model — not just the prose.

### 3.8 Eval discipline

- `evals/deterministic/` — pytest, 0/1, no model judges. "Did the right tool fire?"
- `evals/judge/` — DeepEval, scored %, needs a key. "Was the reply good?"
- `make gate` runs deterministic first; **a non-zero exit blocks before judge even runs**. Missing key
  records judge as `skipped` but deterministic must still pass — a gate cannot turn a logic failure
  into a pass just because the judge was unavailable.

That separation is the single cleanest idea in the repo: conflating "did it do the thing" with "was
it any good" is the classic eval mistake.

### 3.9 Bounded context

`history_turns=12` → only the last 24 messages enter the prompt, regardless of conversation length.
Older turns survive in `chat_log`, get distilled into facts, and return via the gate when relevant.
Their own docs name the gap: **the window bounds message count, not tokens** — memory, skill bodies
and tool output are unbounded.

## 4. Defects found at this commit (verified, not inferred)

I created a throwaway venv, installed the runtime deps (`anthropic`, `python-dotenv`, `openai`,
`rich`), pointed `TINI_HOME` at a writable dir, and ran `evals/deterministic`:
**621 passed, 4 failed, 60 skipped.**

**Critical — `tini/app.py:181` raises `NameError: name 'captured' is not defined`.**
Introduced in commit `451daa7 feature: run_command`, which added a `_capture` usage accumulator
*inside* `respond()` while referencing it from `_respond_via_graph()`, a different scope.

Reproduced: with `TINI_GRAPH_WORKFLOWS=1`, **every quick route throws**, `respond()` catches it, and
the turn falls open to the full loop. The cost-saving path the graph exists for is the one that never
runs — and because fail-open is a *feature*, the failure is invisible. This ships alongside:

- `evals/deterministic/test_triage_workflow.py::test_quick_turn_answers_on_the_small_model_and_skips_the_gate`
  **fails on the repo as committed** — the guard was in the tree and red.
- `test_delegate_env.py::test_every_delegate_spawn_passes_delegate_env` — "8 of 7 delegate spawn
  points pass `env=delegate_env()`": `run_command` added a `subprocess.run` the env-guard doesn't
  know about, so subprocesses there may not get the sanitized environment.
- Two `test_static_assets.py` failures from the same commit: `youtube.svg` lacks `<title>`; a
  `"Analytics & Publishing"` registry group has no display name.

**Two lessons, and they are about process, not code:**

1. **`make gate` was not run before the "feature:" commits.** A one-line `NameError` shipped, and the
   test that would have caught it was committed red in the same tree. Every guarantee in §3.8 is
   worth exactly as much as the habit of running it.
2. **Fail-open hides breakage.** The same property that makes the gate safe in §3.2 makes §4
   undiagnosable from the outside: a broken quick path and a healthy "decided to go full" are
   indistinguishable in the trace. A fail-open needs a loud, counted signal (a counter, a trace field)
   or it becomes a silent permanent failure — the *exact* shape of the xAI/`TINI_SMALL_MODEL` bug in
   §3.6, which they diagnosed and then re-created.

Also: commit hygiene is poor. `2225918 feature: run_command` contains only the removal of a leftover
merge-conflict marker from `README.md`.

## 5. Where this actually touches `harness-eso`

Not architectural kin — the two products solve different problems (`harness-eso` gates an *IDE coding
agent's* evidence; `tini` *is* the agent). The overlap is in **transferable discipline**:

| Tini idea | Where it is already native here | What is arguably better here |
|---|---|---|
| Fail-open gates (§3.2) | consumer-maturity T0–T5 + gate defect register | ours *records* the verdict; tini's fail-open is unrecorded |
| Deterministic vs judge eval, 0/1 first (§3.8) | `qc/` `node:test` + probe/lever tables | — |
| Topology rendered from `describe()`, never hand-drawn (§3.3) | `documents/06.diagrams` + feature/classification map "linted against the code" | same idea, ours is linted |
| Append-only usage ledger separate from resettable trace (§3.7) | observe-server ingest + transcripts | ours dedupes by `(path, size, mtimeMs)` (see commit `6284507`) |
| Bounded working window (§3.9) | prompt lifecycle / guards | tini's is count-bounded; token budget is the open gap |

**The one thing genuinely worth importing:** when we add a fail-open path here, log the *fact that it
failed open* as a first-class verdict field, counted and visible — not just the fallback outcome.

## 6. If we ever need to run it

No venv is provisioned in that checkout. `uv` is **not installed** on this machine; `python3` is
3.14 and lacks the deps. Working recipe used for the audit above:

```bash
python3 -m venv /tmp/tini_probe
/tmp/tini_probe/bin/pip install anthropic python-dotenv pytest openai rich
cd ../tini-agent-eso
TINI_HOME=/tmp/tini_home_probe /tmp/tini_probe/bin/python -m pytest evals/deterministic -q -p no:cacheprovider
```

`TINI_HOME` must be writable — several tests fall back to `./.tini`, which fails under a read-only
workspace sandbox (`PermissionError: [Errno 1] Operation not permitted: '.tini'`).
