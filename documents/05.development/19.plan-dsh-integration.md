## 1. Bối cảnh: DSH khác 3 host cũ ở đâu

3 host cũ đều là **hook host**: IDE gọi command, command trả JSON qua stdout. DSH **không** có
cơ chế đó. Nó là một **Cordis app** — mọi thứ là plugin `@deepseek-ai/dsh-*` nạp từ profile.

| Đặc điểm | Cursor / Antigravity / Claude Code | DSH |
|---|---|---|
| Cách host gọi hook | `hooks.json` / `settings.json` → spawn command | **không có**; chỉ có plugin in-process |
| Cấu hình | file JSON trong repo consumer | `cordis.patch.yml` trong **profile** (`~/.dsh/profiles/<name>/`) |
| Đơn vị mở rộng | hook entry | **bundle** (`package.json` khai `dsh.bundle.patch`) |
| Cài đặt | `harness init profile` ghi file | `plugin_manager install_bundle` (npm / git / path / tarball) |
| Session data | transcript JSONL do IDE ghi | `~/.dsh/sessions/--<cwd-slug>--/session-<uuid>/session.v4.jsonl.zstd` |
| Tool vocabulary | `Bash`, `Edit`, `Write`, `Read` | `bash`, `edit`, `write`, `read`, `read_image`, `subagent`, `workflow`, … |
| Guard | hook `PreToolUse` | `ctx.tools.guard()` (monotonic) + `tools/pre-execute` waterfall |

**Kết luận khả thi:** có 2 đường — (a) tái dùng **bridge Claude Code hooks** mà DSH ship sẵn,
(b) viết **Cordis plugin native**. Cả hai đều là seam chính thức của DSH, không phải hack.

## 2. Bốn approach (xếp theo chi phí)

| # | Approach | Chạm harness-eso | Được | Mất | Ước lượng |
|---|---|---|---|---|---|
| **A** | Skill/instruction pack | `profiles/templates/` → consumer | law gate, skills, workflow | không có runtime guard/telemetry | 0.5–1 ngày |
| **B** | Bridge `dsh-hooks-claude-code` | không sửa package; thêm profile/settings variant | 5/8 hook chạy nguyên | `PreCompact`, `SessionStart/End`, transcript, tool name | 1–2 ngày |
| **C** | Host tree `dsh` trong harness-eso | foundation + host-generic + ingest + CLI | product thống nhất, 8/8 hook | vẫn spawn subprocess, không thấy session event | 5–8 ngày |
| **D** | Cordis plugin `@mu/harness-dsh` | extract `runHook()` + plugin mới | in-process, guard monotonic, event-sourced, UI slot | rewrite guard, bám version rc | 10–15 ngày |

Khuyến nghị: **A → B (POC) → D**, bỏ qua C nếu làm D; giữ C chỉ khi cần hỗ trợ host không cài được plugin.

## 3. Approach B — bridge Claude Code hooks (POC)

### 3.1 Cấu hình

DSH ship sẵn `@deepseek-ai/dsh-hooks-claude-code`: *"run a Claude Code hooks.json / settings hook
config on the DeepSeek Harness interception seams"*.

```yaml
# thêm vào ~/.dsh/profiles/desktop/cordis.patch.yml, hoặc đóng gói thành bundle
- id: harness-eso-hooks
  name: '@deepseek-ai/dsh-hooks-claude-code'
  config:
    configPath: ./.claude/settings.json   # đúng file harness-eso đã provision
    projectDir: .
    defaultTimeoutMs: 120000
```

| Field | Default | Ghi chú cho harness-eso |
|---|---|---|
| `configPath` | required | trỏ `.claude/settings.json` (harness-eso ghi) hoặc file variant `dsh` |
| `projectDir` | session workspace | thay `${CLAUDE_PROJECT_DIR}`; nên set `.` để hook `cd` đúng |
| `pluginRoot` | — | thay `${CLAUDE_PLUGIN_ROOT}`; không dùng |
| `defaultTimeoutMs` | 600000 | preflight maxMs 8000 nên set thấp hơn để fail sớm |
| `stderrSummaryMaxChars` | 500 | giữ default |

### 3.2 Vì sao envelope khớp (verified 2 phía)

harness-eso emit ([`hook-io.mjs`](../../packages/harness-host-generic/src/hook-io.mjs#L60-L137)):

| harness-eso | Output |
|---|---|
| `UserPromptSubmit` + deny | `{"decision":"block","reason":…}` |
| `UserPromptSubmit` + context | `{"hookSpecificOutput":{"hookEventName":"UserPromptSubmit","additionalContext":…}}` |
| `PreToolUse` + deny | `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":…}}` |
| `PreToolUse` + allow | `…"permissionDecision":"allow"` |
| `PostToolUse` + context | `…"additionalContext"` |

DSH parse (`dsh-hook-protocol` — `HookOutput`): `hookSpecificOutput.hookEventName`,
`permissionDecision` (`allow|deny|ask`), `permissionDecisionReason`, `additionalContext`,
`systemMessage`, legacy top-level `decision` (`approve|block`). **Khớp từng field.**

Payload DSH gửi hook (bridge `lib/index.js`): `session_id`, `cwd`, `hook_event_name`,
`prompt`, `tool_name`, `tool_input`, `tool_response`; `transcript_path` **luôn `''`**.

### 3.3 Mapping hook → seam

| harness-eso | CC event | DSH seam | Trạng thái |
|---|---|---|---|
| `preflight` | `UserPromptSubmit` | `agent/pre-step` | ✅ context |
| `route` (prompt) | `UserPromptSubmit` | `agent/pre-step` | ✅ (ghi trace riêng) |
| `route` (tool) | `PreToolUse` / `PostToolUse` | `tools/*` | ✅ |
| `guard-shell` | `PreToolUse` | `tools/pre-execute` | ⚠️ matcher phải là `bash` |
| `guard-write` | `PreToolUse` | `tools/pre-execute` | ⚠️ matcher `edit\|write` |
| `guard-brain` | `PreToolUse` | `tools/pre-execute` | ⚠️ tool name khác |
| `gap-tracker` | `PostToolUse` | `tools/post-execute` | ✅ |
| `post-tool-hint` | `PostToolUse` | `tools/post-execute` | ✅ |
| `pre-compact` | **`PreCompact`** | — | ❌ bridge không hỗ trợ |
| — | `SessionStart` / `SessionEnd` | — | ❌ |

### 3.4 Bốn việc bắt buộc sửa

1. **Tool matcher phải đổi theo vocabulary DSH** (`bash`, `edit`, `write`, `read`). Profile
   `claude-superset.json` hiện match `Bash`, `Edit|Write|MultiEdit|NotebookEdit` → **không khớp gì**.
   Cần `profiles/host/dsh-superset.json`.
2. **`HARNESS_TREE=dsh`** và session dir `.dsh/session/` (hoặc dùng `.claude/session/` để tái dùng
   route-hook). `hook-io.mjs` hiện chỉ nhận `cursor|agents|claude` → phải thêm `dsh`.
3. **`pre-compact` mất** → cost checkpoint trước compaction không chạy. Chấp nhận ở POC; thay bằng
   session event `compaction/start` khi làm D.
4. **`transcript_path=''`** → ingest không có transcript. Chấp nhận ở POC (Observatory sẽ trống);
   xử lý ở §5.

### 3.5 Điều bridge **không** làm được (đừng thiết kế dựa vào)

- Chỉ command handler: `http`, `mcp_tool`, `prompt`, `agent` handler bị bỏ.
- `PreToolUse.allow` **không** pre-approve; `updatedInput` bị bỏ qua (chỉ warn).
- `Stop` blocking = **force another step** (không phải veto); `stop_hook_active` luôn `false`.
- Một `configPath` cho cả process, đọc 1 lần lúc boot, **không reload**.
- Hook chạy **tuần tự**, không song song.

## 4. Approach D — Cordis plugin native (đích)

### 4.1 Mapping

| harness-eso | DSH API | Ghi chú |
|---|---|---|
| `guard-shell` | `ctx.tools.guard()` | monotonic; không listener nào đảo được |
| `guard-shell` (ask) | `tools/pre-execute` → `{kind:'ask'}` | DSH có approval thật, hơn Cursor |
| `guard-brain` | `ctx.tools.restrict()` + guard | restrict ẩn schema → tiết kiệm token |
| `preflight` | `agent/pre-step` + `additionalContexts` | chạy mỗi step, không chỉ mỗi prompt |
| `gap-tracker` | `tools/result` + `sessionProjections` | bỏ `.eso-gap-closure.json` |
| `post-tool-hint` | `tools/post-execute` → `additionalContexts` | |
| `pre-compact` | `session/event` trên `compaction/start` | tốt hơn hook CC |
| `route` trace | `sessionProjections` + `ctx.sessionTelemetry` | event-sourced, replay được |
| `decision-policy.json` | plugin `Config` (Schemastery) | hoặc đọc file để giữ parity |
| Observatory | client slot React | hoặc giữ `:8792` |

### 4.2 Kiến trúc khuyến nghị: extract `runHook()`

Hiện `dispatcher.mjs` là CLI đọc stdin → gọi hook. Tách:

```js
// packages/harness-host-generic/src/run-hook.mjs
export async function runHook({ hook, tree, payload, root }) -> { permission, additional_context, trace }
```

- `harness-hook.mjs` = wrapper mỏng (giữ nguyên hành vi 3 host cũ).
- Cordis plugin import **cùng bundle** và gọi `runHook()` **in-process**.
- Lợi: không spawn (~46ms/lần), không drift logic, test cũ dùng lại, bundle vẫn "no non-`node:*` imports".

### 4.3 Ràng buộc khi viết plugin

- `apply(ctx, config)` + `inject = ['tools','sessions','systemPrompt']`; mọi đăng ký trong `ctx.effect`/`ctx.on`.
- **Không** để exception thoát ra: "plugin failure ends the turn" — khác posture telemetry-allow của harness-eso.
- Chỉ dùng session event đã có; **không** append event type mới (reader sẽ từ chối reopen).
- Config schema để operator chỉnh trong `cordis.patch.yml` (sống qua upgrade).
- Publish dưới `@mu/harness-dsh`, peer deps **exact** theo DSH version; khai `engines.dsh`.

## 5. Observe plane — phần đau nhất

| Nguồn hiện tại | DSH tương đương | Cách ingest |
|---|---|---|
| Cursor/Claude transcript JSONL | `session.v4.jsonl.zstd` (zstd frames + JSONL) | adapter mới, phải theo `format_version` (v0→v4) |
| hook trace file (`route-hook.py`) | `hook/invoked` + `hook/result` **trong session log** | map 2 event này → có evidence hook miễn phí |
| (không có) | `ctx.sessionTelemetry` backend | plugin đẩy ledger record sang observe-server |

Khuyến nghị thứ tự:

1. **Telemetry backend** (`emit/flush/shutdown`) → POST sang `:8792`. Event-exact, có `seq` để dedupe,
   không polling, không zstd. Mapping: `turn/start`≈request, `assistant/message`≈llm_call,
   `tool/call`+`tool/result`≈tool rows, `request/header`≈model/route, `compaction/*`≈cost checkpoint.
2. **Ingest session log** khi cần backfill lịch sử.
3. OTel (`dsh-session-telemetry-otel`) nếu đã có collector.

Ràng buộc identity: `(host, workspace/worktree, agent, session, turn)` — xem
[`18.rfc-capability-fabric.md`](./18.rfc-capability-fabric.md) §5.1. DSH 1 process = 1 profile =
nhiều session; đừng gộp theo `projectId` như hiện tại.

## 6. Lộ trình

| Phase | Việc | Exit criteria |
|---|---|---|
| **D0** | Skill pack `.agents/skills` + `AGENTS.md` cho DSH consumer | agent gọi đúng `eso-recon`/`eso-verify`; không cần runtime |
| **D1** | `dsh-superset.json` + settings variant (matcher `bash`/`edit`/`write`) + bridge row | `preflight` inject context; `guard-shell` **chặn thật** 1 lệnh `rm -rf`; thấy `hook/result` trong session log |
| **D2** | Bundle `@mu/harness-dsh` (patch insert bridge + MCP docgraph/codegraph) | `plugin_manager install_bundle` 1 phát; sống sau restart |
| **D3** | Extract `runHook()`; plugin gọi in-process thay bridge | guard không spawn; test cũ vẫn pass |
| **D4** | Telemetry backend → Observatory hiển thị session DSH | 1 turn DSH hiện đủ request/llm_call/tool trong `:8792` |
| **D5** | Native guards + compaction checkpoint + UI slot | H3–H4 theo conformance của RFC §3.6 |

Phụ thuộc: **D1 cần** RFC P1 (manifest + resolver) nếu muốn chọn provider native/external ngay;
nếu chưa có, hardcode recipe `dsh-native`.
