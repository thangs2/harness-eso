## 1. Executive Summary & Root Cause Analysis

### 1.1 Hiện Trạng & Vấn Đề Cốt Lõi
Hệ thống **Harness-ESO** hiện đóng vai trò là chốt chặn đảm bảo bằng chứng (*Evidence Sufficiency*) cho các dự án consumer (như `baplatform`). Quy trình thực thi chuẩn dựa trên **Reconnaissance Trinity**:
$$\text{AgentMemory} \longrightarrow \text{Docgraph} \longrightarrow \text{Codegraph} \longrightarrow \text{ESO Preflight} \longrightarrow \text{Brain Gate}$$

Tuy nhiên, trong các dự án SaaS Enterprise lớn, hệ thống đang gặp phải hiện tượng **Context Window Bloat & Token Burnout**:
1. **ESO Preflight nhồi dữ liệu thô (Raw Payload Ingestion):** ESO Preflight kiểm tra tính đủ bằng chứng bằng cách đọc trực tiếp nội dung các file, log và lịch sử hội thoại. Khi tạo `[EVIDENCE CONTEXT]`, ESO dump hàng ngàn dòng raw text vào ngữ cảnh của Brain (LLM).
2. **Codegraph thiếu cơ chế Projection (Full-file Leakage):** Khi tra cứu quan hệ phụ thuộc, Agent buộc phải load toàn bộ file code (chứa hàng trăm dòng boilerplate, EF Core configurations, private implementations) chỉ để lấy định nghĩa 1 method hoặc 1 DTO.
3. **Docgraph thiếu bộ lọc Spec/Invariant:** Docgraph tìm kiếm theo chunk văn bản thông thường. Khi trích xuất, toàn bộ background, mô tả dài dòng (prose) đều bị nhồi vào context thay vì chỉ trích xuất các ràng buộc (Invariants).
4. **AgentMemory thiếu Domain Scoping:** AgentMemory trả về các mẩu ký ức vụn vặt, không lọc theo Domain Bounded Context hiện tại, gây nhiễu loạn và tiêu tốn token vô ích.

## 2. Giải Pháp Chi Tiết Tại Nguồn (`harness-eso` Platform)

### 2.1 Trụ Cột 1: Cải Tiến Harness-ESO Core — "Evidence Digest Preflight"

#### A. Cơ chế Evidence Digest
Thay vì truyền raw text vào `[EVIDENCE CONTEXT]`, nâng cấp `eso-preflight.mjs` để sinh ra **Evidence Manifest (Digest)**:
- **Tự động trích xuất mã Invariant:** Nhận diện và xác thực các ID ràng buộc (ví dụ: `INV-AUTH-01`, `INV-PROJECT-ISOLATION`).
- **Tạo Symbol Checksum Table:** Chỉ ghi nhận bảng băm và chữ ký (Signature Hash) của các file/class đã được kiểm chứng.
- **Evidence Sufficiency Proof:** Sinh ra một token chữ ký số nội bộ (Cryptographic / State Proof) xác nhận phiên làm việc đã đạt `LEVEL_STRONG` hoặc `LEVEL_SUFFICIENT`.

#### B. Cấu trúc Payload mới của `[EVIDENCE CONTEXT]`
```json
{
  "esoDigest": {
    "version": "2.0-digest",
    "sufficiencyLevel": "sufficient",
    "score": 0.88,
    "proofHash": "sha256-e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
    "verifiedInvariants": [
      {"id": "INV-PROJECT-01", "rule": "Must isolate queries via CurrentProject.Id"},
      {"id": "INV-PERM-03", "rule": "Require Authorize(BAPlatformPermissions.Bookings.Create)"}
    ],
    "targetSymbols": [
      "BAPlatform.Application.Bookings.ServiceBookingAppService",
      "BAPlatform.Application.Contracts.Bookings.CreateBookingDto"
    ]
  }
}
```
* **Hiệu quả:** Cắt giảm từ **15.000 tokens raw context** xuống còn **dưới 500 tokens structured context**. Cổng `guard-write.py` vẫn fail-closed an toàn tuyệt đối.

### 2.2 Trụ Cột 2: Tối Ưu Codegraph — "AST Skeleton / Stub Projection"

#### A. Vấn đề giải quyết
Hiện tại, khi Agent cần hiểu một class phụ thuộc (Dependency), Agent phải đọc toàn bộ code thực thi của class đó.

#### B. Giải pháp kỹ thuật: AST Skeletonizer
Bổ sung chế độ chiếu hình ảnh (Projection Mode) cho `codegraph`:
- **Tham số mới:** `codegraph_explore(target, viewMode="skeleton")`
- **Cơ chế bóc tách AST:** Sử dụng Tree-sitter / Roslyn AST Engine để lọc bỏ toàn bộ thân hàm (function body):
  ```csharp
  // Input: 850 lines of ServiceBookingAppService.cs
  // Output Skeleton: 40 lines
  namespace BAPlatform.Application.Bookings;

  [Authorize(BAPlatformPermissions.Bookings.Default)]
  public class ServiceBookingAppService : ApplicationService, IServiceBookingAppService
  {
      [Authorize(BAPlatformPermissions.Bookings.Create)]
      public virtual Task<BookingDto> CreateAsync(CreateBookingDto input);

      [Authorize(BAPlatformPermissions.Bookings.Cancel)]
      public virtual Task<BookingDto> CancelAsync(Guid id, CancelBookingDto input);
  }
  ```
* **Hiệu quả:** Giảm **85% - 90%** dung lượng đọc code phụ thuộc, ngăn chặn hoàn toàn việc nhồi code thừa vào Brain.

---

### 2.3 Trụ Cột 3: Tối Ưu Docgraph — "Invariant & Spec Extraction"

#### A. Vấn đề giải quyết
Docgraph hiện tại trả về cả đoạn văn xuôi dài dòng, giải thích bối cảnh lịch sử mà AI không cần trong lúc viết code.

#### B. Giải pháp kỹ thuật: Spec Parser
- Nâng cấp parser của Docgraph nhận diện cấu trúc tài liệu dạng chuẩn:
  - Header Frontmatter (`invariants`, `rules`, `apis`).
  - Section `## Invariants` và `## Acceptance Criteria`.
- **Query Mode Mặc Định:** Khi Docgraph thực hiện tra cứu cho ESO, mặc định chỉ xuất ra **Spec View** (danh sách bullet point luật bất biến), loại bỏ các đoạn văn mô tả (Prose).
* **Hiệu quả:** Giảm **60%** lượng token tài liệu SDLC mà AI phải tiêu thụ.

---

### 2.4 Trụ Cột 4: Tối Ưu AgentMemory — "Domain Bounded Scoping & Consolidation"

#### A. Domain Scoping Filter
- Bổ sung trường `domain_slug` vào metadata lưu trữ của `agentmemory`.
- Khi Agent chạy trong một WBS slice (ví dụ `01.customer`), preflight hook chỉ query các memory có gắn thẻ domain tương ứng, triệt tiêu việc inject ký ức của các module không liên quan (như `billing`, `inventory`).

#### B. Automated Memory Consolidator
- Định kỳ kích hoạt job chạy ngầm (`memory_consolidate`) gộp các bài học vụn vặt qua nhiều session thành **Single Source Rule**:
  - *Thay vì 15 bản ghi về bug null project:* Nén thành 1 rule chuẩn: *"Mọi AggregateRoot phải kế thừa FullAuditedAggregateRootWithUser<Guid, AppUser> và gán CallerId trong constructor."*
