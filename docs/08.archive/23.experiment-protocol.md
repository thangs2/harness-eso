# 23 — Experiment protocol: ESO trên host có/không có harness native

> **Trạng thái:** protocol, chưa chạy. Nối tiếp [`22.quality-audit.md`](./22.quality-audit.md)
> (không có defect nào thoát, check hiện tại toàn false positive) và
> [`21.session-whatif-batch.md`](./21.session-whatif-batch.md) (token không phải claim).
>
> Mục tiêu: trả lời **"ESO có nâng host không có harness native lên ngang host có harness native
> không?"** bằng dữ liệu, không bằng cảm nhận. Naming/positioning hoãn tới sau khi có kết quả.

---

## 1. Câu hỏi và giả thuyết (chốt trước khi chạy)

| ID | Giả thuyết | Bác bỏ khi |
|---|---|---|
| **H1** | Trên Cursor, thêm ESO giảm defect escape và rework so với native-only | giảm < 25% defect escape **và** rework không giảm |
| **H2** | `Cursor+ESO` đạt mức `DSH native` (parity) | `Cursor+ESO` kém `DSH native` ở ≥ 2/3 task |
| **H3** | ESO thêm giá trị trên host đã có harness native (`DSH+ESO` > `DSH native`) | không có khác biệt — ESO dư trên host mạnh |

H3 chỉ chạy nếu có shim DSH ([`19.plan-dsh-integration.md`](../05.development/19.plan-dsh-integration.md)); không
có thì ghi rõ là "not tested", **không** suy ra từ H1/H2.

---

## 2. Thiết kế: 3 arm, không phải 2

| Arm | Mô tả | Trả lời |
|---|---|---|
| **A** | Cursor, native-only (rules/index/hooks sẵn có, không cài ESO) | baseline |
| **B** | Cursor + ESO (preflight, guard, observe, checks) | H1: A→B |
| **C** | DSH native (skills/instructions/session query/guards) | H2: B vs C |
| **D** *(optional)* | DSH + ESO | H3 |

Bỏ Antigravity khỏi vòng 1: nó thêm biến **model** (Gemini), không tách được khỏi biến host. Vòng 2
replicate trên Antigravity chỉ để kiểm tra hướng, không dùng để kết luận.

**Cùng một task phải chạy đủ 3 arm.** Chạy task 1 trên A, task 2 trên B là vô nghĩa.

---

## 3. Chọn task: replay ticket đã ship

- 3 ticket đã merge, cùng shape BAP-38 (feature FE + i18n + test), có PR test.
- Với mỗi ticket: snapshot repo tại **commit cha của PR**, không có remote refs, không có commit
  tương lai.
- Agent chạy 1 turn với prompt y hệt ticket (title + acceptance criteria, không thêm hint).
- Chấm bằng **test của chính PR** + test suite hiện có.

**Chống rò rỉ đáp án** (bắt buộc, nếu không cả experiment vô giá trị):

| Rò rỉ | Cách chặn |
|---|---|
| `git log` thấy commit fix | clone `--depth 1` tại parent, xoá remote, `git reflog expire --expire=now --all` |
| Branch/PR refs còn | `git branch -a`, `git for-each-ref` phải rỗng ngoài HEAD |
| Issue tracker chứa diff | task spec chỉ giữ title + AC, không link Jira có comment fix |
| Test của PR nằm sẵn trong repo | chỉ thêm test **sau** khi agent dừng; test ẩn |

---

## 4. Metric (pre-registered)

| Loại | Metric | Cách đo |
|---|---|---|
| **Primary** | `defect_escape` | số test của PR fail sau khi agent dừng (0..n) |
| **Primary** | `acceptance` | pass/fail toàn bộ AC |
| Secondary | `rework` | số vòng sửa sau review (theo rubric), 0 nếu không có |
| Secondary | `actions` | số tool call (log) |
| Secondary | `wall_time` | phút tới khi agent dừng |
| **Bỏ** | token, score 0–1 | đã bác bỏ ở 21; không dùng để xếp hạng arm |

Rubric review (chỉ cho chất lượng kiến trúc, không dùng để pass/fail): 5 mục nhị phân — đúng layer,
không duplicate logic, i18n parity, error handling, test coverage của diff. Reviewer **không biết arm**;
ghi lại nếu biết.

---

## 5. Health gate: run hỏng thì loại, không tính

Trước khi chấm, mỗi run phải đạt **H ≥ 2** theo conformance của
[`18.rfc-capability-fabric.md`](../05.development/18.rfc-capability-fabric.md) §3.6:

| Tier | Điều kiện |
|---|---|
| H0 | hook fire (prompt/tool/stop) |
| H1 | guard deny **thật sự chặn** |
| H2 | COLLECT ra evidence có provenance |
| H3 | observe thấy đủ request/call/tool |
| H4 | native provider bind đúng |

Ghi `H` vào run record. Run `H < 2` → **discard**, chạy lại. Không có gate này, một run hỏng sẽ được
đọc thành "ESO không hiệu quả".

---

## 6. Bug gate: chỉ fix bug làm nhiễu phép đo

| Loại | Bug | Trạng thái |
|---|---|---|
| **Instrument** | ESO replay không nhận `reads` → mọi request bị chấm `score 0` | **đã fix** (`ingest-transcript.mjs`, `eso-ingest.mjs`) |
| **Instrument** | hook evidence không link → 6/6 check `skip` | **đã fix** — seam hash + one-time rebuild (`ingest-hooks.mjs`, 2 test) |
| **Treatment** | `verify-after-edit` tính cả file scratch ngoài repo → false `warn` | **đã fix** (`checks.mjs` + 2 test) |
| Treatment | `read-before-edit`/`edits-covered` chưa task-type aware | chấp nhận (đều `skip`/`heuristic`) |
| Khác | UI, edge case | hoãn |

Điều kiện vào pilot: **instrument bugs = 0**. Treatment bug được phép còn, nhưng phải ghi vào report.

---

## 7. Confound và cách chặn

| Confound | Chặn |
|---|---|
| Model khác nhau giữa host | ghi model vào run record; không so A/B khác model |
| Loop khác nhau (PTC vs native tool) | so trong cùng host (A vs B); B vs C chỉ để tham chiếu |
| Order effect | randomize thứ tự arm mỗi task; task order cố định |
| Repo state | reset cùng commit, cùng `.harness`/`.cursor` snapshot |
| Agent "bị quan sát" | chấp nhận; không đổi prompt giữa các arm |
| Budget | cap 45 phút + 200 tool call; ghi rõ nếu bị cắt |
| Human can thiệp | không can thiệp; nếu phải, ghi lại và loại run khỏi primary |

---

## 8. Instrumentation (dùng chính observe plane)

Một **run record** thống nhất, xuất từ 2 nguồn:

```json
{
  "runId": "bap38-A-1", "task": "BAP-38", "arm": "A", "host": "cursor", "model": "...",
  "repoCommit": "abc123", "startedAt": "...", "endedAt": "...",
  "h": 3, "health": {"hooks": true, "guards": true, "evidence": 12, "observe": true},
  "actions": 214, "testRuns": 16, "defectEscape": 0, "acceptance": true,
  "rework": 0, "notes": "run cắt ở 45 phút"
}
```

- DSH: `scripts/session-whatif.mjs --json` (đã có) + parse tool/test.
- Cursor: observe-server REST (`/api/requests/:id`) hoặc DB copy.
- Gộp: script mới `scripts/experiment-record.mjs` (chưa viết) đọc 2 nguồn, xuất record.

Giá trị phụ: chính experiment này là **bài test cho observe plane** — nếu không xuất được record
thống nhất, observe plane chưa đủ dùng cho chính sản phẩm.

---

## 9. Sample size và stopping rule

- Vòng 1: **3 task × 3 arm = 9 run**.
- Nếu chênh lệch `defect_escape` giữa A và B ≤ 1 defect → tăng lên 5 task (15 run) trước khi kết luận.
- Dừng sớm nếu: 2 task liên tiếp B thua A ở cả defect và rework → H1 bị bác bỏ, không cần chạy tiếp.

---

## 10. Decision rule (chốt trước)

| Kết quả | Kết luận |
|---|---|
| B giảm defect escape ≥ 25% so với A, và rework giảm | H1 đứng → ESO có giá trị trên host thiếu harness |
| B ≈ A | H1 bác bỏ → ESO không đáng cài trên Cursor |
| B ≈ C | H2 đứng → ESO đưa host yếu lên ngang native |
| B < C rõ rệt | ESO chưa đủ; nêu rõ thiếu gì (H3, guard, evidence) |
| B tốt nhưng D ≈ C | ESO chỉ có giá trị trên host **không** có harness native — định vị sản phẩm hẹp lại |

---

## 11. Việc phải làm trước pilot

1. Fix **hook evidence linking** (instrument bug duy nhất còn lại).
2. Chọn 3 ticket + tạo snapshot không lộ history.
3. Viết `scripts/experiment-record.mjs` (hoặc chấp nhận thu tay cho 9 run đầu).
4. Chạy **pilot 1 task × 3 arm**, kiểm tra rò rỉ + health gate, rồi mới mở rộng.
