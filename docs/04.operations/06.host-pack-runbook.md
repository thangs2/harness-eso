# Runbook — host pack của consumer

> Vận hành `.harness/host-pack/` trên consumer: kiểm tra, nâng cấp, thêm/gỡ IDE, xử lý sự cố.
> Đọc kèm [05.standalone-vs-observe-plane.md](../05.development/05.standalone-vs-observe-plane.md).

---

## 0. Một lệnh để biết trạng thái

```bash
./harness host-pack status --project x79      # hoặc: <consumer-path>
```

Exit **0** = lành. Exit **1** = cần xử lý (dùng được trong script/health probe).

| Trạng thái | Nghĩa | Việc cần làm |
|---|---|---|
| `version … ok` | lành | — |
| `version … ← outdated` | chạy được, lệch bản build | §3 refresh |
| `integrity FAILED` | file trong pack bị sửa/mất ⇒ **guard không quyết định gì** | §3 refresh |
| `verification FAILED` | hook không chạy được (bundle hỏng) | §3, rồi §4 |
| `NOT INSTALLED` | chưa provision, hoặc pack bị xoá | §2 provision |
| `IDE trees: none wired` | cài rồi nhưng không IDE nào gọi | §5 add-ide |
| `consumer-overridden: <hook>` | operator đã sửa hook đó; ta **cố ý không** ghi đè | xem §6 |

Thêm `--json` cho script, `--verify` để chạy lại probe ngay (mặc định đọc kết quả đã ghi).

## 1. Pack gồm gì

```
<consumer>/.harness/host-pack/
    harness-hook.mjs    dispatcher đã bundle — mọi hook, 0 import ngoài node:*
    route-hook.py       Python stdlib
    host-pack.json      version + sha256 từng file
```

`.harness/host-install-state.json` là sổ của ta: hook nào ta đã ghi, command nào, cái nào consumer
đã override. **Không** ghi `id` vào `hooks.json` — file đó là của host app.

## 2. Provision (consumer mới)

```bash
./harness init profile <consumer-path> --id <id> --host-mode dual-ide
```

Ghi cả project (`harness.config.json`, `.harness/decision-policy.json`, `integrations.json`) **và** host
pack. Cuối cùng nó **chạy thử từng hook**; hook nào không ra quyết định ⇒ **provision fail** chứ không
báo thành công.

Trước đó phải có build pack:

```bash
bun run build:host-pack        # bắt buộc sau khi clone; CI cũng chạy bước này
```

## 3. Refresh (nâng cấp pack)

Dùng sau khi `git pull` harness-eso, hoặc khi `status` báo `outdated` / `integrity FAILED`.

```bash
bun run build:host-pack
./harness host-pack refresh --project x79
```

- Cài lại pack (checksum verify) và **reconcile mọi IDE tree** đã ghi trong bootstrap.
- **Không** chạy lại project/policy — đó là việc của `init profile`. Refresh không đổi câu trả lời
  provisioning nào.
- An toàn để chạy nhiều lần: refresh ×N ⇒ `hooks.json` không đổi.
- Hook consumer đã sửa **được giữ nguyên** và ghi vào `overridden`.

## 4. Xử lý sự cố

| Triệu chứng | Nguyên nhân thường gặp | Việc làm |
|---|---|---|
| IDE báo lỗi hook mỗi lần chạy tool | pack thiếu/hỏng; guard fail-closed nên **chặn** | `host-pack status` → `refresh` |
| Mọi lệnh shell bị chặn | `guards.unavailable = deny` (mặc định) + engine không load được | `refresh`; nếu vẫn lỗi, xem §7 |
| Không có guard nào chạy nhưng IDE vẫn bình thường | IDE tree chưa wire (`unwired`) | §5 add-ide |
| Preflight không có `.eso-preflight.json` | prompt chưa submit sau khi provision, hoặc `eso.preflight.enabled=false` trong policy | submit lại prompt; kiểm policy |
| Guard chặn nhưng không rõ lý do | `deny` kèm `hookError`/`reason` trong payload | payload có `reason`; `missing_preflight` nghĩa là chưa đo cho turn đó |

Chạy một hook bằng tay để xem nó trả gì:

```bash
echo '{"command":"bun test"}' | node <consumer>/.harness/host-pack/harness-hook.mjs \
  --hook guard-shell --tree cursor
```

## 5. Thêm / gỡ IDE

```bash
./harness host-pack add-ide --project x79 --profile cursor-superset
./harness host-pack remove-ide --project x79 --ide cursor
```

- `add-ide` áp một **profile descriptor** (`profiles/host/<id>.json`), ghi vào `profileIds`, verify.
  IDE mới = thêm file descriptor; **không** copy code.
- `remove-ide` gỡ **đúng** entry của ta ở tree đó, prune event chỉ còn entry của ta, và **giữ**
  hook của consumer. Pack vẫn còn (dùng chung cho tree khác).

Muốn thêm IDE chưa được hỗ trợ (vd. Codex): tạo `profiles/host/<ide>-superset.json` mô tả thư mục,
event map và schema config của IDE đó, rồi `add-ide`. **Không đoán** đặc tả hook — một profile sai tạo
ra guard không bao giờ chạy, tệ hơn là không có guard.

## 6. Khi consumer sửa hook của ta

Nếu operator sửa một dòng ta đã ghi (thêm wrapper, đổi flag), lần refresh sau sẽ **giữ nguyên bản của
operator** và đánh dấu `overridden` — ta không ghi đè. `status` hiện `consumer-overridden: <hook>`.

Muốn lấy lại bản của product cho hook đó: sửa `hooks.json` cho khớp lệnh trong pack (hoặc gỡ entry và
`add-ide` lại), rồi `refresh`. Xoá `overridden` trong `.harness/host-install-state.json` cũng được,
nhưng sửa config thì rõ ràng hơn.

## 7. Nếu guard chặn hết và bạn cần chạy việc gấp

`guards.unavailable` trong `<consumer>/.harness/decision-policy.json`:

| Giá trị | Hành vi khi guard không quyết định được |
|---|---|
| `deny` (mặc định) | **chặn** + nêu lý do |
| `warn` | cho qua, nhưng turn đó mang ghi chú `[HARNESS GUARD UNAVAILABLE]` |
| (bỏ trống) | theo mặc định của từng hook: guard = deny, telemetry = allow |

`warn` **không tắt guard**: guard vẫn chạy, chỉ đổi cách xử lý khi nó *không chạy được*. Và nó không
áp cho hook telemetry (chặn cả turn vì một dòng trace không ghi được là bug tệ hơn).

Lưu ý: **không thể** hạ cấp guard bằng cách làm hỏng policy — policy không đọc được thì rơi về mặc
định `deny`.
