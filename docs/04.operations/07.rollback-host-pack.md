# Rollback — host pack trên consumer

> Dùng khi `init profile` / `host-pack refresh` trên một consumer đang chạy **không như mong đợi**.
> Đọc kèm [06.host-pack-runbook.md](./06.host-pack-runbook.md).

---

## 0. Trước khi roll out: chụp lại trạng thái

Làm **trước** khi provision consumer thật (vd. x79), vì sau đó các file cũ bị xoá khỏi working tree:

```bash
cd ~/Workspaces/x79
git status --porcelain .harness .cursor .agents > /tmp/x79-before.txt
git stash list                                   # biết đang có gì chưa commit
cp .cursor/hooks.json /tmp/x79-hooks.cursor.json
cp .agents/hooks.json /tmp/x79-hooks.agents.json
ls -la .cursor/hooks/harness-eso/ | wc -l        # đếm file shim cũ (x79: 9 mỗi tree)
```

Nếu x79 có working tree sạch, cách rollback mạnh nhất là `git checkout` (§2). Nếu không, backup ở trên
là đường lui.

## 1. Provision đổi cái gì

| Đối tượng | Trước | Sau |
|---|---|---|
| Hook impl | 9 file shim mỗi tree (`.cursor/hooks/harness-eso/*.mjs`) — **tracked trong git** | `.harness/host-pack/{harness-hook.mjs,route-hook.py,host-pack.json}` |
| `.cursor/hooks.json` · `.agents/hooks.json` | trỏ vào shim, không có `id` | cùng số hook, trỏ vào pack, mỗi cái thêm `id` (`harness-eso-*`) |
| `.harness/sidecar.env` | `HARNESS_ESO_ROOT=<checkout>` | **thay bằng** `HARNESS_REPO_ROOT=<consumer>` |
| `.harness/host-bootstrap.json` | `harnessEsoRoot: "<checkout>"` | `hostPack: { version, ok, failures }` |
| `.harness/harness.config.json` | `registry.registry` = path trong checkout | `~/.harness/registry.json` |
| `.harness/.gitignore` | `*` + 3 ngoại lệ | allowlist mới: **chỉ** `!.gitignore` + `!README.md` — pack, sidecar.env, bootstrap, state, policy, integrations, docs đều **không** được admit |
| `.harness/host-install-state.json` | (chưa có) | sổ theo dõi hook ta đã ghi |
| `~/.harness/` | (chưa có) | `workspace.json` (registry: `projects[]`), `registry.json` |

**18 file shim cũ bị xoá khỏi working tree** (chúng đang được track). `git status` sẽ hiện 18 deletion
— đó là dự kiến, không phải lỗi.

DB **không** đổi chỗ: `~/.harness/observe/x79/harness.db`. Mọi dữ liệu lịch sử còn nguyên.

## 2. Rollback toàn phần (consumer là git repo, working tree sạch)

```bash
cd ~/Workspaces/x79
git checkout -- .cursor/hooks.json .agents/hooks.json
git checkout -- .harness/sidecar.env .harness/host-bootstrap.json .harness/.gitignore
git checkout -- .harness/harness.config.json .harness/integrations.json
git checkout -- .cursor/hooks/harness-eso .agents/hooks/harness-eso   # khôi phục 18 shim
rm -rf .harness/host-pack .harness/host-install-state.json
```

Sau đó shim cũ chạy lại — nhưng chúng spawn từ `$HARNESS_ESO_ROOT`, nên **phải** khôi phục biến đó:

```bash
# sidecar.env đã được git checkout về bản cũ (có HARNESS_ESO_ROOT)
grep HARNESS_ESO_ROOT .harness/sidecar.env    # phải thấy dòng này
```

Nếu `git checkout` không đưa `.harness/sidecar.env` về (vì nó bị ignore ở một số consumer), set tay:

```bash
echo 'HARNESS_ESO_ROOT=/Users/<you>/Workspaces/harness-eso' >> .harness/sidecar.env
```

**Điều kiện:** checkout harness-eso **phải còn** — bản cũ phụ thuộc nó. Đây là lý do thay đổi này tồn tại.

## 3. Rollback cục bộ (không cần git)

Chỉ gỡ wiring, giữ pack:

```bash
./harness host-pack remove-ide --project x79 --ide cursor
./harness host-pack remove-ide --project x79 --ide agents
```

Gỡ **đúng** entry của ta, giữ hook riêng của consumer (`guard-write.py`, `guard-shell.py`). Pack vẫn nằm
trong `.harness/host-pack/` để `add-ide` dùng lại.

Rollback một phần (một IDE):

```bash
./harness host-pack remove-ide --project x79 --ide cursor     # chỉ Cursor
```

## 4. Rollback state sản phẩm

`~/.harness/` được **copy** từ `<checkout>/.harness/`, không move — bản gốc còn nguyên:

```bash
ls -la ~/.harness/                                 # workspace.json (registry), registry.json
```

Quay lại dùng state cũ:

```bash
rm -rf ~/.harness/{workspace.json,registry.json,projects}
```

Nhưng từ giờ code **mặc định** đọc `~/.harness`, nên muốn dùng state trong checkout thì phải chỉ định:

```bash
export HARNESS_PRODUCT_STATE_DIR=~/Workspaces/harness-eso/.harness
```

## 5. Thứ tự quan trọng

1. **Gỡ wiring trước** (§3) — để IDE thôi gọi vào pack. Làm ngược lại sẽ để `hooks.json` trỏ vào một
   pack đã xoá ⇒ mọi hook fail ⇒ guard fail-closed ⇒ chặn hết.
2. Rồi mới khôi phục shim cũ (§2) + `HARNESS_ESO_ROOT`.
3. Cuối cùng mới động vào `~/.harness` (§4) — DB nằm đó, xoá nhầm là mất dữ liệu observe.

## 6. Điều KHÔNG rollback được

| | |
|---|---|
| DB đã ingest bằng code mới | migration thêm cột; schema mới **tương thích ngược** nhưng đừng hạ cấp giữa chừng |
| `.harness/host-install-state.json` bị xoá tay | lần refresh sau mất khả năng phân biệt "ta ghi" vs "operator sửa" ⇒ có thể append trùng. Sửa: `remove-ide` rồi `add-ide` |
| `overridden` trong state | nếu operator đã sửa hook, ta **cố ý** không ghi đè; rollback không tự lấy lại bản product |

## 7. Sau rollback, kiểm tra

```bash
cd ~/Workspaces/x79
git status --porcelain .harness .cursor .agents      # so với /tmp/x79-before.txt
echo '{"command":"bun test"}' | node .cursor/hooks/harness-eso/guard-shell.mjs   # shim cũ chạy?
```

Nếu shim cũ báo `HARNESS_ESO_ROOT is not set` ⇒ §2 chưa xong.
