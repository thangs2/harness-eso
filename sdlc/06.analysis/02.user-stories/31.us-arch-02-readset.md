# US-ARCH-02 — Q1 — sửa X thì **phải đọc file nào**

## Story

> **Là** A-02, **tôi muốn** đọc đúng tập file liên quan, độ sâu có trần, và biết khi nào **không đủ phủ** để nói, **để** không phải sửa mù.

## Giá trị thật thuộc về ai

**A-02** — người chia slice và phải nói peer đọc gì. Read set sai làm **A-03** sửa vào chỗ khác, **A-01** trả giá bằng turn
sửa lại. Read set bị **cắt** mà không nói còn tệ hơn: **A-08** đọc lại tưởng nó đã đầy.

## Vì sao không gộp vào `US-ARCH-01`

`US-ARCH-01` dựng **mô hình** (node · edge · id ổn định · off-path). Đây là **một câu hỏi** trên mô hình đó. Gộp năm câu vào một
story là để **năm câu trả lời** dùng chung một bộ AC — và câu nào phủ thấp cũng sẽ **được trả lời như câu phủ cao**.

## Trong phạm vi

- Trả lời *"sửa X thì đọc file nào"*, độ sâu có **trần**, kèm `completeness` của **chính Q1**.
- Fan-out lớn ⇒ danh sách **bị chặn trần** + nói rõ đã chặn + tổng thật.
- Read set **rỗng** là câu trả lời hợp lệ, vẫn kèm độ phủ của quan hệ đã dùng.
- Phủ thấp ⇒ `unknown`, **không** `absent`.
