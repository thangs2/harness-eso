# 00 — Technical (architecture · data · API)

> **One door into the technical layer.** Three artefacts, three depths, one question each. Read in this order:
> **structure → storage → contract.**
>
> **UI is not here.** Design lives at [`08.ui-design/`](../08.ui-design/00.index.md) because it follows its own standards
> (Figma · Penpot · UI guidelines) that have nothing to do with how the parts call each other.

| # | Folder | Answers | Depth | Gate |
|---|---|---|---|---|
| 01 | [`01.architecture/`](./01.architecture/00.index.md) | **structure**: what exists · who talks to whom · where judgement runs | **high** | reference layer — no per-slice gate |
| 02 | [`02.data-design/`](./02.data-design/00.index.md) | **storage**: what is stored · what the database enforces | middle | stage 5 |
| 03 | [`03.api/`](./03.api/00.index.md) | **contract**: endpoints · payloads · errors · idempotency | **low** | stage 4 |

## 1. Why they are grouped

They are **one reasoning chain**, not three subjects:

```text
C4 says: C1 · C3 · C5      (a container called "control plane" exists)
data says: evidence_turn   (it stores one row per judgement)
API says:  E1 evidence:batch (that container receives turns through this)
```

Grouping makes that chain **walkable in one folder**. Splitting it across three top-level folders made a reader guess which one
owns a question — and the answer is often "all three".

## 2. Two **kinds** of technical document — never confuse them

| | **Reference layer** (`01.architecture`) | **Per-slice artefact** (`02` · `03`) |
|---|---|---|
| Unit | the **system** (one set, for everything) | **one slice** |
| Written | early, revised when a **seam** changes | once per slice |
| Gate | **none** — it has a **revision rule** instead | **stage 4** (contract) · **stage 5** (data) |
| If stale | the whole system is misread | one slice is wrong |

**This distinction is why C4 comes first and is not "stage 6".** An earlier version of the lifecycle standard called stage 6
"Architecture & WBS" and listed C4 as its output — wrong, and it produced a reversed reading order
([`01.sdlc-delivery-lifecycle-standard`](../02.governance/01.standard/01.quality-gate/01.sdlc-delivery-lifecycle-standard.md) Δ).

## 3. Round-trip check — the coupling that a folder cannot show

**X9.** Every endpoint names **real tables**; every table has **a path from** an endpoint, or an `OUT` with a reason.

Why it is a check and not an ordering rule: in this very project three tables were **added after** their endpoints existed —
`sdlc_profile` · `ticket_pack` · `proposal`. Whichever order you pick, the other side moves. So bind them with a check instead of
ordering them.
