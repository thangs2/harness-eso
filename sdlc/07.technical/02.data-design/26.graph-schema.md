# `graph` — `graph_node` · `graph_edge` · `source_claim` · `completeness`

**Nguồn:** [`BIP 2.1`](../../09.wbs/01.packets/01.bip/01.graph-schema.md) §5 · [`18.graph-queries`](../01.architecture/18.graph-queries.md) §3–§4 ·
[`AC-ARCH-01`](../../06.analysis/03.acceptance-criteria/21.arch-us-01-graph.md) · [`20.manifest`](20.manifest.md) §3 · [`02.roundtrip`](../03.api/02.roundtrip.md) §1

**Database:** `graph` ([`D-73`](../../03.inception/02.decision-log/06.architecture-va-data.md)) — dữ liệu **dẫn xuất**, **được phép drop** và
extract lại; không join với `cp`/`ctx`. Vì vậy ba bảng topology được **thay** theo `build_id`, còn `source_claim` là **append-only**
(`BR-06`): nó là nơi duy nhất trả lời *"vì sao cạnh này tồn tại"*.

> **Đóng `OPEN-GRAPH-SCHEMA-01`.** Trước file này `02.schema` §3 ghi *"`graph` — chưa có bảng nào"*; hình dạng cột chỉ nằm trong
> packet BIP §5. File này là **nguồn DDL Stage 5** cho `graph`; BIP §5 chỉ còn là tham chiếu hình dạng.

## 1. Sáu bảng — một đơn vị migration

| Bảng | Giữ gì | Khoá chính | Ghi |
|---|---|---|---|
| `graph_node` | một node của AST/docs graph | `(project, build_id, node_id)` | `node_id` **ổn định qua rebuild** ([`AC-ARCH-01-04`](../../06.analysis/03.acceptance-criteria/21.arch-us-01-graph.md)) |
| `graph_edge` | một quan hệ **có hướng** giữa hai node | `(project, build_id, edge_id)` | **không** cột nguồn — nguồn ở `source_claim` |
| `source_claim` | nguồn gốc của một edge | `(project, build_id, edge_id, seq)` | **append-only** (`BR-06`) — `REVOKE` + trigger |
| `completeness` | độ phủ **theo từng câu** Q1–Q5 | `(project, build_id, question)` | `value` **không** NULL (`BR-05`) |
| `manifest_entry` | build output cho `coverage` — mẫu số độc lập | `(project, build_id, kind, logical_id)` | **append-only** (`BR-06`) — trigger |
| `graph_index_run` | trạng thái chạy và `source_hash` index graph cho API-28 | `(project, build_id, source_kind)` | ghi / cập nhật status, immutable key/hash qua trigger |

Sáu bảng nằm chung **một** file vì chúng là **một** migration: `graph_edge` có FK vào `graph_node`, và `source_claim` chỉ có nghĩa
khi `graph_edge` đã tồn tại. [`BIP 2.1`](../../09.wbs/01.packets/01.bip/01.graph-schema.md) §4 chốt FK `edge → node` phải nằm **cùng
transaction**. Đây là ngoại lệ có lý do của luật *"mỗi bảng một file"* ở [`02.schema` §2](02.schema.md).

## 2. DDL (Postgres)

```sql
-- 1. graph_node: node của code graph + docs graph
CREATE TABLE IF NOT EXISTS graph_node (
  project   text NOT NULL,                  -- = ownerId (D-22); phần ĐẦU của mọi khoá
  build_id  text NOT NULL,                  -- lần build/extract; cùng quy tắc với manifest_entry.build_id
  node_id   text NOT NULL,                  -- id ổn định giữa các build (AC-ARCH-01-04)
  kind      text NOT NULL,                  -- ĐÓNG — xem graph_node_kind_closed
  node_key  text NOT NULL,                  -- khoá tự nhiên trong kind: FQN symbol · tên bảng · route · path doc
  path      text,                           -- file nguồn; NULL khi kind không ứng một file (module · namespace)
  PRIMARY KEY (project, build_id, node_id),
  CONSTRAINT graph_node_kind_closed CHECK (kind IN
    ('module','namespace','class','method','entity','dto','table',
     'endpoint','permission','app_service','service','route','doc')),
  -- Cùng (kind, key) trong một build là MỘT node — nếu không, mỗi lần index lại sinh bản trùng.
  CONSTRAINT graph_node_key_unique UNIQUE (project, build_id, kind, node_key)
);

CREATE INDEX IF NOT EXISTS idx_graph_node_kind ON graph_node (project, build_id, kind);
CREATE INDEX IF NOT EXISTS idx_graph_node_path ON graph_node (project, build_id, path);

-- 2. graph_edge: quan hệ có hướng; KHÔNG có cột nguồn (D-25 · BR-06)
CREATE TABLE IF NOT EXISTS graph_edge (
  project      text NOT NULL,
  build_id     text NOT NULL,
  edge_id      text NOT NULL,               -- id ổn định theo (from, to, kind)
  from_node_id text NOT NULL,
  to_node_id   text NOT NULL,
  kind         text NOT NULL,               -- ĐÓNG — xem graph_edge_kind_closed
  conflict     boolean NOT NULL DEFAULT false,  -- D-57: xung đột là CỜ trên edge, không phải điểm phủ
  PRIMARY KEY (project, build_id, edge_id),
  CONSTRAINT graph_edge_kind_closed CHECK (kind IN
    ('references','maps_to','depends_on','requires','defines',
     'tenant_marker','specifies','constrains','supersedes')),
  -- FK cùng build: một edge không được trỏ node của build khác.
  CONSTRAINT graph_edge_from_node_fk FOREIGN KEY (project, build_id, from_node_id)
    REFERENCES graph_node (project, build_id, node_id),
  CONSTRAINT graph_edge_to_node_fk FOREIGN KEY (project, build_id, to_node_id)
    REFERENCES graph_node (project, build_id, node_id),
  CONSTRAINT graph_edge_unique_triple UNIQUE (project, build_id, from_node_id, to_node_id, kind)
);

CREATE INDEX IF NOT EXISTS idx_graph_edge_from ON graph_edge (project, build_id, from_node_id);
CREATE INDEX IF NOT EXISTS idx_graph_edge_to ON graph_edge (project, build_id, to_node_id);
CREATE INDEX IF NOT EXISTS idx_graph_edge_kind ON graph_edge (project, build_id, kind);

-- 3. source_claim: provenance của edge, CHỈ ghi thêm (BR-06)
CREATE TABLE IF NOT EXISTS source_claim (
  project     text NOT NULL,
  build_id    text NOT NULL,
  edge_id     text NOT NULL,               -- trỏ graph_edge.edge_id; KHÔNG FK — xem §4
  seq         int  NOT NULL,               -- thứ tự claim trong một edge
  source_kind text NOT NULL,               -- ĐÓNG: roslyn | docs
  claim       text NOT NULL,               -- điều nguồn nói (vd. "OrderService → IOrderRepository")
  at          timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (project, build_id, edge_id, seq),
  CONSTRAINT source_claim_seq_positive CHECK (seq >= 1),
  CONSTRAINT source_claim_source_kind_closed CHECK (source_kind IN ('roslyn','docs'))
);

CREATE INDEX IF NOT EXISTS idx_source_claim_kind ON source_claim (project, build_id, source_kind);

-- 4. completeness: MỘT dòng cho mỗi (build, câu hỏi) — BR-05
CREATE TABLE IF NOT EXISTS completeness (
  project     text NOT NULL,
  build_id    text NOT NULL,
  question    text NOT NULL,               -- ĐÓNG: Q1..Q5 (18.graph-queries §2)
  per_kind    jsonb NOT NULL,              -- { "kind": coverage } — chỉ đọc nguyên khối, không lọc trong jsonb
  value       numeric(4,3) NOT NULL,       -- min(coverage(kind)) trên K(question); KHÔNG NULL
  measured_at timestamptz NOT NULL,
  PRIMARY KEY (project, build_id, question),
  CONSTRAINT completeness_question_closed CHECK (question IN ('Q1','Q2','Q3','Q4','Q5')),
  CONSTRAINT completeness_value_range CHECK (value >= 0 AND value <= 1),
  CONSTRAINT completeness_per_kind_object CHECK (jsonb_typeof(per_kind) = 'object')
);

-- 5. manifest_entry: build output cho coverage — khoá (project, build_id, kind, logical_id)
CREATE TABLE IF NOT EXISTS manifest_entry (
  project      text NOT NULL,
  build_id     text NOT NULL,
  kind         text NOT NULL,
  logical_id   text NOT NULL,
  path         text NOT NULL,
  at           timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (project, build_id, kind, logical_id)
);

CREATE INDEX IF NOT EXISTS idx_manifest_entry_kind ON manifest_entry (project, build_id, kind);

DROP TRIGGER IF EXISTS trg_manifest_entry_no_change ON manifest_entry;
CREATE TRIGGER trg_manifest_entry_no_change
BEFORE UPDATE OR DELETE ON manifest_entry
FOR EACH ROW EXECUTE FUNCTION raise_append_only();

-- 6. graph_index_run: trạng thái chạy và source_hash index graph cho API-28
CREATE TABLE IF NOT EXISTS graph_index_run (
  project      text NOT NULL,
  build_id     text NOT NULL,
  source_kind  text NOT NULL CHECK (source_kind IN ('roslyn','docs')),
  source_hash  text NOT NULL,
  status       text NOT NULL CHECK (status IN ('queued','running','succeeded','failed','parse_failed')),
  created_at   timestamptz NOT NULL DEFAULT now(),
  completed_at timestamptz,
  PRIMARY KEY (project, build_id, source_kind)
);

CREATE INDEX IF NOT EXISTS idx_graph_index_run_build ON graph_index_run (project, build_id);

CREATE OR REPLACE FUNCTION check_graph_index_run_immutable_keys()
RETURNS TRIGGER AS $$
BEGIN
  IF NEW.project <> OLD.project OR NEW.build_id <> OLD.build_id OR NEW.source_kind <> OLD.source_kind OR NEW.source_hash <> OLD.source_hash THEN
    RAISE EXCEPTION 'IMMUTABLE_KEY: project, build_id, source_kind, and source_hash cannot be modified';
  END IF;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

DROP TRIGGER IF EXISTS trg_graph_index_run_immutable ON graph_index_run;
CREATE TRIGGER trg_graph_index_run_immutable
BEFORE UPDATE ON graph_index_run
FOR EACH ROW EXECUTE FUNCTION check_graph_index_run_immutable_keys();
```

**Vì sao `value` không có `CHECK` bằng `min(per_kind)`:** PostgreSQL không cho `CHECK` đọc tập con của `jsonb`. Cột giữ **đúng**
công thức [`18` §3](../01.architecture/18.graph-queries.md); phép so `value = min(per_kind)` là `AC-ARCH-01-02`, kiểm ở tầng đọc.

**Nguồn của bốn tập đóng:** `graph_node.kind` = `K(Q)` của [`18` §2](../01.architecture/18.graph-queries.md) + `node.kind` của
[`API-35`](../03.api/36.graph-docs.md) + `kind` của [`manifest_entry`](20.manifest.md) §2; `graph_edge.kind` = quan hệ của `18` §2 +
`specifies`/`constrains`/`supersedes` của [`BIP 2.6`](../../09.wbs/01.packets/01.bip/46.docs-graph.md) §5; `source_kind` = `roslyn`
([`API-28`](../03.api/29.graph-index.md)) + `docs` (2.6); `question` = `Q1`…`Q5` của `18` §2. Thêm một giá trị là sửa **CHECK + `K(Q)` +
test** — không phải thêm dòng dữ liệu.

## 3. Khoá, FK, và `project` leading

| Luật | Cưỡng chế |
|---|---|
| `project` là **phần đầu** của mọi khoá chính và mọi index | PK `(project, build_id, …)`; index dưới đây bắt đầu bằng `project` |
| `build_id` là phần thứ hai | hai build **không** trộn node/edge/completeness; `coverage` so đúng một build |
| `graph_edge → graph_node` **cùng build** | FK composite `(project, build_id, from_node_id)` + `(project, build_id, to_node_id)` |
| `source_claim` **không** FK vào `graph_edge` | xem §4 — FK sẽ chặn rebuild hoặc xoá provenance, cả hai đều trái `BR-06`/`D-73` |
| `completeness` không FK | `build_id` là khoá logic; `manifest_entry` — mẫu số của `coverage` — đã được gán database `graph` ở [`02.schema` §3](02.schema.md), đóng `OPEN-GRAPH-SCHEMA-04` |

## 4. `source_claim` append-only — và vì sao **không** FK

```sql
REVOKE UPDATE, DELETE, TRUNCATE ON source_claim FROM eso_app;

DROP TRIGGER IF EXISTS trg_source_claim_no_change ON source_claim;
CREATE TRIGGER trg_source_claim_no_change
BEFORE UPDATE OR DELETE ON source_claim
FOR EACH ROW EXECUTE FUNCTION raise_append_only();   -- RAISE ABORT 'APPEND_ONLY'
```

| | |
|---|---|
| **Vì sao `REVOKE` lẫn trigger** | `REVOKE` chặn role ứng dụng; trigger chặn cả role còn quyền (kể cả chủ bảng). Một mình `REVOKE` là lời dặn, không phải cơ chế |
| **Vì sao không FK `source_claim.edge_id → graph_edge`** | `graph` **được phép drop/rebuild**; `graph_edge` bị thay theo `build_id`. FK `RESTRICT` chặn rebuild; FK `CASCADE` **xoá** provenance — đúng thứ `BR-06` cấm. `edge_id` vẫn ổn định và có index qua PK, còn claim mồ côi sau rebuild là **log** (không join vào edge hiện hành), không phải lỗi |
| **Ai ghi** | chỉ extractor/bộ dựng coverage; **không** endpoint nào `UPDATE`/`DELETE` ([`02.roundtrip`](../03.api/02.roundtrip.md) §1: `API-28` · `API-29` ghi) |

## 5. Cô lập project (RLS) — `ENABLE` + `FORCE` + `WITH CHECK`

```sql
ALTER TABLE graph_node   ENABLE ROW LEVEL SECURITY;
ALTER TABLE graph_node   FORCE ROW LEVEL SECURITY;
ALTER TABLE graph_edge   ENABLE ROW LEVEL SECURITY;
ALTER TABLE graph_edge   FORCE ROW LEVEL SECURITY;
ALTER TABLE source_claim ENABLE ROW LEVEL SECURITY;
ALTER TABLE source_claim FORCE ROW LEVEL SECURITY;
ALTER TABLE completeness ENABLE ROW LEVEL SECURITY;
ALTER TABLE completeness FORCE ROW LEVEL SECURITY;
ALTER TABLE manifest_entry ENABLE ROW LEVEL SECURITY;
ALTER TABLE manifest_entry FORCE ROW LEVEL SECURITY;
ALTER TABLE graph_index_run ENABLE ROW LEVEL SECURITY;
ALTER TABLE graph_index_run FORCE ROW LEVEL SECURITY;

DROP POLICY IF EXISTS graph_node_project_only ON graph_node;
CREATE POLICY graph_node_project_only ON graph_node
  FOR ALL
  USING      (project = current_setting('eso.project', true))
  WITH CHECK (project = current_setting('eso.project', true));

CREATE POLICY graph_edge_project_only ON graph_edge
  FOR ALL

DROP POLICY IF EXISTS source_claim_project_only ON source_claim;
CREATE POLICY source_claim_project_only ON source_claim
  FOR ALL
  USING      (project = current_setting('eso.project', true))
  WITH CHECK (project = current_setting('eso.project', true));

DROP POLICY IF EXISTS completeness_project_only ON completeness;
CREATE POLICY completeness_project_only ON completeness
  FOR ALL
  USING      (project = current_setting('eso.project', true))
  WITH CHECK (project = current_setting('eso.project', true));

DROP POLICY IF EXISTS manifest_entry_project_only ON manifest_entry;
CREATE POLICY manifest_entry_project_only ON manifest_entry
  FOR ALL
  USING      (project = current_setting('eso.project', true))
  WITH CHECK (project = current_setting('eso.project', true));

DROP POLICY IF EXISTS graph_index_run_project_only ON graph_index_run;
CREATE POLICY graph_index_run_project_only ON graph_index_run
  FOR ALL
  USING      (project = current_setting('eso.project', true))
  WITH CHECK (project = current_setting('eso.project', true));

DROP POLICY IF EXISTS graph_node_project_only ON graph_node;
CREATE POLICY graph_node_project_only ON graph_node
  FOR ALL
  USING      (project = current_setting('eso.project', true))
  WITH CHECK (project = current_setting('eso.project', true));

DROP POLICY IF EXISTS graph_edge_project_only ON graph_edge;
CREATE POLICY graph_edge_project_only ON graph_edge
  FOR ALL
  USING      (project = current_setting('eso.project', true))
  WITH CHECK (project = current_setting('eso.project', true));

DROP POLICY IF EXISTS source_claim_project_only ON source_claim;
CREATE POLICY source_claim_project_only ON source_claim
  FOR ALL
  USING      (project = current_setting('eso.project', true))
  WITH CHECK (project = current_setting('eso.project', true));

DROP POLICY IF EXISTS completeness_project_only ON completeness;
CREATE POLICY completeness_project_only ON completeness
  FOR ALL
  USING      (project = current_setting('eso.project', true))
  WITH CHECK (project = current_setting('eso.project', true));
```

`USING` lọc **đọc**, `WITH CHECK` chặn **ghi**; thiếu `WITH CHECK` thì `INSERT` project khác **lọt** rồi vô hình với chính người
vừa ghi — mất dữ liệu im lặng ([`02.schema` §4](02.schema.md)). `FORCE` để test chạy dưới role migration **không xanh giả**.
Test isolation phải chạy bằng role `NOSUPERUSER NOBYPASSRLS` trong **một** session ([`BIP 2.1`](../../09.wbs/01.packets/01.bip/01.graph-schema.md) §6).

## 6. Index tối thiểu

| Index | Cho truy vấn |
|---|---|
| `graph_node` PK `(project, build_id, node_id)` | đọc node theo id; rebuild theo `(project, build_id)` |
| `graph_node (project, build_id, kind)` | Q1/Q3 lọc theo loại node |
| `graph_node (project, build_id, path)` | *"file nào cho symbol X"* — Q1 |
| `graph_edge (project, build_id, from_node_id)` | traversal xuôi (Q1 · Q2 · Q3) |
| `graph_edge (project, build_id, to_node_id)` | impact ngược (Q2) |
| `graph_edge (project, build_id, kind)` | lọc theo quan hệ (Q4 · Q5) |
| `source_claim` PK | *"vì sao cạnh này tồn tại"* theo edge |
| `source_claim (project, build_id, source_kind)` | audit theo nguồn |
| `completeness` PK | độ phủ của đúng câu Q, đúng build |

## 7. Migration

1. **Một transaction:** `graph_node` → `graph_edge` → `source_claim` → `completeness`; FK `edge → node` chỉ hợp lệ nếu node đã có.
2. **Idempotent** (`D-47`): `CREATE TABLE/INDEX IF NOT EXISTS`; policy và trigger dùng `DROP … IF EXISTS` trước `CREATE`.
3. **RLS + `REVOKE` + trigger trong cùng transaction với bảng** — bật sau là có cửa sổ ghi bằng role ứng dụng.
4. **Rebuild** (`API-29`) thay `graph_node`/`graph_edge` của **đúng** `build_id`; **không** chạm build khác. `source_claim` chỉ được
   **thêm**, không xoá — claim của edge không còn tồn tại là log lịch sử, không phải dòng cần dọn.
5. `graph` drop/rebuild **không** chạm `ctx`/`cp` ([`D-73`](../../03.inception/02.decision-log/06.architecture-va-data.md)).

### 8.1 `OPEN-GRAPH-SCHEMA-02` — full diff: code SQLite vs target Stage 5b

| Mục | [`eso/graph/src/schema.mjs`](../../../eso/graph/src/schema.mjs) (đang chạy) | File này (target Postgres, BIP §5 + `D-73`) |
|---|---|---|
| engine / kiểu | SQLite: `TEXT` timestamp, `metadata_json`, trigger `RAISE(ABORT)` | Postgres: `timestamptz`, `jsonb`, `EXECUTE FUNCTION raise_append_only()` |
| `graph_node` PK | `id TEXT PRIMARY KEY` — **không** `project` leading | `(project, build_id, node_id)` |
| `build_id` | **không** có trên node/edge/completeness | phần thứ hai của mọi khoá; rebuild theo `(project, build_id)` |
| `graph_node` cột | `id` · `project` · `kind` · `name` · `path` · `metadata_json` · `created_at` · `updated_at` | `project` · `build_id` · `node_id` · `kind` · `node_key` · `path`; `kind` **đóng** |
| `graph_edge` cột | `id` · `project` · `source_id` · `target_id` · `relation` · `metadata_json` · `created_at` | `project` · `build_id` · `edge_id` · `from_node_id` · `to_node_id` · `kind` · `conflict`; `kind` **đóng** |
| `source_claim` đích | gắn **node**: `node_id` · `claim_type` · `claim_payload` · `created_at` | gắn **edge**: `edge_id` · `seq` · `source_kind` · `claim` · `at` (BIP §5; xem `OPEN-05`) |
| append-only | trigger `UPDATE`/`DELETE`, **không** `REVOKE` | `REVOKE UPDATE, DELETE, TRUNCATE` **+** trigger |
| `completeness` | `id` PK · `question_id` · `value` · `status` · `details_json` · `calculated_at`; **không** `build_id`/`per_kind` | `(project, build_id, question)` PK · `per_kind jsonb` · `value` · `measured_at`; **không** `status` |
| RLS | `ENABLE` + `USING` | `ENABLE` + **`FORCE`** + `USING` + **`WITH CHECK`** cho cả bốn bảng |
| FK | `source_claim.node_id → graph_node.id`; edge → node theo `id` đơn | edge → node theo **cùng** `(project, build_id)`; source_claim **không** FK (lý do §4) |
| idempotent | `IF NOT EXISTS` cho bảng/index | `IF NOT EXISTS` + `DROP … IF EXISTS` trước policy/trigger (`D-47`) |

**Ba `OPEN` đầu là tích hợp liên stage, không phải lỗi thiết kế Stage 5:** DDL/khoá/index/RLS/append-only ở file này đã đủ; chúng
chỉ ra ba chỗ **khác** chưa cập nhật theo (code · status register · data inventory). `OPEN-GRAPH-SCHEMA-05` là câu hỏi hình dạng
duy nhất còn mở trong bốn bảng.

## Luật sửa

File này **sai** khi:

1. DDL ở đây khác DDL chạy thật — file là bản đọc được của schema, không phải nguồn song song;
2. [`01.entities`](01.entities.md) mô tả `E-GNODE` khác file này;
3. `03.api` có endpoint ghi vào bốn bảng mà file này không nêu;
4. một `CHECK` hoặc `FK` bị bỏ mà không có quyết định — mỗi cái đang thay cho một `if` trong code;
5. `source_claim` nhận `UPDATE`/`DELETE`, hoặc `project` rời khỏi vị trí đầu khoá.
