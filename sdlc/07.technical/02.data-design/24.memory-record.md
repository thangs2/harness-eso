# `memory_record` — fact 12 chiều, có version, chỉ ghi thêm

**Nguồn:** [`ESO-MEMORY`](../../05.requirements/03.eso-memory.md) E-1…E-7 · [`US-MEM-01`](../../06.analysis/02.user-stories/59.memory-contract.md) ·
[`AC-MEM-01`](../../06.analysis/03.acceptance-criteria/59.memory-contract.md) · [`D-73`](../../03.inception/02.decision-log/06.architecture-va-data.md) ·
[`BR-06`](../../06.analysis/01.business-analysis/03.business-rules.md)

**Database:** `ctx` ([`D-73`](../../03.inception/02.decision-log/06.architecture-va-data.md)) — *"memory không có git"*: backup hằng ngày,
**không bao giờ drop**. Không nằm ở `cp` (dựng lại từ git) và không nằm ở `graph` (được phép drop).

```sql
CREATE TABLE memory_record (
  project       text        NOT NULL,      -- = ownerId (D-22); phần ĐẦU của mọi khoá
  memory_id     uuid        NOT NULL,
  version       int         NOT NULL CHECK (version >= 1),
  memory_type   text        NOT NULL,      -- đóng — xem memory_type_closed
  title         text        NOT NULL,
  content       text        NOT NULL,
  concepts      text[]      NOT NULL DEFAULT '{}',   -- từ khoá đã tách (E-1.6)
  files         text[]      NOT NULL DEFAULT '{}',   -- neo vào code (E-1.3)
  session_ids   text[]      NOT NULL DEFAULT '{}',   -- neo vào phiên (E-1.4)
  strength      numeric(4,3) NOT NULL CHECK (strength >= 0 AND strength <= 1),
  tier          text        NOT NULL,      -- short | long (AC-MEM-02-02)
  scope_kind    text        NOT NULL,      -- repo | service | route | module (E-3)
  scope_value   text        NOT NULL,
  provenance    text        NOT NULL,      -- native | migrated (E-7, D-89)
  migrated_from text,                      -- id ở store nguồn; chỉ khi provenance='migrated'
  migrated_at   timestamptz,
  content_hash  text        NOT NULL,      -- sha256 nội dung chuẩn hoá — idempotency + tamper
  created_at    timestamptz NOT NULL,      -- thời điểm version 1
  updated_at    timestamptz NOT NULL,      -- thời điểm version NÀY được ghi
  CONSTRAINT memory_type_closed CHECK (memory_type IN
    ('workflow','architecture','fact','decision','pattern','preference','bug')),
  CONSTRAINT memory_tier_closed  CHECK (tier IN ('short','long')),
  CONSTRAINT memory_scope_closed CHECK (scope_kind IN ('repo','service','route','module')),
  CONSTRAINT memory_prov_closed  CHECK (provenance IN ('native','migrated')),
  CONSTRAINT memory_migrated_has_source
    CHECK (provenance <> 'migrated' OR (migrated_from IS NOT NULL AND migrated_at IS NOT NULL)),
  PRIMARY KEY (project, memory_id, version)
);
```

**`project` là phần đầu của khoá chính** — luật §1 của [`02.schema`](02.schema.md), không phải tuỳ chọn: mọi index dưới đây bắt
đầu bằng `project`, và RLS lọc theo cùng cột đó.

## 1. Mười hai chiều — cột nào giữ chiều nào

| agentmemory | Ở đây | Ghi chú |
|---|---|---|
| `id` | `memory_id` | `uuid`; ổn định qua mọi version |
| `version` | `version` | tăng, **không** ghi đè |
| `isLatest` | **view** `memory_latest.is_latest` | **không** phải cột — §2 |
| `type` | `memory_type` | tập **đóng** 7 giá trị; `decision` ≠ `preference` phải lọc được |
| `title` · `content` | `title` · `content` | nội dung |
| `concepts[]` | `concepts` | `text[]` + GIN — recall theo concept |
| `files[]` | `files` | `text[]` + GIN — *"memory nào nói về file này"* |
| `sessionIds[]` | `session_ids` | `text[]` + GIN — trace ngược về phiên/turn |
| `strength` | `strength` | `0..1`; **decay tính lúc đọc**, xem §4 |
| `createdAt` · `updatedAt` | `created_at` · `updated_at` | version này ghi lúc nào |

Ngoài 12 chiều, ba chiều **bắt buộc** của ESO: `scope_*` (E-3) · `provenance` + `migrated_*` (E-7) · topology refs ở
[`25.memory-topology-ref`](25.memory-topology-ref.md) (E-2).

## 2. `isLatest` là **view**, không phải cột

```sql
CREATE VIEW memory_latest WITH (security_invoker = true) AS
SELECT r.*, true AS is_latest
FROM memory_record r
WHERE r.version = (
  SELECT max(m.version) FROM memory_record m
  WHERE m.project = r.project AND m.memory_id = r.memory_id
);
```

**Vì sao không có cột `is_latest`:** ghi một version mới mà đặt `is_latest` thì phải `UPDATE` dòng cũ — đúng thứ `BR-06`
cấm, và `AC-MEM-01-05` trả `APPEND_ONLY`. Hai lệnh ghi cho một lần save còn tạo trạng thái *hai latest* (hoặc **không**
latest) nếu tiến trình chết giữa hai lệnh; view không có trạng thái trung gian.

**Version mới nhất là duy nhất** vì `(project, memory_id, version)` là khoá chính; `max(version)` trả đúng một dòng.
Đây là thứ `AC-MEM-01-04` kiểm (`version` mới · bản cũ còn · `isLatest` đúng) và `AC-MEM-02-05` kiểm (*one latest*).

`security_invoker = true` (PG ≥ 15) để view **không** chạy bằng quyền chủ bảng rồi bỏ qua RLS — xem `OPEN-MEM-03`.

## 3. Vì sao mảng `text[]`, không `jsonb`

`concepts` · `files` · `session_ids` đều là **điều kiện lọc** (recall theo concept, theo file, theo phiên) — luật §5 của
[`02.schema`](02.schema.md) cấm đặt phần lọc trong `jsonb`. `text[]` + GIN cho `concepts @> ARRAY['order.created']` là
index scan, và vẫn đọc được bằng `psql` mà không cần hàm JSON.

`scope_kind`/`scope_value` là **cột**, không suy từ `files[0]`: trên microservices hai service khác repo, không share path
nào, nhưng gắn qua một routing key ([`E-3`](../../05.requirements/03.eso-memory.md)). Suy scope từ path là **đoán**.

## 4. Chỉ ghi thêm (append-only)

| Luật | Cưỡng chế |
|---|---|
| Sửa = **version mới**, không `UPDATE` | khoá chính `(project, memory_id, version)`; ghi qua hàm `save` |
| Không xoá | `REVOKE UPDATE, DELETE, TRUNCATE ON memory_record FROM eso_app` |
| Tầng DB không tin tầng ứng dụng | trigger `BEFORE UPDATE OR DELETE` → `RAISE ABORT 'APPEND_ONLY'` |

```sql
CREATE TRIGGER trg_memory_record_append_only
BEFORE UPDATE OR DELETE ON memory_record
FOR EACH ROW EXECUTE FUNCTION raise_append_only();   -- RAISE ABORT 'APPEND_ONLY'
```

**Version kế tiếp** giữ `created_at` của version 1 và đặt `updated_at = now()`; `memory_id` không đổi. **Consolidation**
short → long (`AC-MEM-02-02`) là **version mới** với `tier='long'`, không phải `UPDATE` — nên lịch sử tier đọc lại được.

**Decay tính lúc đọc**, không lưu: `strength_effective = strength × exp(−λ · (now − updated_at))`. Ghi `strength` đã
decay là tạo áp lực `UPDATE` lên bảng append-only, và mỗi lần đọc lại ra một số khác nhau mà DB không đổi.

**Idempotency / conflict** (`AC-MEM-02-05`): ghi đúng `(memory_id, version)` đã có — nếu `content_hash` **bằng** ⇒ no-op
idempotent, trả dòng cũ; nếu **khác** ⇒ `CONFLICT` (unique violation `23505`), **không** ghi đè.

## 5. Cô lập project (RLS)

```sql
ALTER TABLE memory_record ENABLE ROW LEVEL SECURITY;
ALTER TABLE memory_record FORCE ROW LEVEL SECURITY;       -- chủ bảng cũng bị luật

CREATE POLICY memory_project_only ON memory_record
  USING      (project = current_setting('eso.project', true))
  WITH CHECK (project = current_setting('eso.project', true));
```

`WITH CHECK` là phần chặn **ghi** — thiếu nó thì `INSERT` project khác vẫn lọt rồi **vô hình** với chính người vừa ghi
([`02.schema` §4](02.schema.md)). `FORCE` để test RLS chạy dưới role migration không xanh giả.
Thiếu `eso.project` ⇒ **0 dòng**, không phải toàn bộ. `project` **không** đến từ client (`API-1` kiểm bằng credential).

## 6. Index

| Index | Cho truy vấn |
|---|---|
| `(project, memory_id, version DESC)` | bản mới nhất của một fact |
| `(project, memory_type, updated_at DESC)` | *"decision gần đây"* — typed recall |
| `(project, scope_kind, scope_value)` | không trộn fact của service khác (E-3) |
| `(project, strength DESC, updated_at DESC)` | xếp hạng `hit` / `weak` (E-5) |
| `gin (concepts)` · `gin (files)` · `gin (session_ids)` | recall theo concept · file · phiên |

## 7. Migration

1. Tạo `memory_record` **trước** [`memory_topology-ref`](25.memory-topology-ref.md) (bảng con có FK về đây).
2. Bật RLS + `REVOKE` + trigger **trong cùng migration** — bật sau là có một cửa sổ ghi được bằng role ứng dụng.
3. Không backfill: trước file này **chưa có** bảng memory nào (`02.schema` §2 từng ghi *"`memory_fact` không tồn tại"*).
   Dữ liệu agentmemory cũ đi qua `migrated_from`/`migrated_at` (`AC-MEM-03-01`), không qua `INSERT` tay.
4. `graph` drop/rebuild **không** chạm bảng này ([`D-73`](../../03.inception/02.decision-log/06.architecture-va-data.md)).

## Luật sửa

File này **sai** khi:

1. DDL ở đây khác DDL chạy thật — file là bản đọc được của schema, không phải nguồn song song;
2. [`01.entities`](01.entities.md) mô tả `memory_record` khác file này;
3. `03.api` có endpoint ghi vào `memory_record` mà file này không nêu;
4. một `CHECK` hoặc `FK` bị bỏ mà không có quyết định — mỗi cái đang thay cho một `if` trong code.
