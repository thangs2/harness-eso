# C4 L2 — Container: process · data store · deployable

> **Một mức:** chỉ L2. Component ở [`03.component.md`](03.component.md).
> **Chỉ cấu trúc:** không sequence, không luồng.

## 1. Năm container

| ID | Container | Công nghệ | Chạy ở đâu | Vì sao **tách** (không phải thư viện) |
|---|---|---|---|---|
| **C1** | **Adapter** | JS/ESM | **trong process của host** | phải ở trong host mới thấy được turn và inject được rule |
| **C2** | **Control Plane API** | Node/ESM · HTTP | process riêng, **cùng máy** (`D-20`) | giữ DB + sống ngoài vòng đời host; host tắt vẫn còn |
| **C3** | **Control Plane UI** | React/TS (static) | do C2 phục vụ | phục vụ A-01 · A-08 |
| **C4** | **Postgres** | Postgres (docker) | cùng máy | một DB, partition theo project, RLS (`D-22`) |
| **C5** | **Graph Extractor** | .NET (Roslyn) | process con, **theo yêu cầu** | cần compiler .NET; chạy nặng nên **ngoài** đường turn |

**C5 tách khỏi C1 vì hai lý do khác nhau:** ngôn ngữ khác (D-36), **và** nó nặng — build graph không được nằm trên đường
turn ([`D-22`](../../../03.inception/02.decision-log/00.index.md)).

## 3. Chỗ **chia cắt** quan trọng nhất: cục bộ hay từ xa

Đây là quyết định L2 lớn nhất, và nó bị **ép** bởi hai ràng buộc: đường turn phải nhanh, và control plane có thể **không
sẵn**.

| Việc | Ở **C1** (cục bộ) | Ở **C2** (từ xa) | Vì sao |
|---|---|---|---|
| đọc file project · git | ✅ | ❌ | phải cục bộ; và không gửi nội dung project ra ngoài |
| phân giải **3 vùng skill** | ✅ (file **là** nguồn) | — | `pool`/`shared`/`project` là file trong repo |
| **judgement** (level · basis · mode) | ✅ | ❌ | trên đường turn; không chờ mạng |
| **ghi evidence** | ✅ vào **outbox** | ✅ ingest | bất biến: **ghi trước, ship sau** (`D-20`) |
| **khai báo** (ai · quyền · policy) | cache **đọc** | ✅ **nguồn** | declaration là SoT ở control plane (`D-23`) |
| **diagnosis** | ❌ | ✅ | tính từ log, không phải việc của turn |
| **sync file ↔ DB** | một nửa (khi `provision.sh`) | một nửa (khi lưu UI) | hai cửa vào, một đường ghi (`D-17`, `D-24`) |
| **đọc lại bản ghi evidence** | ❌ **mặc định** | chỉ khi khai báo cho phép **loại + TTL** | bản ghi là **output**, không phải **input** ([`D-46`](../../../03.inception/02.decision-log/00.index.md)) |

**Hệ quả phải nói ra:** C1 cần **cache** khai báo. Và khi control plane **không sẵn**, C1 vẫn phán được với cache — nhưng mức
bảo đảm **bị hạ** và phải **nói ra** (`REQ-HOST-02`). Đây là chỗ "gắn vào, không thay thế" trở thành ràng buộc kỹ thuật, không
phải khẩu hiệu.

## 4. Giao thức giữa container

| Cặp | Giao thức | Đồng bộ? |
|---|---|---|
| C1 → C2 | HTTP/JSON | **không** cho evidence (outbox) · **có** cho khai báo |
| C1 → C5 | spawn + stdio | **có** (nhưng ngoài đường turn) |
| C2 → C4 | SQL | có |
| C2 → C3 | HTTP static | có |
| C1 → A-07 | filesystem + git | có |

**Không** có giao thức nào giữa C1 và C3: UI **không** nói chuyện trực tiếp với adapter. Nếu cần, đi qua C2 — nếu không thì
ta có hai đường ghi.

## 5. Một deployment, nhiều project

| | |
|---|---|
| **Một** C2 + **một** C4 cho **nhiều** project | `D-21` |
| Cô lập | **RLS** theo `project` + `visibility` **tính** ở tầng ứng dụng (`D-45`), không chỉ ở DB |
| Một project **không** có control plane riêng | `D-21` loại bỏ observatory theo consumer |

⇒ Hệ quả: **C1 phải biết mình thuộc project nào**, và không được tin giá trị đó từ client. Nó lấy từ file cấu hình
project (`harness.profile.json`) — tức từ một thứ **A-01 khai**.
