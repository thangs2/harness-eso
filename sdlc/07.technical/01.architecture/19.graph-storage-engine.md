# `19` — Graph storage engine: Postgres, SQLite, hay Neo4j?

> **Trạng thái:** `DECIDED` — **D-92**: **Postgres only**, không SQLite runtime, không Neo4j.
> `D-22`/`D-73` vẫn giữ; D-92 thay phần graph engine của D-22. `D-93` mở rộng **no SQLite** ra toàn ESO product.

## 1. Câu hỏi

Cho **MVP** (monolith C#, single consumer) và **doc-graph** (specific-relative), engine nào đúng?

- SQLite có đủ cho doc-graph MVP không?
- Nếu mỗi consumer có SQLite file riêng thì có giải quyết "nhiều service cùng DB" không?
- Code-graph tương lai microservices có cần Neo4j không?

## 2. Ba lớp kiểm tra — không gộp

| Lớp | Câu hỏi | Kết luận |
|---|---|---|
| **Khả năng dữ liệu** | engine có lưu/query được node, edge, provenance, version, coverage? | SQLite **được một phần**; Postgres đủ |
| **Cô lập & đồng thời** | nhiều host/agent cùng ghi một SoT? RLS/role? | SQLite **không**; Postgres có |
| **Vận hành & scale** | backup, migration, index, query planner, nhiều service | SQLite **không**; Postgres có |

**Điểm quyết định không phải "SQLite có recursive CTE không".** SQLite có. Điểm quyết định là **D-90: một SoT dùng chung cho nhiều host** — SQLite file là file local/single-writer, không phải SoT nhiều host.

## 3. Doc-graph: SQLite làm được gì?

Doc-graph theo `D-89`/`D-90` là **specific-relative**, không phải semantic search:

```text
doc --specifies--> method
doc --constrains--> service
doc --derived_from--> doc
doc --supersedes--> doc
doc --anchored_to--> file/symbol/route
```

| Chức năng | SQLite | Ghi chú |
|---|---|---|
| `graph_node` · `graph_edge` · typed relation | ✅ | bảng + FK + index |
| traversal 1–3 tầng bằng `WITH RECURSIVE` | ✅ | có depth cap |
| provenance `source_claim` append-only | ✅ | trigger SQLite |
| version/`supersedes`/`as_of` | ✅ | cột + query |
| JSON metadata | ✅ | JSON1 |
| full-text title/content | ✅ | FTS5 |
| coverage/completeness | ✅ | bảng + aggregate |
| project isolation | 🟡 | **app-level filter**, không RLS |
| role/permission DB | ❌ | không có role như Postgres |
| nhiều writer cùng lúc | ❌ | single-writer; WAL chỉ giúp readers |
| nhiều host cùng SoT | ❌ | file local/lock; không phải shared store |
| query planner graph lớn | 🟡 | kém hơn; một process |
| extension (`pg_trgm`, `pgvector`, `ltree`) | ❌/🟡 | không chuẩn; phải cài riêng |
| backup/PITR/observability | 🟡 | file copy; không chuẩn vận hành |

**Kết luận doc-graph:** SQLite *về kỹ thuật* cover được bảng/edge/traversal/FTS/JSON ở single-host, nhưng **D-92/D-93 loại SQLite**; không dùng cho MVP. Nó không đủ cho multi-host, RLS, concurrent rebuild, shared SoT.

## 4. "Mỗi consumer một SQLite riêng" — có giải quyết không?

Nó giải quyết **trộn dữ liệu giữa các consumer**, nhưng đổi topology:

| | Được | Mất |
|---|---|---|
| **SQLite/consumer** | cô lập file; không cần server; offline | không portable nhiều host (`D-90`); backup/migration từng file; không query cross-consumer; không RLS thật |
| **Postgres/consumer** | cùng engine; RLS; nhiều host; backup/migration một chuẩn | cần container/DB cho mỗi consumer |

**Đã chốt 2026-11-08 — `D-105`:** nếu mục tiêu chỉ là **không trộn consumer**, dùng **một database + `project` + RLS** (predicate `project` bắt buộc); database riêng chỉ khi cần tách vật lý. Nó giữ được `D-73`/`D-90` và không tạo engine thứ hai.

Nếu có **Lite/offline mode**, đó là **D mới**; không dùng SQLite trong graph theo D-92.

## 5. Code-graph: Postgres hay Neo4j?

`D-92` đã chốt:

- **Postgres only** — method-level 10⁵–10⁶ node/edge; `WITH RECURSIVE` có **trần độ sâu 1–3**; index `(src)`, `(dst)`, `(src,kind)`; query nặng off-path.
- **Không Neo4j** hiện tại hoặc tương lai. Nếu workload vượt Postgres, phải mở **D mới + benchmark**; không tự chuyển.
- Mô hình `node · edge · kind · provenance · completeness` phải **độc lập engine**; Postgres là engine duy nhất.

**Không dùng Neo4j** vì:

- thêm store thứ hai, sync/dual-write, backup, Cypher, vận hành;
- MVP monolith không có traversal vô hạn;
- D-92 đã loại, không có điều kiện mở.

Nếu microservices vẫn chỉ cần blast radius 1–3 hop, **Postgres vẫn đủ**. Neo4j là quyết định theo **workload**, không theo danh từ "microservices".

## 6. Quyết định

1. **Graph runtime = Postgres `graph`** cho cả code graph + docs graph.
2. **Không SQLite ở bất kỳ đâu trong graph** — runtime, demo, acceptance, unit test; test dùng Postgres isolated.
3. **Không Neo4j** hiện tại hoặc tương lai; nếu vượt Postgres, mở D mới + benchmark, không tự chuyển.
4. **Per-consumer isolation = Postgres riêng** (DB/instance/schema), không phải SQLite file.
5. `ESO-447` CRITICAL; graph BIP `2.6–2.9` phải `READY-SPLIT` với `OPEN-GRAPH-SCHEMA-02` blocking.
