## 3. Business binding

| | |
|---|---|
| **Input** | consumer id (từ `provision.sh`/`harness.config.json`) · connection string do **profile page** khai lúc init |
| **Xử lý** | resolve consumer → đọc/nhận connection string → bảo đảm database + schema + migration → đăng ký `project` → ghi `storage.graph` |
| **Output** | `storage.graph = {host, port, database, schema, ssl, isolation}` trong `harness.config.json`; secret ở `.harness/` (gitignored) |
| **Không làm** | không tạo DB mới khi `isolation: "shared"` (mặc định); không ghi mật khẩu vào config; không đoán DB từ env |

## 4. Contract & transaction

1. `provision.sh <consumer> --plan` — **read-only**: in `storage.graph` dự định ghi, **không** mở kết nối DB, **không** ghi file.
2. `provision.sh <consumer>` — apply: mở kết nối **một lần** cho cả bước schema + register (không để cửa sổ nửa vời); lỗi ⇒ dừng, không ghi config.
3. `be-demo.sh --consumer=<id>` — chỉ đọc `harness.config.json` của consumer; thiếu block hoặc thiếu secret ⇒ exit ≠ 0 kèm `./provision.sh <id>`.
4. `verify-consumer.sh` — assert `SELECT 1` + schema version khớp; `--plan` không ghi.

## 5. Data & persistence

- Bảng/DDL: theo `26.graph-schema.md` (`graph_node` · `graph_edge` · `source_claim` · `completeness`), RLS `ENABLE` + **`FORCE`**, `REVOKE UPDATE/DELETE` + trigger append-only.
- Ghi một dòng đăng ký `project` (idempotent theo `project`).
- **Không** bảng mới ở slice này; chỉ bảo đảm DDL đã có chạy được trên DB thật.

## 6. Invariants

- `INV-KB-01`/`BR-14`: một `project` một chủ — không ảnh hưởng.
