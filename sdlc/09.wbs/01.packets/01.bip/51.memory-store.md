## 3. Business binding

| `BR` | Câu | Vì sao ràng buộc slice này |
|---|---|---|
| **`BR-05`** | **`unknown` ≠ `absent`** | `recall` trả **ba** trạng thái `hit`/`weak`/`miss`; gộp `weak` vào `miss` là nói *"không có"* khi thực ra *"có nhưng yếu"* (`AC-MEM-02-03`) |
| **`BR-06`** | Record chỉ ghi thêm | Consolidation short→long và đổi `strength` là **version mới**, không `UPDATE` — lịch sử tier đọc lại được (`AC-MEM-02-02`) |
| **`BR-01`** | Cùng câu hỏi ⇒ cùng phán quyết | Hai lần `recall` cùng input + cùng store ⇒ cùng kết quả; `order by` không xác định là bug |
| **`BR-12`** | Cô lập project | `recall` không trộn fact của project khác |

## 4. Contract & transaction

| | |
|---|---|
| endpoints | `API-36` `POST /v1/memory:save` · `API-38` `POST /v1/memory:recall` |
| vào | `save`: record + `version`; `recall`: tiêu chí (concept/file/scope) + `limit` |
| ra | `save`: record + `version`; `recall`: snippet + `provenance` + trạng thái `hit`/`weak`/`miss`; traversal trả **đường đi** |
| lỗi đã đăng ký | `CONFLICT` (409, cùng khoá khác nội dung) · `OUT_OF_SCOPE` (403) |
| **must not change** | `API-1`–`API-35`, `API-37`; `evidence_*`; graph schema |

## 5. Data & persistence

Không thêm bảng. Đọc/ghi qua `memory_record` (append-only) và `memory_topology_ref` (traversal: index `(project, node_id)`).

| Hành vi | Cách cài trên schema đã có |
|---|---|
| `fetch` theo id | view `memory_latest` (một dòng/`memory_id`) |
| `hit`/`weak`/`miss` | `strength_effective = strength × exp(−λ·(now − updated_at))` **tính lúc đọc**; sàn phân biệt `hit`/`weak` là `OPEN-API-MEM-02` (giá trị, không phải cột) |
| consolidation short→long | ghi **version mới** với `tier='long'`; không `UPDATE` |
| traversal | join `memory_topology_ref` theo `(project, node_id)` — cùng database `ctx` |

| `AC` | type | kiểm bằng | RED trước / GREEN sau |
