# 02 — Gates: marks, statuses, and how blocking works

**Standard:** [`00.index.md`](./00.index.md) `L2` · **Type:** `standard`

> A gate has no "nearly there". One wrong box ⇒ **stop**. That is `L2`, and it is the most violated rule because "probably enough"
> always sounds reasonable.

## 1. Four **marks** — how complete one plane is

| Mark | Meaning | Counts as complete? |
|---|---|---|
| **`OK`** | this plane is **complete** for the slice | ✅ |
| **`P`** | **partial** — missing, but **the gap is named** + has an `OPEN` id | ✅ if the gap has an `open_id` |
| **`OUT`** | **not part of** this increment/wave | ✅ (the `OUT` decision must be recorded) |
| **`—`** | **no artifact at all** | ❌ |

**`OUT` replaced an undefined `N/A`.** `N/A` was used in eleven places and defined nowhere; a mark with no definition is an opinion.
`OUT` now means **not applicable, reason required** — and an `OUT` with no reason counts as `—`.

**`P` ≠ `—`** is the most important thing in this table:

| If only OK / not-OK exists | Reality |
|---|---|
| "not started" and "started, with a note" get **merged** | progress **lies**, and nobody knows which needs work |

## 2. Five **statuses** — for one artifact or one slice

| Status | Meaning | Who may set it |
|---|---|---|
| `DRAFT` | being written | anyone |
| `OPEN` | has unanswered questions, **recorded in the register** | the author |
| **`READY`** | **complete** for the next step | author + **gate** check |
| **`READY-SPLIT`** | one part complete, the rest **held by name** | author + gate |
| **`BLOCKED`** | incomplete **and cannot proceed** | the gate, **owner required** |

### `READY-SPLIT` — the status ESO needs most

BAP uses it when the HTTP contract is missing but domain/persistence is verified: do the available part, **hold** the rest.

ESO uses the same shape, with real examples:

| Complete | Held |
|---|---|
| judgement + evidence (logic) | **interface** not designed |
| AC + scenarios | **data schema** not settled |

⇒ Without `READY-SPLIT`, **one** unfinished part blocks the **whole** slice — and every slice is "not done" until everything is.

### `BLOCKED` **must** carry an owner

| No owner | Consequence |
|---|---|
| a `BLOCKED` slice | **nobody clears it**; it sits there, and everything depending on it stalls |

**Rule:** `BLOCKED` without an `owner` + `open_id` is **invalid** and counts as `—`.

## 3. Pre-flight — checked **in order**, one wrong box stops the line

> The **stage transition table** (1→2 … 8→9: what evidence, who approves) lives in
> [`01.sdlc-delivery-lifecycle-standard`](../04.quality-gate/01.sdlc-delivery-lifecycle-standard.md) §3 — **not** copied here.

Before a slice enters active work, walk the **9 stages** of [`01`](../04.quality-gate/01.sdlc-delivery-lifecycle-standard.md). Each
stage records:

| Column | Content |
|---|---|
| stage | 1…9 |
| owner | A-01…A-04 |
| **evidence** | a **file path** in the repo — never "checked" |
| **criteria** | the tick list |
| **status** | `OK` · `P` · `OUT` · `—` |

**Three escalation modes** (from BAP, renamed to their real meaning):

| Mode | Condition | Action |
|---|---|---|
| **Warning** | one box **wrong** | slice **must not** enter active work |
| **Split** | interface/data missing, logic verified | `READY-SPLIT` — do the available part, hold the rest **by name** |
| **Stop** | invariants · schema · isolation **undetermined** | `BLOCKED` **with an owner** in the register |

## 4. The `OPEN` register — the only home for unanswered questions

| Column | Why |
|---|---|
| `open_id` | so it can be **cited** elsewhere |
| the question | what is unknown |
| **impact** | which file/table/AC it touches |
| **owner** | who answers |
| **closure source** | what closes it (a document, a decision) |
| **blocks** | which `US`/`AC`/slice it blocks |

**Rule:** an `OPEN` not in the register **does not exist**. An unanswered question that is not recorded gets **forgotten** — or worse,
**assumed**.

## 5. Falsification

1. **Using `P` for "not started".** ⇒ `—` disappears and progress becomes meaningless.
2. **`BLOCKED` with no owner.** ⇒ nobody clears it; treat as `—`.
3. **A gate that "partly passes".** ⇒ `L2` is gone and every later gate is ceremonial.
4. **`OPEN` not in the register.** ⇒ it gets assumed at the next reading.
