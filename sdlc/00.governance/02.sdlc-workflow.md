## 1. The canonical pipeline — **8 stages**, each a document gate

```text
1 Requirements (BRD/FRD/SRS) → 2 Analysis (US+AC) → 3 QC (Scenario Matrix)
  → 4 Interface (App contracts + HTTP) → 5 Data (ERD + DDL + persistence verify)
    → 6 Architecture/WBS (BIP) → 7 Test Spec (RED packets) → 8 TDD (RED→GREEN)
```

| # | Stage | Owner | Main output | Gate law |
|---|---|---|---|---|
| 1 | Requirements | PM/BA | BRD · FRD · SRS (**sharded**) | IDs bound to SoT; in/out scope explicit; **no vague statements** |
| 2 | Analysis | BA | US + AC **Given/When/Then** | each AC **testable by one test**; traceable to a requirement ID |
| 3 | QC | QC | **Scenario Matrix** | **1:1 AC ↔ scenario**; happy + boundary + negative; tenant + RBAC |
| 4 | Interface | Arch/BE | app service contracts + HTTP specs | in-process vs HTTP separated; DTOs + status codes; unfinalised ⇒ `OPEN`, **never invented** |
| 5 | Data | BE | logical ERD + Postgres DDL + **persistence verification** | **zero drift** ERD ↔ SQL ↔ DbContext; tenant filters mapped |
| 6 | **BIP** | BE Lead | **Backend Implementation Packet** | **planes A–E** + invariants F–P (UoW · concurrency · errors); certified `READY` / `READY-SPLIT` |
| 7 | Test Spec | DEV/QC | **RED test packets** | names the **exact class + test file**; concrete expected failure (**true RED**) |
| 8 | TDD | DEV | tests + code | RED → GREEN; coverage **≥80%** on touched code; 0 anti-patterns |

**Its strongest property:** each stage **consumes** the previous stage's output **by direct reference**, and *"inventing unverified
contracts is strictly forbidden"*. No stage may invent a contract.

## 2. Four **delivery planes** — an increment does not run in one pass

| Plane | From → to | Who signs |
|---|---|---|
| **A** · preparation | intake A–H → stages **1–6** → slice Leader GO → Jira `Ready` | Lead + human (on large scope) |
| **B** · dev | RED → implement → verify → **agent HIL** → pod DEV Done | agent → human |
| **B′** · QC | G-QC PASS → qc-runtime → QC HIL → pod QC Done | agent → human |
| **C** · ship | DoD · review · release → **Story Done** | **human only** |

And one separating rule: *"Session phases in one chat ≠ Plane A"* — **a chat session is not a plane**. Do not confuse *which stage I am
in* with *which conversation I am in*.

## 3. Three document kinds — and where each lives

This is what the operator asked for, and baplatform **already separates them**:

| Kind | Where | Role | Reader |
|---|---|---|---|
| **HUMAN** | `sdlc/01..12` (BRD, US, AC, ERD, WBS…) | full source of truth, with diagrams and reasons | people |
| **AI** | `sdlc/00.agent-manifests/` + governance routers | **router** ≤ 40 lines, **pointing at** HUMAN, never copying | agents |
| **JIRA** | Jira + `scripts/jira-*.sh` | **live execution SoT**; markdown synced **on demand** | both |

**Rule:** *"Jira MCP is the live execution SoT; only sync `00.jira/` or WBS `[HIL]` when explicitly asked"* — Jira is not copied into
markdown on every change.

**And each kind has a stated token budget:** agent specs `< 300 tokens/file`, the wave router `< 200 tokens` to resolve the whole
hierarchy.

## 4. C4 in the architecture — a **folder ladder**, not one file

baplatform's `04.architecture/` is split **by C4 level**, not by module:

| Folder | Level | Content |
|---|---|---|
| `01.landscape` | L0/L1 | broad context |
| `02.context` | **C4 L1** | system ↔ external actors |
| `03.container` | **C4 L2** | processes/data stores/deployables |
| `04.component` | **C4 L3** | components inside a container |
| `11.code` | **C4 L4** | real classes/modules |
| `05.api` · `06.data-model` · `07.workflows` | supporting | HTTP contracts · ERD · flows |
| `00.decisions` · `00.governance` · `00.target` | law | ADR · diagram standards · target |

**Their rule:** *"C4 = **static structure only**. Flows, activity, sequence, ERD, user journeys live in **other phases**."* Putting flows
into C4 is what makes a diagram useless.

## 5. After planning: **`00.context-contract.json`**

Location: `sdlc/00.governance/00.context-contract.json`. It maps **module → paths · invariants · lawAnchors · agent spec**. It is a
**declared map** that every other router points into — so it comes **after** the domains and code paths are known.

## 6. Checklists — two layers, never confused

| Layer | File | Role |
|---|---|---|
| **Governance** | `02.feature-increment-bootstrap-checklist.md` | **how to run**: planes, order, ticks, agent stop-lines |
| **Quality gate** | `03.quality-gate/02.pre-flight-readiness-checklist.md` | **evidence** of each stage PASS/FAIL |

**Their rule:** *"Do not duplicate artifact min-content here"* — a checklist **cites**, never copies. And `BIP READY` is a **document
gate**, **not** a Jira status.

## 7. Applied to ESO — the abbreviated pipeline and the operator's order

The operator set: **discovery → charter → planning/WBS → `00.context-contract.json`**.

| Phase | Which BAP stage | ESO output |
|---|---|---|
| **Discovery** | before Stage 1 (≈ `03.intake`) | problem · actors · context · constraints — **not yet** requirements |
| **Charter** | between discovery and planning | scope · goals · constraints · stakeholders |
| **Planning** | Stages 1–5 | requirements · US+AC · scenarios · interface · data |
| **WBS** | Stage 6 + `08.wbs` | Epic/Story/Task + **BIP/FIP** per slice |
| **Context contract** | after planning | `00.context-contract.json` |

**What ESO keeps from BAP:** the hard stage order · testable AC · `1:1 AC↔scenario` · `OPEN` instead of invention · BIP/FIP as document
gates · C4 static-only · the three document kinds · two-layer checklists.

**What ESO must change:**

| BAP | ESO |
|---|---|
| Modules `M01–M16` from `docs/releases/v1.9-final` | **six product domains** ([manifest](../00.agent-manifests/README.md)) — no release SoT yet, it must be created |
| ABP / .NET / EF | control plane on Postgres + a Roslyn sidecar; **no ABP** |
| Penpot / UI journeys | control-plane UI (React) — not designed yet |
| Stage 5 requires Postgres DDL + DbContext | ESO has Postgres but **no schema yet** — must be built |

**What ESO must add that BAP does not have:** C4 for the **control plane itself**, and **BIP/FIP for ESO slices** — BAP's templates
cannot be borrowed because the stack differs.

## 8. Questions that **must** be settled before running discovery

1. **What is a "charter"?** Read as project charter: scope · goals · constraints · stakeholders. A different meaning shifts the whole
   phase.
2. **Is there a `docs/releases/<version>` module SoT?** BAP has `v1.9-final`; ESO has none — and Stage 1 needs it to bind IDs.
3. **Who holds BA / QC?** BAP separates PM/BA/QC/Arch/DEV. ESO has **one** human plus agents. If roles merge, the **gates that lose
   independence** must be stated.
