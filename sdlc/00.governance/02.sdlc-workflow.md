**Trạng thái:** `DRAFT` để duyệt · 2026-10-25 · **Loại:** governance · **Đo từ:** baplatform `sdlc/00.governance/`

## 1. Pipeline chuẩn — **8 stage**, mỗi stage một cổng tài liệu

```text
1 Requirements (BRD/FRD/SRS) → 2 Analysis (US+AC) → 3 QC (Scenario Matrix)
  → 4 Interface (App contracts + HTTP) → 5 Data (ERD + DDL + persistence verify)
    → 6 Architecture/WBS (BIP) → 7 Test Spec (RED packets) → 8 TDD (RED→GREEN)
```

| # | Stage | Chủ | Output chính | Luật cổng |
|---|---|---|---|---|
| 1 | Requirements | PM/BA | BRD · FRD · SRS (**sharded**) | ID gắn SoT; in/out scope rõ; **không câu mơ hồ** |
| 2 | Analysis | BA | US + AC **Given/When/Then** | mỗi AC **test được bằng một test**; truy được về requirement ID |
| 3 | QC | QC | **Scenario Matrix** hợp nhất | **1:1 AC ↔ scenario**; happy + boundary + negative; tenant + RBAC |
| 4 | Interface | Arch/BE | App service contracts + HTTP specs | tách in-process vs HTTP; DTO + status code; chưa chốt ⇒ `OPEN`, **không bịa** |
| 5 | Data | BE | ERD logic + DDL Postgres + **persistence verification** | **zero drift** ERD ↔ SQL ↔ DbContext; filter tenant được map |
| 6 | **BIP** | BE Lead | **Backend Implementation Packet** | đủ **plane A–E** + invariant F–P (UoW · concurrency · errors); ký `READY`/`READY-SPLIT` |
| 7 | Test Spec | DEV/QC | **RED test packets** | nêu **đúng class + file test**; expected failure cụ thể (**RED thật**) |
| 8 | TDD | DEV | test + code | RED → GREEN; coverage **≥80%** trên code chạm; 0 anti-pattern |

**Điểm mạnh nhất của pipeline này:** mỗi stage **tiêu thụ** output stage trước **bằng tham chiếu trực tiếp**, và
*"inventing unverified contracts is strictly forbidden"*. Không stage nào được tự nghĩ ra hợp đồng.

## 2. Bốn **Delivery Plane** — vì một increment không chạy một mạch

| Plane | Từ → đến | Ai ký |
|---|---|---|
| **A** · chuẩn bị | intake A–H → stage **1–6** → slice Leader GO → Jira `Ready` | Lead + người (khi scope lớn) |
| **B** · dev | RED → implement → verify → **agent HIL** → pod DEV Done | agent → người |
| **B′** · QC | G-QC PASS → qc-runtime → QC HIL → pod QC Done | agent → người |
| **C** · ship | DoD · review · release → **Story Done** | **chỉ người** |

Và một luật tách bạch: *"Session phases in one chat ≠ Plane A"* — **phiên chat không phải một plane**. Không được lẫn
việc "đang ở stage nào" với "đang chat trong phiên nào".

## 3. Ba loại tài liệu — và chỗ của mỗi loại

Đây là thứ operator yêu cầu, và baplatform **đã tách sẵn**:

| Loại | Ở đâu | Vai | Ai đọc |
|---|---|---|---|
| **HUMAN** | `sdlc/01..12` (BRD, US, AC, ERD, WBS…) | SoT đầy đủ, có Mermaid, có lý do | người |
| **AI** | `sdlc/00.agent-manifests/` + `00.governance/*router*` | **router** ≤ 40 dòng, trỏ về HUMAN, **không chép** | agent |
| **JIRA** | Jira + `scripts/jira-*.sh` | **live execution SoT**; markdown sync **on-demand** | cả hai |

**Luật:** *"Jira MCP is the live execution SoT; only sync `00.jira/` or WBS `[HIL]` when explicitly asked"*. Nghĩa là
Jira **không** bị chép vào markdown mỗi lần đổi — chỉ đồng bộ khi được yêu cầu.

**Và mỗi loại có ngân sách token viết ra:** agent spec `< 300 tokens/file`, wave router `< 200 tokens` để phân giải cả
hierarchy.

## 7. Áp cho ESO — pipeline rút gọn và thứ tự của operator

Operator đặt: **discovery → chapter → planning-wbs → `00.context-contract.json`**.

| Phase | Là stage nào của BAP | Output ESO |
|---|---|---|
| **Discovery** | trước Stage 1 (≈ `03.intake`) | vấn đề · actor · bối cảnh · ràng buộc — **chưa** phải yêu cầu |
| **Chapter** *(?)* | giữa discovery và planning | xem §8 |
| **Planning** | Stage 1–5 | requirements · US+AC · scenario · interface · data |
| **WBS** | Stage 6 + `08.wbs` | Epic/Story/Task + **BIP/FIP** mỗi slice |
| **Context contract** | sau planning | `00.context-contract.json` |

**Cái ESO giữ nguyên từ BAP:** thứ tự stage cứng · AC test được · `1:1 AC↔scenario` · `OPEN` thay vì bịa · BIP/FIP là
cổng tài liệu · C4 static-only · ba loại tài liệu · checklist hai tầng.

**Cái ESO phải đổi:**

| BAP | ESO |
|---|---|
| Module `M01–M16` từ `docs/releases/v1.9-final` | **6 miền sản phẩm** ([manifest](../00.agent-manifests/README.md)) — chưa có SoT release, phải tạo |
| ABP / .NET / EF | control plane Postgres + sidecar Roslyn; **không** ABP |
| Penpot / UI journey | UI control plane (React) — chưa có thiết kế |
| Stage 5 yêu cầu DDL Postgres + DbContext | ESO có Postgres nhưng **chưa có schema** — phải làm |

**Cái ESO phải thêm mà BAP không có:** C4 cho **chính control plane** (BAP làm C4 cho sản phẩm của họ; ESO phải làm C4
cho sản phẩm của mình), và **BIP/FIP cho slice của ESO** — không mượn được template BAP vì stack khác.

## 8. Câu hỏi **phải** chốt trước khi chạy discovery

1. **"Chapter" là gì?** Tôi đọc là **charter** (hiến chương dự án: scope · mục tiêu · ràng buộc · stakeholder). Nếu
   nghĩa khác thì cả phase này lệch.
2. **Có `docs/releases/<version>` làm SoT module không?** BAP có `v1.9-final`; ESO **chưa có** — và Stage 1 cần nó để
   gắn ID.
3. **Ai giữ vai BA / QC?** BAP tách PM/BA/QC/Arch/DEV. Ở ESO hiện có **một** người (operator) + agent. Nếu gộp vai thì
   phải nói rõ **cổng nào mất tính độc lập**.
