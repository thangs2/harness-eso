# Source of truth

## 1. Everything has exactly one home

| Thing | SoT | Who edits | Nature |
|---|---|---|---|
| **What v1 is, how it runs** *(prior art)* | `documents/` | edit when **v1** changes | describes **v1**, NOT the product |
| **Where we are going**, and why | `sdlc/01.inception/` | edit when a **decision** changes | direction, carries status |
| What it must **be able to do** | `sdlc/02.requirements/` | edit when requirements change | verifiable statements |
| Technical model | `sdlc/04.architecture/` | edit when a **seam** changes | axes, providers, graph |
| Work to be done | `sdlc/08.wbs/` | live, updated per slice | the **only** WBS |
| What is **broken** | `documents/05.development/03.open-issues.md` | edit on discovery/fix | current state |
| Invariants | `documents/05.development/02.invariants.md` | rare, each with a defect | technical law |
| Identified defects | `documents/05.development/09.gate-defect-register.md` | add `G-nn` on discovery | evidence |

## 2. How to cite

- A statement about **current code** ⇒ cite `packages/...` or a test. Never cite `sdlc/` for current state.
- A statement about **plan** ⇒ cite `sdlc/` — and it must **not** be presented as existing.
- A statement about a **defect** ⇒ cite `G-nn`. Do not describe the defect again.
- A number ⇒ with its measurement date and command. An unmeasurable number must be marked `[opinion]`.

## 3. What must not be done

| Not allowed | Why |
|---|---|
| Create a second WBS | two WBS means both are wrong. `sdlc/08.wbs/` is the only one |
| Copy content from `documents/` to here | the two will drift, and the reference copy is the correct one |
| Put consumer work into product objectives | consumers are beneficiaries, not what is being built |
| Write "done" without a commit/test/measurement | strangers read this repo, and they will check |
| Use "enterprise", "stronger", "optimal" as done criteria | unfalsifiable ⇒ not criteria |

## 4. Three kinds of statement — never mixed

From [`D-06`](../../01.inception/02.decision-log/00.index.md): **v2 is greenfield, v1 is a case study.**

| Kind | Example | Used as |
|---|---|---|
| **Requirement** | P1–P6 · vision · goals | design input, comparison baseline |
| **Design** | zones · layers · axes · seams | design input |
| **Prior art** | `packages/*`, `documents/*`, v1 measurements | **evidence to learn from** |

**Rule:** a statement about **prior art** is never written as an **existing capability** of the product. No sentence of the form *"X
already exists so we only need to add Y"*. If an idea from v1 survives into v2, it must be **re-justified from the requirement**.

**Why this rule is needed:** `documents/` describes v1 in great detail, so it *looks like* the product. That is the origin of the one
error repeated most in this project: reading a v1 description and proposing an increment on top of v1.

## 5. Current phase — the blocking gate

**`D-40`:** we are in **discovery → planning**. In this phase only **documents** under `sdlc/` may be created; **no**
rule/script/code/operating configuration.

The reason is in §1: `sdlc/` documents describe *intent*; rules and scripts **execute** that intent. Writing the executor before the
intent exists creates maintenance nobody approved.
