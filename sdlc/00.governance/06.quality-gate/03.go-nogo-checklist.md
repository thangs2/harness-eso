# 03 — Go / No-Go: dashboard per **increment**

> **Different from pre-flight:** pre-flight covers **one slice**; this covers **the whole increment** — what blocks the wave.
> **Rule:** **`P`** means "missing, but the gap is named" — **different** from **`—`**, "nothing exists". Merging them makes progress lie.

## 1. Marks

| Mark | Meaning | Sufficient to GO? |
|---|---|---|
| `OK` | complete for this increment | ✅ |
| `P` | missing, **gap named + `OPEN` id** | ✅ if an `open_id` exists |
| `OUT` | **not part of** this increment | ✅ (the `OUT` decision must be recorded) |
| `—` | **no artifact** | ❌ |

**Docs Ready** = `REQ ∩ US/AC ∩ SCN ∩ IF ∩ DATA` all **`OK`** or **`P` with an `open_id`**, **and** the packet matching the side:

| Slice | Required packet |
|---|---|
| `[be]` | **BIP** `READY`/`READY-SPLIT` |
| `[fe]` | **FIP** `READY`/`READY-SPLIT` |
| mixed | **two** packets — never merged ([`04.bip-fip`](../03.sdlc-standard/04.bip-fip.md)) |

**If this table ever says `YES`:** either the packet exists, or someone turned `—` into `P` without an `open_id`.

## 4. GO / NO-GO

| Question | Answer today |
|---|---|
| Is any slice **GO**-able? | **No** — every slice needs **BIP** (be) or **FIP** (fe), and **neither exists** |
| What **blocks**? | **BIP**: the WBS (one task) · **FIP**: **UI design** (a different task) |
| What next? | **WBS** → BIP for 9 · **UI design** → FIP for 7 |

**Δ ESO vs BAP:** BAP has a separate **UX** column (Penpot ZONE). ESO uses **FIP** in its place — a FIP **contains** the UX trace and the test spec, and one column should mean one packet.
