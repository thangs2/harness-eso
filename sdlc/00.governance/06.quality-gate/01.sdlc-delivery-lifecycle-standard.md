# 01 — SDLC Delivery Lifecycle Standard (harness-eso)

**Original, compared 1:1:** baplatform `sdlc/00.governance/03.quality-gate/01.sdlc-delivery-lifecycle-standard.md`.
Section structure follows theirs; content is ESO's. Every difference is marked **Δ**.

---

## 0. Pipeline (Canonical Form)

```text
Requirements (REQ-*)
  ↳ Analysis (UC + BR + US + AC)
    ↳ Quality Control (Scenario Matrix — SCN-*)
      ↳ Interface Design (Endpoint Contracts + Surfaces)
        ↳ Data Design (Entities + Schema + Persistence Verification)
          ↳ Architecture & WBS (C4 + WBS + BIP/FIP)
            ↳ Test Specification (RED Test Packets per Subtask)
              ↳ Implementation (RED Test Code → GREEN Implementation)
                 ↳ Delivery (Agent → Human In Review; human → Done)
```

**Δ:** ESO has **no EF/`DbContext`** branch. Stage 5 verifies the **actual schema** plus **`visibility`** instead of context mappings.

---

## 1. Scope & Non-Negotiables

1. **Applies to:** every capability slice before active work begins.
1a. **Precondition:** the six items in **[§1.1](#11-preconditions--true-before-stage-1)** must be true first. **P0.3** — a
`document-status` register — is **mandatory**; without it the pipeline is not running.
2. **Document DoR / DoD:** satisfied **in order**. Each stage **consumes** the previous stage's artifact **by direct reference**; inventing contracts is **forbidden** ([`L1`](./00.index.md)).
3. **Domain boundary:** the product domains (`eso-core` · `eso-knowledge` · `eso-graph` · `eso-evidence` · `eso-control-plane` · `eso-adapters`) are **fixed** — do not add domains.
4. **Separation:** logic lives in `eso-core`; **UI and transport do not hold business rules** ([`04.bip-fip`](../03.sdlc-standard/04.bip-fip.md) rule 4).
5. **Δ ESO:** a gate is a **document condition**, **not** a Jira status ([§3](../03.sdlc-standard/02.gates.md)).

### 2.2 Detailed Stage Narrative

#### Stage 1 — Requirements (`REQ-*`)
- **Input:** P1–P6, findings measured in the field.
- **Output:** `sdlc/02.requirements/04.requirements.md` — 19 `REQ-*`.
- **Gate:** verifiable statement; **no** REQ omits *"what it does not cover"*; **6/6 P** have at least one `MUST`.

#### Stage 2 — Analysis (`UC` · `BR` · `US` · `AC`)
- **Input:** approved REQ.
- **Output:** `01.business-analysis/` (actor catalog · use cases · business rules) + `02.user-stories/` + `03.acceptance-criteria/`.
- **Gate:** each AC **testable alone**; **no AC references another US's AC**; every `US` traces to **UC** + **REQ**; `P1–P6` each have a US.

#### Stage 3 — Quality Control (`SCN-*`)
- **Input:** US + AC.
- **Output:** `04.quality-control/` — scenario matrices **+ RTM**.
- **Gate:** **1:1 AC ↔ SCN**; happy + edge + failure covered; **`rbac` + `tenant`** rows **or `OUT` with a reason**; each row declares automated/manual.

#### Stage 4 — Interface Design
- **Input:** SCN + AC.
- **Output:** `07.interface-design/01.contracts.md` (endpoints) + `02.surfaces.md` (surfaces).
- **Gate:** in/out/errors explicit; **no endpoint on the turn path**; duplicate ≠ error but **same key with different content = 409**; unfinalised ⇒ `OPEN`.

#### Stage 5 — Data Design
- **Input:** endpoints + AC.
- **Output:** `06.data-design/` — `01.entities` · `02.schema` · `03.declaration-format`.
- **Gate:** **zero drift** entity ↔ schema; `project` is the **leading** key part; RLS on every evidence table; `REVOKE UPDATE, DELETE`; `jsonb` **only** for non-filtered parts.

#### Stage 6 — Architecture & WBS (BIP / FIP)
- **Input:** stages 1–5.
- **Output:** C4 at all four levels (`04.architecture/c4/`) + WBS (`08.wbs/`) + `01.bip.md` / `01.fip.md` per slice.
- **Gate:** C4 is **static structure**, one level per file; BIP carries **planes A–E** plus a **`BR` × enforcement layer × test** table; status `READY` / `READY-SPLIT` / `BLOCKED` **with an owner**.

#### Stage 7 — Test Specification (RED packet)
- **Input:** approved BIP/FIP.
- **Output:** `sdlc/10.test/` — one RED packet per subtask.
- **Gate:** exact **test file** + test names; fixtures; concrete **expected failing assertion** (true RED).

#### Stage 8 — Implementation (RED → GREEN)
- **Input:** RED packet.
- **Output:** code + tests in `packages/`; green via `bun test`.
- **Gate:** RED first, GREEN after · coverage **≥ 80%** · **0 CRITICAL** per rubric; **never** delete or skip a test to pass.

#### Stage 9 — Delivery
- **Input:** stage 8 evidence.
- **Output:** `Human In Review` → `Done`.
- **Gate:** evidence complete (no silent `OPEN`) · **`GRANT`** for wide-blast changes ([`D-15`](../../01.inception/02.decision-log/00.index.md)) · **only A-01** sets `Done`.

## 3. Stage Transition Rules (Gate Evidence)

| Transition | Gate Evidence Required | Reviewer / Approver |
|:---:|---|:---:|
| **1 → 2** | `REQ-*` has an id · traces to **P** · priority · **boundary** · **verification path** | A-01 |
| **2 → 3** | every `US` has AC **testable alone**; **no orphan AC** | A-01 · A-04 |
| **3 → 4** | **1:1 AC ↔ SCN**; `rbac`/`tenant` rows **or `OUT` with a reason** | A-04 |
| **4 → 5** | endpoints + surfaces explicit; **0 endpoints on the turn path**; every `OPEN` is in the register | A-02 |
| **5 → 6** | entity ↔ schema **zero drift**; `project` leading key; RLS + `REVOKE` | A-02 |
| **6 → 7** | C4 all four levels; **BIP/FIP `READY` or `READY-SPLIT`**; `BLOCKED` has an owner | A-02 · A-01 |
| **7 → 8** | RED packet for **every** subtask · names the exact test file · **true RED** | A-04 |
| **8 → 9** | `bun test` green · coverage ≥ 80% · **0 CRITICAL** · links and `§` refs still resolve | A-03 · A-04 |
| **9 → Done** | evidence complete; **human** signs; no silent `OPEN` | **A-01** |

**Δ ESO:** the **8 → 9** row also checks **links, `§` references and the agent-spec size budget** — because in ESO the documents are part of the product.

## 9. Unit Test as Jira Task/Subtask Management

- **Tests are a first-class delivery item:** the `tdd-unit` label in the quartet, **not** a side task.
- **Document vs code separation:**
  - **Stage 7** produces the test **design** (`01.red-tests-*.md`).
  - **Stage 8** is the test **execution** (`qc/eso-*.test.mjs`).
- **Ticket protocol:** one `tdd-unit` ticket per subtask; the ticket body **links** to Stage 7; it moves to `Human In Review` only with a **`bun test` PASS log** attached.

## 10. Agent-native slice layer

The nine stages above are the **product** pipeline. An agent slice **also** carries working memory, but that memory **loses** to those stages:

| Piece | Home |
|---|---|
| Workforce · roles · policy · flow | `sdlc/00.agent-manifests/02.capabilities/` + [`17.jira-slp-operating`](../../04.architecture/17.jira-slp-operating.md) |
| Ticket pack | [`16.jira-ticket-contract`](../../04.architecture/16.jira-ticket-contract.md) · `E18` |
| `OPEN` items | [`04.open-register`](../04.open-register.md) |
| Document status | [`05.document-status`](../05.document-status.md) |

**An agent slice never replaces** `REQ`, `US`/`AC`, or the WBS pack. It only **carries** them more compactly.
