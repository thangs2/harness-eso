# C4 L4 — Code: thành phần ↔ package

> **Mức cuối.** Ở đây C4 dừng: bên dưới là code thật, và code thật **chưa tồn tại** ([`D-40`](../../01.inception/02.decision-log/00.index.md)).
>
> **Trạng thái thật:** đây là **ánh xạ dự kiến**, không phải mô tả code có sẵn. Chưa có file nào trong `packages/eso-*`.

## 1. Ánh xạ — một package một miền

| Container | Thành phần | Package | Ghi chú |
|---|---|---|---|
| **C1** | C1.1 hook · C1.2 probe | `packages/eso-adapters` | theo từng host: DSH · Cursor · Antigravity |
| **C1** | C1.3 resolver | `packages/eso-knowledge` | ba vùng skill là nội dung của miền này |
| **C1** | C1.4 judge · C1.5 gaps | `packages/eso-core` | miền phán quyết |
| **C1** | C1.6 buffer · C1.7 sync | `packages/eso-evidence` | outbox thuộc evidence, không thuộc core |
| **C2** | C2.1 … C2.5 | `packages/eso-control-plane` | API + DB + sync |
| **C3** | UI | `packages/eso-ui` | React/TS |
| **C5** | C5.1 … C5.3 | `tools/graph-extractor` | .NET/Roslyn, **không** phải package npm |
| — | test tích hợp | `qc/eso-*.test.mjs` | quy ước repo |

**Vì sao C1.6 tách khỏi C1.4:** `core` phán quyết; `evidence` ghi. Nếu gộp, thì `eso-core` phải biết về outbox — và
`allowed_files` của hai miền chồng nhau, đúng thứ `plan-runtime` cấm.

## 2. Ranh giới **ghi** của từng miền

| Package | `allowed_files` khi làm việc trên nó |
|---|---|
| `eso-core` | `packages/eso-core/**` · `qc/eso-core-*.test.mjs` |
| `eso-knowledge` | `packages/eso-knowledge/**` · `qc/eso-kb-*.test.mjs` |
| `eso-evidence` | `packages/eso-evidence/**` · `qc/eso-ev-*.test.mjs` |
| `eso-graph` | `packages/eso-graph/**` · `qc/eso-graph-*.test.mjs` |
| `eso-control-plane` | `packages/eso-control-plane/**` · `qc/eso-cp-*.test.mjs` |
| `eso-ui` | `packages/eso-ui/**` |
| `eso-adapters` | `packages/eso-adapters/**` · `qc/eso-adapter-*.test.mjs` |
| `graph-extractor` | `tools/graph-extractor/**` |

**Rời nhau từng cặp** — kiểm được bằng mắt, và đó là điều kiện để chia slice song song.

## 3. Chỗ C4 **dừng** — và vì sao dừng ở đây

| Bên dưới L4 | Thuộc |
|---|---|
| class, hàm, kiểu dữ liệu | **code** — chưa có |
| chi tiết thuật toán tính `level` | [`07.sufficiency`](../07.sufficiency.md) (mô hình, không phải code) |
| schema bảng | `06.data-design/` (**chưa tạo**) |
| hợp đồng HTTP | `07.interface-design/` (**chưa tạo**) |

**Vì sao không vẽ tiếp:** vẽ class trước khi có code là **đoán** rồi trình bày như thiết kế — đúng thứ `L1` của chuẩn cấm.
L4 ở mức **package** là mức xa nhất còn **kiểm được** khi chưa có code: nó khớp `allowed_files`, và `allowed_files` khớp
miền.

## 4. Điều L4 này **khẳng định**, và sẽ phải kiểm lại khi có code

| Khẳng định | Kiểm bằng |
|---|---|
| Mỗi miền **một** package | `allowed_files` rời nhau (§2) |
| `eso-core` **không** biết outbox | grep import từ `eso-evidence` trong `eso-core` phải **rỗng** |
| `eso-ui` **không** import `eso-adapters` | cùng cách |
| `graph-extractor` **không** phải npm package | nó ở `tools/`, không ở `packages/` |

Bốn khẳng định này là **hợp đồng kiến trúc**. Khi có code, chúng thành test — và nếu chúng sai, thì C4 sai, không phải code
sai.

## 5. Không thuộc L4

| Không | Ở đâu |
|---|---|
| danh sách file trong từng package | sinh ra khi có code; **không** dự đoán |
| API nội bộ giữa module | `07.interface-design/` |
| thứ tự implement | `08.wbs/` |
