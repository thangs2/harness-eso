# 00 — UI / UX design

> **This folder is design, not contract.** It says what a **person** sees and does: surfaces · screens · flows.
> The machine-to-machine contract lives in [`07.technical/03.api/`](../07.technical/03.api/00.index.md) — deliberately a separate folder.

| File | Answers |
|---|---|
| [`01.surfaces.md`](01.surfaces.md) | 5 surfaces `S1…S5` · who uses each · what it must show |
| [`02.wireframes.md`](02.wireframes.md) | **ASCII wireframe** per surface — markdown only, no Figma/Penpot |
| [`03.states.md`](03.states.md) | **state matrix** `ST1…ST6`: empty · loading · error · denied · partial · stale |
| [`04.flows/00.index.md`](04.flows/00.index.md) | **flow tables**: step → sees → taps → system does → AC |
| [`05.prototype-index.md`](05.prototype-index.md) | surface ↔ wireframe ↔ states ↔ flows ↔ AC · plus **X14** |

**Why split from API:** an API changes for technical reasons, a surface changes for reasons of use. One folder for both means one
always drags the other, and the reviewer cannot tell which question a change answers.

**Prototype is markdown.** No design tool. `S1` is prototyped; `S2…S5` are not, so no `FIP` can be written for them
([`03.document-status`](../02.governance/03.document-status.md) §I.3).
