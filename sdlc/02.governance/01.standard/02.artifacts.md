# 02 — Artifacts: the required shape of each document kind

**Standard:** [`00.index.md`](00.index.md) · **Type:** `standard`

> **Why this file.** "Standardise the documents" is unverifiable when it only means "be clear". So each document kind gets a
> **required header** and **required sections**, both checkable by eye or by script.

## 1. Header — **theirs**, not invented

> **Corrected 2026-10-25.** An earlier version of this file defined `doc_kind` · `id` · `stage` · `standard_version` — **four keys I
> made up**. A census of baplatform's `1 360` files shows the common keys are **`sot_doc_version`** (1 350) · `status` (966) ·
> `source_of_truth` (510) · `id` (56) · `type` (42) · `phase` (110).
>
> Different names, different meanings, and **no key that connected a document to its source**.

### 1.1 Two zones — with **different** headers

| Zone | Where | Reader | Header carries |
|---|---|---|---|
| **HUMAN** | `sdlc/01…12` | people | `sot_doc_version` · `status` · **`source_of_truth`** · `phase` |
| **AI** | `sdlc/01.agent-manifests/` | agents (preflight) | `sot_doc_version` · **`human_sot`** (pointer to the HUMAN document) |

### 1.1a Zone **language** — follows the reader, not preference

| Zone | Language | Why |
|---|---|---|
| **HUMAN** | **Vietnamese** | the operator reads it to **understand**; an English translation is optimising for the wrong reader |
| **AI** | **English** | an agent loads it on **every** task; it is a small fixed corpus read repeatedly |

**Rules:**

1. A document is written in **its zone's language**. Mixing inside one file is a defect, not a style choice.
2. **Never translate a HUMAN document to save tokens.** The saving is real and the cost is larger: the person who must understand it
   loses.
3. A pointer across zones **may** cross languages — `human_sot` pointing at a Vietnamese document from an English spec is **correct**.
4. Governance ([`02.governance/`](../README.md)) counts as **AI-facing**: it is read before any work starts, by agents
   first.

**`human_sot` is the most important key in this standard.** It turns mapping and reference lookup into a **single lookup** rather than
a search: every AI document **points at** its HUMAN source.

### 1.2 HUMAN header

```yaml
---
sot_doc_version: "0.1.0"
source_of_truth: "sdlc/…"      # or the product SoT — the real origin
status: DRAFT | OPEN | READY | READY-SPLIT | BLOCKED
phase: "1"                      # which stage (1…9)
id: REQ-SET                     # for reference lookup
---
```

| Key | Required | Why |
|---|---|---|
| `sot_doc_version` | ✅ | which **version** of the standard it follows; changing the standard shows what needs review |
| `source_of_truth` | ✅ | **answers "what does this rest on"** — without it nothing can be rechecked |
| `status` | ✅ | [`02`](01.gates.md) §2 |
| `phase` | ✅ | which gate it belongs to |
| `id` | ✅ when cited | so other files can point at it |

**Kind-specific keys** are added, never replacing the common ones: `module` · `wave` · `domain_slug` · `task_id` · `sp` · `role` · `cr`.

### 1.3 AI header

```yaml
---
sot_doc_version: "0.1.0"
human_sot: "sdlc/06.analysis/01.business-analysis/05.iam-functions.md"
id: IAM-SPEC
type: capability-spec
---
```

### Budget — source, and a **checkable proxy**

**Source:** baplatform, `sdlc/01.agent-manifests/README.md` and `00.index.md` — *"so AI agents … load exact invariants and topology
graphs in `< 300 tokens/file`"*; the wave router is stricter: `< 200 tokens`.

> **Correction 2026-10-25.** An earlier version of this file stated *"`< 300 tokens/file`"* as **our** rule, **citing nobody**.
> Checked: that number appears **nowhere** in their `.cursor/rules/` — it is **prose describing intent**, not an enforced rule. I
> promoted a description into law and presented it as mine.
>
> **And it cannot be measured:** this repo has no tokenizer. I once wrote *"391 tokens"* for a spec — that was `words × 1.3`, an
> **English** heuristic, **not a measurement**, and plainly wrong for Vietnamese.

**So the rule uses a deterministic proxy:**

| Checked by | Threshold |
|---|---|
| `wc -l` | **≤ 150 lines** |
| `wc -c` | **≤ 4 000 characters** |

**The proxy is deliberately ~2–3× looser than their intent:** Vietnamese uses more characters for the same content, and **a
threshold that can be checked beats a number nobody measures**. If a spec exceeds it, fix the spec — never raise the threshold.

Exceeding the budget is a **design error**, not "a bit long" — the agent will skip it and read the HUMAN document instead, which
defeats the purpose of having an AI document at all.

## 2.0 Required tree — an SDLC without these is **not** an SDLC

> **A precondition, not a suggestion.** `sdlc:init` ([`E15`](../../07.technical/03.api/01.contracts.md)) must create all of these, and
> `sdlc:check` ([`E16`](../../07.technical/03.api/01.contracts.md)) must fail when one is missing.

| Path | Why it is required |
|---|---|
| `02.governance/01.standard/` | the **standard itself** — without it there is no "conforms" |
| **`02.governance/03.document-status.md`** | **the status register** — without it nobody can say what is documented |
| `02.governance/04.open-register.md` | the only home for unanswered questions |
| `01.agent-manifests/` | the agent zone; a spec per capability |
| `02.governance/02.quality-gate/` | the gate instruments (pre-flight · go-no-go · flow) |
| a **`status` index per stage folder** (`README.md` or `00.index.md`) | so a reader can navigate without crawling |

**Rule:** a project with documents but no **document-status** register is **not** an SDLC project — it is a folder.
The register is what turns "we wrote things" into "**this is what exists, this is what is missing, and this is how we know**".

**`sdlc:check`** verifies presence, not quality: a register that exists but is empty **passes** the presence check and **fails**
cross-check X8 (every item must have a mark).

## 2. Required sections per **kind**

> **Corrected 2026-10-25.** Rewriting §1 **deleted** this table and I did not notice until I needed to add `query-spec`. Recorded
> because it is the same failure as everything else here: change one thing, lose another, and no check catches it.

| `type` | **Required** sections | **Forbidden** |
|---|---|---|
| `standard` | rules · how to check · self-check | a rule with no stated source |
| `requirement` | verifiable statement · **traces to P** · priority · **boundary** · **verification path** | an unverifiable statement |
| `actor-catalog` | actor · **kind** · **authority** · **forbidden** · **bears the consequence** | an actor with no authority stated |
| `use-case` | actor · trigger · **before/after** · main flow · **alternate flows** · invariants | mentioning technology |
| `business-rule` | statement · **where it is checked** · **what breaks if violated** | no stated consequence |
| `user-story` | story · **whose value it is** · **why not merged** · in/out of scope · planned AC | multiple actors · the word "depends" |
| `acceptance-criteria` | **8-column** table + `type` · **postconditions** · **the test that proves it** · **what this AC does not check** | an AC that cannot be tested alone · an AC using another US's AC |
| `scenario-matrix` | `SCN` 1:1 with AC · `type` (happy/edge/failure/**rbac**/**tenant**) · automated/manual | missing `rbac`/`tenant` rows without an **`OUT` + reason** |
| `c4` | **exactly one level** · **static structure** | flows or sequence diagrams |
| `data-model` | entities · relationships · **schema** · `project` + `visibility` | prose that contradicts the schema |
| `api-contract` | endpoint · in/out · errors · **idempotency** · `OPEN` where unfinalised | invented routes or DTOs · business rules |
| `ui-design` | surface · who uses it · what it must show · **what it must not decide** | deciding `exists`/permissions in the UI |
| `query-spec` | per query: **question** · traversal · source · **how coverage is measured** · expected level | measuring coverage as **one global number** |
| `wbs` · `bip` · `fip` | see [`04`](03.bip-fip.md) | merging BIP with FIP |
| `checklist` | per-item **marks** — either tick boxes **or** a mark column (`✅` / `⚠️` / `❌`) · **evidence = a file path** | a mark with no path behind it |
| `feature-catalog` | one row per feature: id · **what it is** · actor · `REQ` · `UC` · `US` · **AC count** | a feature row with no `REQ` |
| `traceability-matrix` | one row per **AC** → `SCN` → endpoint → table → test · **coverage total** | a matrix without the uncovered rows listed |
| `domain-spec` | **AI zone**: what the domain owns · invariants · what it must not do · file boundaries · `human_sot` | an invariant with no test named |
| `capability-spec` | **AI zone**: what it owns · rules · wire (endpoints/tables) · refs · `human_sot` · **≤ 150 dòng / ≤ 4 000 ký tự** | a spec that copies its human document |
| `capability-index` | **AI zone**: one row per capability — id · spec path · `human_sot` · status | an index row without a spec file |
| `decision-log` | date · status · **what was rejected and why** | a decision with no rejection clause |

## 2.1 **Edge catalogue** — a boundary is chosen from a list, not from imagination

> **Why this exists.** Measured 2026-10-26: the median user story carried **exactly three criteria** — one happy, one edge, one failure.
> The single "edge" was whatever came to mind first, so it varied per story and was usually the most obvious one. A boundary picked from
> memory cannot be audited; a boundary picked from a **closed list** can.

| id | Boundary | Applies when |
|---|---|---|
| **E1** | **empty** — zero items | the behaviour takes a list, set or collection |
| **E2** | **single** — exactly one item | same, when one is the minimum meaningful case |
| **E3** | **volume** — many (100 / 1 000) | lists, aggregation, pagination |
| **E4** | **at the limit** — value exactly at the threshold | numeric or date threshold |
| **E5** | **just over** — the smallest value that is refused | same threshold, the other side |
| **E6** | **duplicate / replay** — same input twice | any write path, any keyed operation |
| **E7** | **concurrent** — two actors at once | shared state, counters, locks |
| **E8** | **time boundary** — before / exactly at / after | due dates, expiry, measurement windows |
| **E9** | **odd input** — longest allowed, unicode, leading zeros | free text or identifiers |
| **E10** | **dangling reference** — points at something deleted | foreign keys, links, ids |

**Rule:** each `US` covers **≥ 2 catalogue edges**, or records `OUT` naming the categories that do not apply **and why**. A story about a
single scalar with no list, no threshold and no time has genuinely fewer edges — that is fine, but it must be **said**, not implied.

**Forbidden:** an edge that is not in E1–E10 without adding it to this table first. Otherwise the catalogue drifts into decoration.

### 2.2 Kinds added by **X7**, not invented in advance

> `feature-catalog` and `traceability-matrix` were **in the tree before they were in the standard**: `06.eso-features.md` and `03.iam-rtm.md`
> declared types the table had never heard of, so no rule applied to them. **X7** found it. They are real kinds — a catalogue and a trace matrix
> are not a `checklist` — so the table gained them **with required sections**, which is the fix that makes them checkable rather than exempt.

**Hai kind của vùng AI** (`domain-spec` · `capability-spec`) cũng **không có trong bảng** cho tới lần chạy `X7` này — chúng tồn tại
trong `00.agent-manifests/` từ đầu. Vùng AI có **bộ mục riêng** (ngắn hơn, vì mục tiêu là **đọc trong một phút**), nên bảng ghi **mục bắt
buộc riêng** cho chúng thay vì áp mục của vùng HUMAN.

**`checklist` now accepts a mark column.** A table of `✅ / ⚠️ / ❌` with an evidence column is the same instrument as a tick box: per-item, checkable,
and diffable. Tick **boxes** were never the point; **a mark per item with a path behind it** was.

## 3. Five things **every** document must have

| | Why |
|---|---|
| **What question it answers** | a file answering two questions is two files |
| **What it does **not** answer** | the boundary — so it does not expand |
| **What it rests on** (citations) | so it can be rechecked when the source changes |
| **What happens if it is wrong** | a document with no stated consequence gets dropped the first time it is inconvenient |
| **Questions must carry answers** | a bare question is **offloading work**. An "unresolved" section records `question · **proposal** · basis` |

### 3.1 A question may **not** stand alone

Before writing an open question, do **two** things:

| Task | If skipped |
|---|---|
| **check the existing decisions** — it may already be answered | re-asking something answered makes the reader lose trust |
| if not, write a **proposal** + **its basis** | a bare question forces the approver to **start from nothing** |

**And if the answer sits in the same file** — as a lifecycle table stating that a paused worker keeps its work — then it is **not an
open question**; it is **not having re-read what I wrote**.

## 4. Naming

### 4.1 **Two independent sequences** — the rule this repo broke

> **Corrected 2026-10-26.** Folders and files were numbered in **one** sequence: `01.sources.md` · `02.sdlc-workflow.md` ·
> `01.standard/` · `02.quality-gate/`. That makes the number carry **two** meanings — "third item" and "this happens to be a folder" —
> and the moment a file is added or a folder is split, **every** later number shifts for one kind and not the other.

| | Rule |
|---|---|
| **Folders** | numbered `01…` **among folders only**, gapless |
| **Files** | numbered `01…` **among files only**, gapless |
| a number | means **one** thing in **one** namespace — `01.standard/` and `01.sources.md` are unrelated |
| `README.md` | unnumbered in **both** namespaces; it is navigation |

**Forbidden:** `01.file` · `02.file` · `03.folder` in the same parent — one sequence, two kinds.
**Allowed:** `01.folder/` · `02.folder/` beside `01.file` · `02.file` — two sequences, one parent.

**Why it matters:** with one sequence, adding a file after a folder **renumbers the folder**, which moves its path, which breaks every
link into it. With two sequences, adding a file touches files only.

### 4.2 Remaining shape rules

| | Rule |
|---|---|
| file & folder | `{NN}.{kebab-case}` (except `README.md`) |
| `01.business.process` | ❌ — must be `01.business-process`, **exactly one** dot after the index |
| `README.md` | the only unnumbered markdown in a folder — and needs **no header**: it is **navigation**, not a normative artifact |
| lower numbers first | reading order |
| **no release version in paths** | `sdlc/` **is** the latest |
| ids | follow the project's own items ([`D-42`](../../03.inception/02.decision-log/00.index.md)): `REQ-*` · `UC-*` · `BR-*` · `US-*` · `AC-*` · `SCN-*` |
| stable ids | changing an id changes **every** reference ⇒ change only when necessary |

**Exception — AI zone:** the **`.spec.md`** suffix is allowed and **does** carry extra dots:
`01.identity.spec.md` · `01.wave-1.topology.spec.md`. That is a convention **of the AI zone**, not a violation.

⇒ **A rule must state its exceptions**, otherwise either the AI zone is wrong or the rule is — and both make people abandon the rule.

## 5. The **reopening** rule — `L3`

Changing a source ⇒ **every** dependent document must be **marked**, never silently kept.

```text
P1–P6  ←  REQ-*  ←  UC-*  ←  US-*  ←  AC-*  ←  SCN-*  ←  test
                     ↑        ↑
                     └─ BR-* ─┘   (BR holds across use cases)
```

| Change this | Reopen |
|---|---|
| `REQ` | every `US` tracing to it · their `AC` |
| `UC` | `US` derived from it |
| `US` | its `AC` · the `SCN` covering them |
| `AC` | the matching `SCN` · the matching test |
| `BR` | every `AC`/`SCN` it constrains |
| `sot_doc_version` | every document whose `phase` belongs to that standard |

**How to mark:** set `status: OPEN` plus a line `reopened_by: <id changed>`. **Never** delete the old document — it remains evidence of
the previous reading.

## 6. Validity check — 7 questions, question 7 checked by `wc`

1. Does it have the **required header**?
2. Does it have the **required sections** for its `type`?
3. Does it have a **"does not answer"** section?
4. Is every claim **citable**? (Is every `OPEN` in the register?)
5. Is `status` used correctly? (`P` ≠ `—`, `BLOCKED` has an owner)
6. If this document is **wrong**, who finds out, and when?
7. **(AI zone)** is `wc -l` ≤ 150 and `wc -c` ≤ 4 000?

Question 6 is the most often skipped, and it is what separates a document that **works** from one that is merely **read**.
