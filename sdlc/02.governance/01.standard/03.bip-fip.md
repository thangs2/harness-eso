# 03 — BIP / FIP: the **readiness unit** of one slice

**Standard:** [`00.index.md`](00.index.md) · **Type:** `standard`

> **BIP** = Backend Implementation Packet · **FIP** = Frontend Implementation Packet.
> **One packet per slice.** A module / epic / wave approval **does not** substitute for a packet.

#### 0. What a **slice** is — and the order that produces it

> **A slice is one leaf work package of the WBS.** Nothing else. A wave, an epic, a story, or a whole deliverable is **not** a slice — each of those
> contains several, and approving the container leaves its leaves unreviewed.

| Step | Artefact | Produces |
|---|---|---|
| 1 | `05.requirements` · `06.analysis` | `REQ` → `US` → **`AC`** — the criteria are the unit everything downstream counts |
| 2 | `07.technical` · `08.ui-design` | planes **B** (C4) · **C** (contract) · **D** (schema) — a packet cannot cite what does not exist |
| 3 | **`09.wbs`** | **deliverable → work package**, each leaf owning specific `AC` — this is where **`slice id`** comes from |
| 4 | **packet** (`bip` / `fip`) | one per leaf, citing step 1 and step 2 |
| 5 | code | follows the packet, never leads it |

**The dependency is one-way and it is not negotiable:** a packet needs a slice id, a slice id exists only in the WBS, and the WBS needs criteria. So
**WBS comes before packets**, and criteria come before both. Writing a packet before the WBS means inventing a slice id that the WBS will later
contradict.
>
> **`READY` means "ready to implement" only.** It does **not** mean Jira `In Progress`, merged, or deployed.

## 1. Which packet

| Slice | Packet |
|---|---|
| `[be]` — logic · data · API | **BIP** |
| `[fe]` — UI · surfaces | **FIP** |
| **mixed** slice | **two** packets, **one per side** |
| | **never merge** BIP and FIP into one file |

In ESO: `[be]` = `packages/eso-*` · `[fe]` = `packages/eso-ui`. A logic-only slice needs a BIP and `FIP = `OUT`` **with a reason**.

### 1.1 When a slice needs **no packet at all** — `OUT` at slice level

**A slice that produces no behaviour has no packet.** Not an empty one — **none**, recorded as `OUT` **with a reason**, in the same folder, because a
missing file cannot be told apart from a forgotten one.

| Slice produces | Packet | `OUT` reason must name |
|---|---|---|
| **behaviour** with criteria (`AC`) | **BIP** (and **FIP** if it shows a surface) | — |
| **no behaviour** — infrastructure that makes work possible | **`BIP = OUT`** | **which** capability it unblocks, and **what test** proves the infrastructure works instead |
| **a contract** with no behaviour — an interface, a schema, a wire format | **`BIP = OUT`** | **what implements it**, and why the contract itself has no criterion |

**Why not an empty BIP:** the nine sections are a checklist of things to *decide*. A slice with no criteria has nothing to put in §3 (`BR`), §6
(invariants) or §7 (test plan) — so an "empty BIP" is either **nine `OUT` lines** or **invented content**. The first is `OUT` written the long way;
the second is the failure mode §5 calls out, where `OUT` becomes where unfinished work hides.

**The test that catches the difference:** a slice **may** be `OUT` only if **no `AC`** is assigned to it in the WBS. A slice that owns criteria and
claims `OUT` is hiding work.

## 2. BIP — 9 sections

| § | Section | Content | What ESO adds over BAP |
|---|---|---|---|
| 1 | **Slice identity** | id · domain · `REQ` · `US` · `AC` · **touches `visibility`?** · **changes schema?** · **idempotent?** · status | `visibility` replaces tenant scope; no `writes money` |
| 2 | **Sources** | plane **A–E** × `OK`/`OPEN`/`OUT` + note | `OUT` **requires a reason**; `OPEN` **requires** an entry in §8 |
| 3 | **Business binding** | which `REQ` → `US` → `AC` → `BR` constrain the slice | **`BR-*` is mandatory** — BAP has no equivalent |
| 4 | **Contract & transaction** | in/out · errors · ordering · what must **not** change | — |
| 5 | **Data & persistence** | tables/columns · indexes · **`project` + `visibility`** | real schema, not EF |
| 6 | **Invariants** | `rule` × **`enforcement layer`** × **`test`** | the **`BR` → layer → test** table ESO was missing; a rule whose layer is "the application tries hard" is not enforced |
| 7 | **Test plan** | `AC` × type: unit · integration · **project isolation** · **RBAC** · **failure/concurrency** · `SCN` × `RED/GREEN` | tenant → **`project`**; adds a **`BR`** row |
| 8 | **`OPEN` register** | `open_id` · question · impact · **owner** · closure source · **blocks what** | — |
| 9 | **Decision** | `PASS`/`FAIL` · blocking reason · reviewer · date · evidence | — |

## 3. FIP — rules and planes

**Ten rules**, taken from BAP, adjusted where ESO differs:

| # | Rule |
|---|---|
| 1 | every packet **cites** `REQ`/`US` or an approved source |
| 2 | unknown ⇒ **`OPEN`**, never guessed |
| 3 | **invent nothing**: no routes · fields · error codes · permission names · i18n keys · theme tokens |
| 4 | **the backend is authoritative** for business rules; the frontend **presents and gates `visibility`**, and does **not** reimplement logic |
| 5 | stack: React/TS for `eso-ui` — **do not** add frameworks |
| 6 | `project` and permissions come **from the session**, never from the client |
| 7 | `documents/` is **read-only** |
| 8 | status ∈ `OK`/`OPEN`/`OUT`, **each with a citation or a reason** |
| 9 | **changing a source reopens the FIP** ([`03`](02.artifacts.md) §5) |
| 10 | no UI is **done** without component tests + an accessibility check + coverage on touched code |

**FIP planes A–E:** business · **UX trace** · FE architecture · data/API binding · test spec.

**Rule 4 is [`D-45`](../../03.inception/02.decision-log/00.index.md) at the presentation layer:** the UI gates `visibility`, it never
decides `exists`.

## 5. Falsification

1. **Approving a whole wave instead of a BIP.** ⇒ "ready" becomes an opinion, and no slice has a reviewer.
2. **Merging BIP and FIP.** ⇒ both layers blur, and rule 4 loses its home.
3. **`OUT` with no reason.** ⇒ `OUT` becomes where unfinished work hides.
4. **`READY` read as Jira `Done`.** ⇒ the document gate gets used as a work status, and both lose meaning.
5. **§6 without an `enforcement layer`.** ⇒ you know the rule but not where it is held, so you cannot tell what broke when it fails.
