# 04 — `OPEN` register: what is unresolved, with proposals

**Standard:** [`01.standard/01.gates.md`](01.standard/01.gates.md) §4 — *"an `OPEN` item not in the register **does not exist**"* · §2 (*"a question that does not change a shape blocks nothing"*)

> **Corrected 2026-10-25 — the first version of this file asked nine questions, five of which already had answers.** I built the list
> from memory instead of reading the 46 decisions first. This version checks each one; anything already answered is **cited**, not
> asked again.
>
> The consequence was worse than redundancy: my original proposal for `OP-01` (*"refresh the cache at the start of every turn"*)
> **contradicted** [`D-24`](../03.inception/02.decision-log/00.index.md) (*"no periodic refresh"*). Had it been approved, it would have
> reintroduced exactly what that decision removed.

## 1. Already answered — **do not ask again**

| Question | Answer at | Meaning for interface/schema |
|---|---|---|
| **When is the declaration cache refreshed?** | [`D-24`](../03.inception/02.decision-log/00.index.md): sync **on UI save** and **on `provision.sh`**; **no periodic refresh** | C1 does **not** call C2 every turn. The cache refreshes **at provision** (and after a UI save pushes files down) |
| **Who spawns the graph extractor?** | [`c4/02`](../07.technical/01.architecture/c4/02.container.md): **C1 spawns C5**; it is heavy so it runs **off** the turn path ([`D-22`](../03.inception/02.decision-log/00.index.md)) | no "build graph" endpoint on the turn path |
| **At runtime, read files or the database?** | [`14`](../07.technical/01.architecture/14.data-inventory.md) row **6**: `.harness/` (derived) is **read every turn**; [`D-23`](../03.inception/02.decision-log/00.index.md): the DB is the control plane's **operational** copy, not C1's | C1 reads **`.harness/`**, not the DB; no SQL client in C1 |
| **Who creates the `project` id?** | [`D-22`](../03.inception/02.decision-log/00.index.md) + [`13 §3.7`](../07.technical/01.architecture/13.control-plane.md): **`project = ownerId`**; declared by A-01 in `harness.profile.json` ([`D-43`](../03.inception/02.decision-log/00.index.md)) | the partition key is `ownerId`; **never** derived from a path |
| **How old may a cache be before the guarantee drops?** | [`D-46`](../03.inception/02.decision-log/00.index.md): a declaration grants **kind + TTL** | this is a **value**, not a shape ⇒ under standard §2 it **blocks nothing** at stages 4–5 |

## 2. Closed — four shape questions (D-47), kept as evidence

## 3. Why these four and not ten

| Kind | Handling |
|---|---|
| changes an API/schema **shape** | must be settled before stages 4–5 → the four above |
| changes only a **value** (threshold, TTL, batch size) | that is **data** → settle later |
| changes **behaviour** but not a shape | decided at a later stage |

**Removed from the register because they are values:** evidence batch thresholds · cache TTL · rows per ship.

## 5. How to close an `open_id`

1. Approve the proposal ⇒ record it as decision `D-nn` and point here from it.
2. Change the row to `CLOSED · D-nn`.
3. If the proposal is **rejected** ⇒ write the alternative, **do not delete** the row.

**Never** delete a closed row: it is evidence that the question **was** asked.

## 6. Lessons from this correction

| Mistake | Fix |
|---|---|
| building the question list from **memory** | **read the decisions first**, then ask only what is missing |
| proposing something that **contradicted** an existing decision | every proposal must **grep** for a decision that says otherwise |
| mixing **values** with **shapes** | only shape questions may block a stage |
