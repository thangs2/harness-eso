# 03 — Document status **standard**: completeness, cross-checks, and how a status is claimed

**Type:** `standard` · **Requires:** [`03.artifacts.md`](01.standard/02.artifacts.md) (shape) · [`01.gates.md`](01.standard/01.gates.md) (marks)

> **Why this became a standard.** It used to be a table of numbers. Every number was typed by hand, and **four separate totals were
> wrong in one session** (82 vs 83 AC · 22 vs 23 · "391 tokens" · a BIP totals update that never wrote). A status that is typed is a
> **claim**; a status that is **checked** is a **fact**.
>
> So this file defines: **what "documented" means**, **eight cross-checks** that must pass, and **how results are recorded**.
> The table at the end is an **instance** generated by those checks — never an opinion.

## 0. This file is a **precondition**, not a report

> **Stage 0** ([`01.sdlc-delivery-lifecycle-standard`](02.quality-gate/01.sdlc-delivery-lifecycle-standard.md) §1.1 **P0.3**):
> a project whose SDLC tree has **no `03.document-status.md`** has not started the pipeline. `sdlc:init` must create it
> ([`E15`](../07.technical/03.api/01.contracts.md)), and `sdlc:check` must fail without it.

| Why it is a precondition | Consequence of skipping it |
|---|---|
| it is the only place that says what **exists** and what is **missing** | "documented" becomes whoever speaks last |
| the gate instruments **read** it ([§5](#5-process-completeness--this-file-feeds-the-gates-it-does-not-replace-them)) | pre-flight and go/no-go become opinions |
| it records the **cross-check results** | nobody can tell whether a claim was ever checked |

**An SDLC tree without this file is a folder.** The register is what turns *"we wrote documents"* into *"this exists, this is missing,
and this is how we know"*.

## 1. Definition — "documented" means **three** things, not one

| Level | Meaning | Fails when |
|---|---|---|
| **exists** | the file is present | a link to it is broken |
| **conforms** | it has the required header and sections for its `type` | a key or a section is missing |
| **connected** | it is reachable from a requirement and to a test | an `AC` has no `SCN`, a `US` has no `REQ` |

**Only all three count.** A file that exists but is unreachable is **dead weight**; a file that conforms but nothing points at it is
**decoration**.

## 2. The completeness contract — what each item must have

An **item** (capability) is "documented" when every **required** slot is filled. `OUT` is allowed **only with a reason** and counts as
filled.

| Slot | Required | Belongs to |
|---|---|---|
| `REQ` | ✅ always | stage 1 |
| `UC` | ✅ when the item has a user-facing flow | stage 2 |
| `US` | ✅ ≥ 1 | stage 2 |
| `AC` | ✅ ≥ 1 per US | stage 2 |
| `SCN` | ✅ **every** AC | stage 3 |
| `interface` | ✅, or `OUT` — **reason required** | stage 4 |
| `data` | ✅, or `OUT` — **reason required** | stage 5 |
| **`BIP`** (backend slice) | ✅, or `OUT` — reason | stage 6 |
| **`FIP`** (frontend slice) | ✅, or `OUT` — reason | stage 6 |
| **AI spec** | ✅ per capability | stage 2 (agent zone) |
| `executed` scenarios | ✅ before `Done` — **not** before `READY` | stage 8 |

**`BIP` and `FIP` are separate slots.** A slice may be `[be]`, `[fe]`, or mixed; a mixed slice needs **both**
([`04.bip-fip`](01.standard/03.bip-fip.md)). One packet column cannot describe two sides.

## 3. Eight **cross-checks** — the whole point of this file

**A status claim is invalid unless all eight pass.** Each is a command, not a judgement.

| id | Proves | How | What it catches |
|---|---|---|---|
| **X1** | every link resolves | markdown link scan against the filesystem | renamed/deleted files still referenced |
| **X2** | header per zone | HUMAN: `sot_doc_version` · `source_of_truth` · `status` · `phase` · AI: `human_sot` | documents with no provenance |
| **X3** | `AC` ↔ `SCN` 1:1 | every `AC` id appears in a scenario row's `ac_ref`; no row cites a missing `AC` | an AC added after its matrix |
| **X4** | trace up and down | every `US` cites `UC` + `REQ`; every `P` has a `REQ` | invented requirements; orphan stories |
| **X5** | agent-spec budget | `wc -l` ≤ 150 · `wc -c` ≤ 4 000 | a spec the agent skips |
| **X6** | id uniqueness | no `AC`/`SCN` id defined in two files | a count that drifts |
| **X7** | shape per `type` | for each file: read `type:` → take the required headings from [`03` §2](01.standard/02.artifacts.md) → check each heading exists | a "user story" with no AC section |
| **X8** | packet per slice | every item has `BIP`/`FIP` or an `OUT` with a reason | a slice that can never be implemented |
| **X9** | API ↔ data round trip | every endpoint names **real tables**; every table has **a path from** an endpoint, or an `OUT` with a reason | an endpoint writing to a table nobody defined, and a table nothing can reach |
| **X10** | reference layer has a **revision rule** | each `01.architecture/` document states **what change makes it wrong** | C4 drifting silently while every slice is built against it |
| **X11** | **every `UC` has ≥ 1 `US`** | count `UC-*` in the catalogue, grep `US` files for each id | a use case nobody serves — the behaviour is described and **nobody owns it** |
| **X15** | **every UI criterion is reachable from a flow** | each `AC-UI-*` appears in ≥1 step of ≥1 flow, or carries `OUT` + reason | a state that exists in the matrix and in no behaviour — so nothing tests it end to end |
| **X14** | **surface is designed only when prototyped** | for each surface: ≥1 wireframe · all **6** states (`ST1…ST6`) · ≥1 flow whose steps each name an AC | a screen described by name only, with no empty/loading/error/denied states and no behaviour |
| **X13** | **≥ 2 catalogue edges per `US`** (`E1…E10`) | count edge criteria per US; each must cite `E1…E10`, or the US records `OUT` + reason | a story whose only boundary is the first one someone thought of |
| **X12** | **every `UC` alternate flow is named by ≥ 1 `AC`** | alternate flows carry ids (`UC-14.1a`); each id must appear in an `AC` file | a branch that was designed and **never tested** |

**X3 and X4 are the two that catch the errors actually made here:** an AC added without a scenario, and a US that traces to nothing.

### 3.1 Recording a result

| Column | Rule |
|---|---|
| `measured` | **a date**, from the run |
| `command` | the exact command — so it can be re-run |
| `result` | the **number**, not "ok" |
| `fails` | the **count of violations**, never a list of names only |

**A cell without a date and a command is not evidence.** "Checked" is not a result.

## 4. The status table is **generated**, never written

```text
X1…X15  →  per-slot marks  →  this table
```

| Mark | Meaning |
|---|---|
| `OK` | slot filled **and** its check passes |
| `P` | filled, gap **named + `OPEN` id** |
| `OUT` | not applicable, **reason recorded in the item's detail** |
| `—` | **absent** |

**Rule:** if a mark and a check disagree, the **check wins** — the mark is wrong.

## 5. Process completeness — this file **feeds** the gates, it does not replace them

| Instrument | Reads |
|---|---|
| [`02.quality-gate/02.pre-flight`](02.quality-gate/02.pre-flight-readiness-checklist.md) | one slice, 9 stages, **this table's slots** are its evidence column |
| [`02.quality-gate/03.go-no-go`](02.quality-gate/03.go-nogo-checklist.md) | one increment, **this table's marks** are its dashboard |
| this file | what is **documented**, and **what that costs** |

**Do not fill the same status in three places.** This file is the **source**; the other two **consume** it. If they disagree, this
file is wrong — fix it here.

## 6. Falsification — how to know this standard is being violated

1. **A number here disagrees with a fresh run.** ⇒ the file was typed, not generated. Fix the process, not the number.
2. **A row has no `—` or `P`.** ⇒ either finished (nothing is) or **debt is hidden**.
3. **`OK` on a slot whose check fails.** ⇒ the mark is an opinion. The check wins.
4. **An `OUT` with no reason.** ⇒ that is where unfinished work hides.
5. **A waiver of "one unchecked box"** ([`02.gates`](01.standard/01.gates.md) `L2`). ⇒ every later gate becomes ceremony.

## I.3a The analysis is **thin** — measured, and it is a generation defect

> Found by the operator asking *"one US per item? this is not a small project"*. Measured, not argued.

| Measurement | Value |
|---|---|
| `UC` in the catalogue | **14** |
| `US` files | **22** |
| `UC` with **zero** `US` | **1** — `UC-02` (*"say what is missing"*) |
| `UC` served by **exactly one** `US` | **6 of 14** (was 10 — `UC-10`, `UC-14`, `UC-12`, `UC-11` decomposed) |
| `UC` served by many | `UC-04` (6) · `UC-05` (4) · `UC-01` (2) |

**Diagnosis — the US were generated from the feature list, not from behaviour.** `F-01…F-18` maps one-to-one onto US, so an item got
one story because it had one feature. `UC-04`/`UC-05` escaped only because they are setup flows that were decomposed by **function**
(workers · roles · policies · flows · accept · config). Everything else got a single story **regardless of its steps, branches or
actors**:

| UC | Main steps | Alternate flows | US |
|---|---|---|---|
| `UC-14` choose capability source | **9** | **2** | **1** |
| `UC-01` ask "is it enough" | 5 | **3** | 2 |
| `UC-02` say what is missing | 3 | 0 | **0** |
| `UC-12` understand a project | — | — | 1 |

⇒ The count tracked **how the docs were written**, not **how much behaviour exists**. That is exactly the failure the cross-checks exist
to catch, and **X1–X10 could not catch it**: every one of them checks a document's **shape**, and this was a defect of **coverage**. That is
why **X11** and **X12** were added — they check that behaviour is *served*, not that documents are *well formed*.
