# Learning — capability spec

## Propose, **never** apply
Generated from a **cluster of risks of the same kind**. Required: `evidence[]` (risk ids) · `expected_effect` · **`revert`**.
Missing `revert` ⇒ **422 `NO_REVERT`** — and the constraint lives in the **schema** (`revert NOT NULL`), not only in the API.

## Three rules
- **only a human applies** (`operator`); an agent ⇒ `APPLY_FORBIDDEN`
- applying **opens a `measure_window`** — it is **not yet** "effective"
- **effective** only when `unsat_rate` **falls** **AND** `defect_rate` **does not rise**; window still open ⇒ `NO_MEASUREMENT`

Why both numbers: a falling `unsat_rate` alone can be achieved by **lowering the bar**, and `defect_rate` is what catches that.

## Wire
`E19 learning:propose` · `E20 learning:apply`. Table `proposal` (`project` leading key, `revert` NOT NULL).
`tenant`: **N/A with a reason** — isolation comes from the partition.
